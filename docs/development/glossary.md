# ドメイン用語集

[ドキュメント一覧](../README.md) · [ソース構成](architecture.md)

Clutch-CS の利用・開発で使う用語と、その意味をまとめています。導入や基本操作に必要な用語は、[README の用語](../../README.md#用語)でも確認できます。

## クラスターと PC

| 用語名（日本語・英語） | 意味 |
| --- | --- |
| クラスター<br>Cluster | 設定や状態を共有し、協調して処理するピアのグループです。 |
| ホスト<br>Host | Clutch-CS が識別する PC です。同じホストに複数のピアを配置できます。 |
| ピア<br>Peer | クラスターに参加する一つの CoreService です。ホストが PC を表すのに対し、ピアはその PC で動くサービスの単位を表します。 |
| ホストグループ<br>Host group | 実行先をまとめて指定するために、クラスター内のホストへ付けるグループです。 |
| コーディネーター<br>Coordinator | 優先順位に従って選ばれるクラスターの管理役です。実行先を指定しない処理も、このピアが担当します。 |
| オブザーバー<br>Observer | ピアとして参加せず、クラスターを発見して状態の確認や管理要求を行う役割です。ClientHost がこの役割を担います。 |
| 起動実体<br>Instance | ある一回の起動で動いているプロセスです。同じピアを再起動した場合も別の実体として識別し、停止前の処理結果などと区別します。 |
| 参加状態<br>Peer status | クラスターへの参加状況です。Ready は同期と参加条件の確認が済んだ状態、Syncing は同期中です。[状態ごとの意味](../guides/web-client.md#接続状態を確認する)も参照してください。 |

## ワークフローとデータ

| 用語名（日本語・英語） | 意味 |
| --- | --- |
| ワークフロー<br>Workflow | ノードと接続線で組み立てた一連の処理です。処理内容、設定、実行する PC を定義します。 |
| ノード<br>Node | 一つの処理や値を表す部品です。受信、変換、条件分岐、ファイル操作などを組み合わせます。 |
| 入出力端子<br>Port | ノードの値や信号を受け渡す接続口です。TCP・UDP の通信ポート番号とは別のものです。 |
| 待受ノード<br>Source | 通信の受信、時刻、状態の変化などを待ち、後続処理のきっかけを作るノードです。 |
| 信号<br>Signal | 処理の開始や完了を後続へ知らせるものです。処理するデータを渡す接続とは別に、実行のタイミングを指定できます。 |
| 状態データ<br>State | ワークフローから読み書きし、実行が終わっても保持する値です。ワークフロー内、ピア内、クラスター全体など、共有する範囲を選べます。ピアの参加状態とは別です。 |
| フック<br>Hook | ノードの実行、ログの記録、ピアの状態変化などのイベントを受け取り、後続処理へつなぐ仕組みです。 |
| サブワークフロー<br>SubWorkflow | 複数のノードと接続をまとめた再利用用の定義です。親ワークフローでは一つのノードとして配置できます。 |
| サブグラフ<br>Subgraph | ワークフローの一部のノードと接続を選んだ範囲です。部分復元などの対象に使います。 |

## 設定の保存と操作

| 用語名（日本語・英語） | 意味 |
| --- | --- |
| 有効版<br>Effective revision | 現在、新しい処理の実行に使われる設定の版です。保存・共有が済んだ版と同じとは限らないため、別々に確認できます。 |
| スナップショット<br>Snapshot | 復元に使うために保存した、ある時点の設定や状態です。外部への送信や機器の動作まで取り消すものではありません。 |
| 安全制御<br>Safety | 障害時などに処理を停止・継続するための制御です。利用者による停止、一時的な続行、通常の判断への復帰を区別します。 |
| 操作 ID<br>Operation ID | 設定変更、更新、復元など、一回の管理操作を識別する値です。応答が途切れた場合も、同じ ID で元の操作結果を確認できます。 |
| 実行 ID<br>Execution ID | ワークフローの一回の実行を識別する値です。ノードの結果やログを、その実行に結び付けて調べられます。 |
