# アプリケーションを管理する

[ドキュメント一覧](../README.md)

Dashboard の **Applications** では、アプリケーションの起動・停止・監視を設定できます。
登録先の PC で実行するため、ファイルパスや起動アカウントもその PC のものを指定してください。

## 登録する

1. **Applications** を開き、登録先のホストを選択してください。
2. アプリケーション名、実行ファイルの絶対パス、作業ディレクトリを入力してください。「参照…」では登録先 PC のファイルを選べます。
3. 引数が必要な場合は、1 欄に一つずつ入力してください。不要な場合は一覧を空にしてください。
4. 起動アカウント・セッションと、ウィンドウ表示を選択してください。
5. 内容を確認して保存してください。

| 管理方法 | できること |
| --- | --- |
| 管理対象 | 起動・停止・再起動・監視 |
| 監視のみ | 指定した既存プロセスの状態確認。起動・停止は行いません。 |

引数は入力した値のまま渡されます。シェルの変数展開は行われません。
登録後に表示名を変えても、ワークフローが参照する ID は変わりません。

## 登録を削除する

Applications の一覧または詳細画面で **登録を削除** を選び、ホスト名とアプリケーション名を確認して削除してください。
登録を削除すると、自動監視・自動復旧・起動スケジュールが解除されます。実行中のアプリケーションは停止しません。
この登録を参照するワークフローはアプリケーションを操作できなくなるため、参照先も見直してください。

## 画面のあるアプリケーションを起動する

Windows で利用者の画面に表示する場合は、「Windows: ログインユーザーのデスクトップ」と、適切なウィンドウ表示を選択してください。
CoreService の実行セッションを選択すると、サービスからの起動では利用者の画面に表示されません。

ログイン中のユーザーや必要な権限を確認できない場合は、起動が拒否されます。
アカウント・表示方法の変更は次回の起動から適用されます。

## 自動監視・復旧を設定する

「Core稼働中に自動で監視する」を有効にすると、ブラウザーやワークフローを開いていなくても監視が続きます。
再起動する条件、遅延時間、試行回数の上限を指定してください。

新規登録では自動監視は無効です。再起動条件の初期値は異常終了、遅延は 1,000 ms、試行上限は 3 回です。
アプリケーションの起動成功を確認すると、自動復旧による起動も含めて試行回数を0へ戻します。CoreService自体の再起動では、未解決の試行回数を維持します。

時刻を指定した起動や、ワークフローからの起動・再起動も同じ登録内容を使用します。
詳細は[起動・監視・スケジュールの設定](../reference/applications.md)を参照してください。

## 複数のアプリをまとめて復旧する

依存関係のあるアプリは、**アプリグループ**で起動順序と復旧方法を設定できます。対象は同じホスト・Peerに登録した「管理対象」のアプリです。

1. 対象アプリを個別に登録してから、Applicationsの**グループを作成**を選んでください。
2. グループ名を入力し、対象アプリを追加してください。一つのアプリを複数のグループへ重複登録することはできません。
3. 上下ボタンで起動順を設定し、各アプリの**起動前の待ち時間（ms）**を入力してください。
4. **終了・異常を検出したアプリだけを再起動**、または**全員を停止して順番に再起動**を選択してください。自動復旧を使用する場合は、**グループの自動復旧を有効にする**を選択してください。
5. 通常終了の待ち時間と、終了しない場合の処理を選び、保存してください。

グループ一覧から起動・停止・再起動できます。グループの停止は自動復旧も抑止し、グループの起動・再起動で抑止を解除します。起動待ちの途中でも、グループの停止を選択できます。

起動間隔の基準や、結果不明時の扱いは[アプリグループの動作](../reference/applications.md#アプリグループ)を参照してください。グループを削除してもアプリの登録は残り、実行中のアプリは停止しません。

## 結果を確認する

操作後はアプリケーションの状態と運用ログを確認してください。
起動要求の送信だけで、対象アプリケーションが正常動作したとは判断できません。
結果不明の場合は、プロセスと元の操作記録を確認してから再操作してください。
