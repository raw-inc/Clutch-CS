# クラスターの設定を保存・復元する

[ドキュメント一覧](../README.md)

クラスターの共通設定とワークフローを、一つのZIPファイルに保存できます。バックアップからの復元や、別のクラスターへの移行に利用してください。ログ本文・履歴を含めるかどうかも選択できます。

## 保存される内容

| 対象 | 内容 |
| --- | --- |
| 共通設定 | タイムゾーン、PCグループ、ファイル処理の方針、安全確認、ログ・データの保持設定、ライブ編集など |
| ワークフロー | 通常のWFとレシピの定義、保存済みの版、現在使用している版、反映方法 |
| ログ（任意） | クラスター内の各Coreが保持する、書き出し開始時刻までのログ本文・履歴 |

**復元すると、書き出し時に有効だった設定がすぐに反映されます。** 保存済みでもまだ反映していない変更がある場合、その変更は復元後も未反映のまま残ります。

PC固有の `contents.toml`、ネットワーク設定、サービス登録、ClientHostの接続・表示設定、アプリケーション登録、シークレットの保存値は含みません。実行途中の状態、過去の実行結果・操作記録、WFが扱うファイル本体も対象外です。復元先には、WFで使うノード、スクリプト、ファイル、シークレットなどを別途用意してください。

## WebUIから書き出す

1. 書き出し元のクラスターと、使用可能なCoreを選択してください。
2. Dashboardの **Settings & maintenance** を開いてください。
3. 「クラスターのアーカイブ」で、必要に応じて「保持中のログ本文・履歴を含める」を選択してください。
4. 「アーカイブを書き出す」を押し、ZIPファイルをダウンロードしてください。

ログを含める場合は、クラスター内の全参加Coreが `Ready` である必要があります。取得できないログがあれば書き出しを中止します。既に削除されたログは復元できません。

## セットアップから復元する

1. **Clutch-CS-Setup.exe** で「修復」を選択してください。
2. 復元先のクラスターを一つ選択してください。複数の通信経路が表示された場合は、使用する経路を一つ選んでください。
3. 「アーカイブから復元する」を選び、ZIPファイルを指定してください。
4. 「復元先にだけあるワークフロー」の扱いを選択してください。
5. 次の画面で、追加・上書き・削除されるWFとログ件数を確認し、復元を開始してください。

| 復元先にだけあるWF | 動作 |
| --- | --- |
| 残す | 取り込み元にないWFは残します。 |
| 削除して取り込み元にそろえる | 取り込み元にないWFは削除します。 |

どちらの場合も、同じIDのWFは上書きされ、新しいWFは追加されます。共通設定も取り込み元の設定で上書きされます。

復元先の全参加Coreが `Ready` で、設定の競合が解消されている状態で実行してください。

## CLIから操作する

以下では実行ファイルを `contents-cli` と表記します。配布物の `files/cli/ReArtWord.Contents.BackgroundService.CommandLine.exe` に読み替えてください。`--url` は手元のClientHost、`--cluster` と `--peer` は操作先を指定します。

設定とログを書き出す場合は、次のように実行してください。ログが不要な場合は `--logs true` を省略できます。保存先には、既存のファイルと重ならない名前を指定してください。

```powershell
contents-cli --url http://127.0.0.1:5081 --cluster studio-cluster --peer peer-a archive export --file C:\Backups\studio.zip --logs true
```

復元は、変更内容の確認と実行の二段階で行います。まずZIPファイルを指定して、変更内容を確認してください。`merge` は復元先にだけあるWFを残し、`replace` は削除します。省略時は `merge` です。

```powershell
contents-cli --url http://127.0.0.1:5081 --cluster restored-cluster --peer peer-a archive preview --file C:\Backups\studio.zip --mode merge
```

応答の `response.added`（追加）、`replaced`（上書き）、`deleted`（削除）、`logEntries`（ログ件数）を確認してください。復元する場合は、返された `operationId` と `response.confirmation` を指定してください。

```powershell
contents-cli --url http://127.0.0.1:5081 --cluster restored-cluster --peer peer-a archive import --id "<operationId>" --confirmation "<confirmation>"
contents-cli --url http://127.0.0.1:5081 --cluster restored-cluster --peer peer-a archive status --id "<operationId>"
```

確認後に復元先の設定変更やCoreの再起動があった場合は、復元を開始できません。もう一度 `archive preview` を実行し、変更内容を確認してください。書き出し・事前確認には、`--operation-id` で操作IDを指定することもできます。

## 復元結果を確認する

結果には、設定の保存、設定の反映、ログの取り込みの成否が別々に表示されます。ログは設定の反映後に取り込まれるため、設定の復元だけが完了している場合があります。

取り込んだログは、元の時刻と発生元を保持して、復元を受け付けたCoreに保存されます。同じログが既にある場合は重複して取り込みません。復元後もログ保持設定が適用されるため、保存期間を過ぎたログは整理の対象になります。

通信断やCoreの再起動で結果を確認できなかった場合は、同じクラスター・Coreと操作IDで `archive status` を実行してください。結果が `unknown` の場合は、次のコマンドで再確認できます。

```powershell
contents-cli --url http://127.0.0.1:5081 --cluster restored-cluster --peer peer-a archive reconcile --id "<operationId>"
```

`archive reconcile` は復元をやり直すコマンドではありません。復元が完了したか確認できない間は、対象のWFと共通設定の編集が保留される場合があります。結果を確認してから、次の操作に進んでください。

## ファイルの上限と保管

ZIPファイルと展開後の内容は、それぞれ最大1 GiB、設定本文は最大16 MiBです。ログを含めると上限を超える場合は、設定だけを書き出し、必要なログは[ログ画面](logs.md)で別途取得してください。

Core上では、完了から24時間を過ぎた作業ファイルや、24時間以上進んでいない転送のファイルを、次のアーカイブ処理の終了時に整理します。ダウンロードを始めたファイルは、その時点から24時間保持します。操作記録と、結果不明の処理に必要なファイルは保持します。ダウンロードしたZIPファイルは利用者が保管してください。
