# クラスターを管理する

[ドキュメント一覧](../README.md)

Dashboard では、PC の稼働状態、ワークフローの活動、直近のログを確認できます。
設定を変更した後は「保存できたか」と「実行に反映されたか」を分けて確認してください。

## 日常の状態を確認する

1. **Dashboard** を開き、**All clusters** または **Selected cluster** を選択してください。
2. PC・ピアの状態、稼働版、最終確認時刻を確認してください。
3. CPU・メモリなどのグラフ、ワークフローの活動、直近ログから変化を確認してください。

同じ PC に複数のピアがある場合、PC の資源使用量は重複して集計されません。
値が取得できない場合は「—」や未確認として表示されます。使用量がゼロになったことを意味しません。

## 保存・共有・反映を確認する

| 段階 | 意味 |
| --- | --- |
| 保存 | 設定の内容が保存された状態 |
| 共有 | 同じクラスターの対象ピアと保存内容を共有した状態 |
| 反映・有効化 | その版を新しい処理に使用する状態 |

競合や保護用スナップショットの失敗があると、新しい設定への反映が保留される場合があります。
画面下部の **Storage status** では、保存済みの版、使用中の版、復旧に使える版と、未保存・未共有の状態を確認できます。

設定変更は開始済みの一回の処理には反映されません。変更後に始まる処理で結果を確認してください。

## 競合や通信断がある場合

内容が競合した場合は、画面または CLI で候補を比較し、採用する内容を選択してください。
対象の版が変わった場合は、内容を再確認する必要があります。

明示的に離脱させたピアは、PC を再起動しても自動では再参加しません。
再参加時には、離脱中の変更とクラスター側の変更を比較できます。

通信断だけで処理の成否を判断しないでください。
「失敗」「未実行」「結果不明」は別の状態です。結果不明の場合は元の操作 ID を使って確認してください。
