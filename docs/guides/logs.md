# ログを調べる

[ドキュメント一覧](../README.md)

LogViewer では、処理が失敗した理由や、ワークフローの一回の実行に関連する記録を検索できます。
通信が途切れた操作は、同じ操作 ID の結果を確認してから次の操作を判断してください。

## 条件を指定して検索する

1. **LogViewer** を開いてください。
2. 検索範囲を確認してください。既定は「観測可能なすべてのクラスター」です。接続中のピアだけを調べる場合は範囲を変更してください。
3. 日時、レベル、ワークフロー、ノード、関連 ID、本文など、分かる条件を指定してください。
4. 検索を実行し、ログの詳細を開いてください。

日時は項目名に表示されたタイムゾーンで解釈されます。
表示用タイムゾーンは Dashboard の「設定・保守」→「表示設定」で変更できます。

「直近の履歴のみ検索する」は既定で有効です。これは日数ではなく、圧縮されていないログに検索範囲を絞る設定です。
古い記録が見つからない場合は、この設定を無効にして検索してください。

## 一回の処理を追う

ワークフローの実行 ID（`causationId`）で絞り込み、終了ログと、各ノードを実行したピアのログを確認してください。

| 記録 | 読み方 |
| --- | --- |
| `workflow.unsuccessful` | 失敗・結果不明・未実行などを含む終了記録。対象ノードと理由を確認できます。 |
| `workflow.cancelled` | 取消を確認できた処理 |
| `node.exception` | ノード実行時の例外 |
| `parentExecutionId` | 別の信号から始まった子実行を、元の実行へたどるための ID |

入力や出力の本文、秘密値は常に記録されるわけではありません。
ログの取得先が応答しない場合や詳細が省略された場合は、その範囲を未確認として扱ってください。

## 継続して監視する

自動再取得は既定で無効です。
必要な場合は 5・10・30・60 秒から間隔を選択してください。次ページを開くと自動再取得は無効になります。
取得できなかった場合は前回の結果が残るため、更新時刻と未確認表示も確認してください。

## ログをファイルに保存する

検索条件を確認してから **.logで保存** を押してください。画面で開いていない続きのページも、同じ条件で検索して一つのUTF-8ログファイルに保存できます。
日時には画面の表示タイムゾーンが適用され、本文に加えて記録済みの詳細情報も含まれます。取得できなかった範囲はファイル末尾の `Summary`、省略された詳細は各ログの `omission` で確認してください。

テキストとJSONを別ファイルで保存する場合は、**ZIPをダウンロード** を押してください。ZIPにはテキストとJSONのログ、検索条件の `request.json`、取得結果の `summary.json` が含まれます。
未確認の取得先や出力上限への到達は `summary.json` で確認できます。
保持期限を過ぎるログを保護するスナップショットではありません。

検索・記録の上限は[クラスターの動作](../reference/cluster-operations.md#結果の確認)、保存期間や圧縮は[ログ・履歴の保存設定](../reference/history-storage.md)を参照してください。
