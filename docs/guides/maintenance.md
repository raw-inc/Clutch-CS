# 更新・修復・アンインストール

[ドキュメント一覧](../README.md)

配布物の **Clutch-CS-Setup.exe** から、更新・修復・アンインストールを実行できます。
処理を始める前に、対象のクラスター・PC と実行内容を確認してください。

## 更新する

1. 使用する版の配布 ZIP を展開し、セットアップを起動してください。
2. 「更新」を選択してください。
3. 使用するネットワークを選択し、検索結果を確認してください。
4. **CoreService** では、全クラスター、指定したクラスター、指定したピアから対象範囲を選択してください。
5. **WebClient** では、このPCと接続先PCのうち、更新する管理画面にチェックを入れてください。CoreServiceとは別に選択できます。管理画面だけを更新する場合は、CoreServiceの対象範囲を「ピア」にしてチェックを外してください。
6. 更新方式を選択してください。
7. 対象一覧と実行内容を確認し、確認欄にチェックを入れて更新を開始してください。
8. 進捗と完了結果を確認してください。詳細欄では、CoreServiceとWebClientそれぞれの結果を確認できます。

| 更新方式 | 動作 |
| --- | --- |
| 処理中の対象は更新しない | 処理中のCoreServiceは更新せず、それ以外を更新します。 |
| 処理を停止して更新する | 選択したCoreServiceで新しい処理の受け付けを止め、実行中の処理を停止してから更新します。 |
| 1台ずつ順番に更新する（Fleet Update） | CoreServiceを1件ずつ更新します。更新後の起動とクラスターへの参加を確認してから、次の対象へ進みます。 |

Fleet Updateでは、ほかのPCの稼働状況も確認します。クラスターの稼働を維持できない対象は保留し、更新できる対象から進めます。詳しい条件は[更新の仕様](../reference/update-process.md)を参照してください。

CoreServiceの更新ファイルは TCP を優先して転送します。
送信元の PC に CoreService をインストールする必要はありません。
未対応の転送先や TCP 接続を開始できない場合は UDP を使用します。転送開始後の切断では、別方式での自動再送は行われず、元の結果の確認に進みます。

WebClientの更新対象は、セットアップで導入され、自動起動が登録された稼働中の管理画面です。接続先PCはWindowsに対応し、そのCoreServiceに関連付けられた管理画面が表示されます。ユーザー権限で使っている管理画面は、その利用者がサインインして起動している状態で更新してください。

接続先のCoreServiceがWebClient更新に未対応の場合は、CoreServiceも更新対象に含めてください。セットアップはCoreServiceの更新成功を確認してから、WebClientを更新します。接続先への転送にはCoreServiceへのTCP接続が必要です。表示されない管理画面や接続できないPCは、そのPCでセットアップを起動して更新してください。

WebClientの設定、保存データ、ポート番号、起動方法は保持されます。更新中は管理画面への接続が一時的に切れます。新しい版の起動に失敗した場合は旧版へ戻し、復帰を確認した結果が表示されます。

管理画面から更新する場合は Dashboard の **Settings & maintenance** を使用できます。
複数クラスターの一括更新、日時予約、CLI の操作は[更新の仕様](../reference/update-process.md)を参照してください。

## 更新に失敗した場合

元の操作 ID と、対象ごとの入れ替え・旧版への復帰・起動確認の結果を確認してください。
結果不明の対象がある場合は、先にその状態を確認する必要があります。

旧版への復帰が確認できた失敗と、復帰したか分からない状態は別です。
再試行や未着手の対象の更新は、元の結果を確認してから開始してください。
手動での確認方法は[トラブルシューティング](troubleshooting.md)に記載しています。

## 修復する

1. セットアップで「修復」を選択してください。
2. 検索された状態を確認し、「問題を自動で修復する」「プログラムを入れ直す」「アーカイブから復元する」のいずれかを選択してください。
3. 「プログラムを入れ直す」では対象と、データを保持するか再同期するかを指定してください。
4. 実行内容を確認して開始し、完了後の参加状態を確認してください。

データを再取得するには、同じクラスター内に正常な別のピアが必要です。
修復完了後は Dashboard で `Ready` と同期理由を確認してください。

「アーカイブから復元」では、共通設定・WFと、アーカイブに含まれるログを一括で取り込めます。復元先にだけあるWFを残すか削除するか選択し、変更内容を確認してから実行してください。復元すると、書き出し時に有効だった設定がすぐに反映されます。詳しい手順は[クラスターの設定を保存・復元する](cluster-archive.md)を参照してください。

保守操作の状態ファイルに読取りエラーや不正な内容がある場合、CoreServiceは停止せず、保守保留を維持して再確認します。WARNログに操作IDが記録されます。結果不明の操作は再実行せず、元の操作結果と対象PCの稼働状態を確認してください。

## アンインストールする

1. セットアップで「アンインストール」を選択してください。
2. クラスター・ピア・全体から削除する範囲を指定してください。
3. データと設定を残すか選択してください。Web クライアントの削除有無も選択できます。
4. 実行内容と警告を確認してからアンインストールしてください。

Web クライアントは、他の PC の管理にも使用できます。
この PC の CoreService を削除した後も使う場合は、Web クライアントを残してください。
