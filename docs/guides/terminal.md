# ターミナルを使う

[ドキュメント一覧](../README.md)

Terminal は、ピア上のシェルをブラウザーから操作する機能です。作成したセッションは CoreService が管理するため、ブラウザーを閉じてもシェルは動き続けます。

## 接続と終了

1. ヘッダーの `Terminal` を開き、左側のクラスター一覧からピアを選択してください。
2. `Shell` で使うシェルを選び、`＋ User session`（ユーザー実行）または `＋ Administrator`（管理者実行）を押してください。候補には実行ファイル名と絶対パスを表示し、先頭の候補が既定で選択されます。
3. 既存のセッションを操作する場合は、共有セッション一覧で `Take over` を押してください。操作権が現在の画面へ移り、以前の画面からの入力は受け付けなくなります。
4. 画面との接続だけを切る場合は `Disconnect`、シェルを終了する場合は `Terminate` を押してください。画面移動やブラウザーの終了でも、シェルは終了しません。

## シェルの選択

利用できるシェルは CoreService の起動時に検索します。シェルの追加・削除や PATH の変更を反映するには、CoreService を再起動してください。選択の変更は次に作成するセッションへ適用されます。

| OS | 検索する場所 | 既定の優先順 |
| --- | --- | --- |
| Windows | PATH と標準のインストール先にある PowerShell、Windows PowerShell、cmd、bash、sh、Nushell、Git Bash | pwsh → Windows PowerShell → cmd |
| Unix 系 | `SHELL`、`/bin/sh`、`/etc/shells`、PATH 上の既知のシェル | 有効な `SHELL` → `/bin/sh` |

PowerShell 7 は Program Files 配下の `PowerShell` と `WindowsApps/Microsoft.PowerShell_7.*` も検索します。PATH にない Store 版はほかの候補の後へ追加します。Store 版は利用者のパッケージ権限によって DLL を読み込めない場合があるため、通常ユーザーで使う場合は通常の PowerShell 7 配置を推奨します。

候補の一覧は CoreService の実行アカウントから確認できる範囲で作り、最大 64 件を表示します。実行ファイルの存在と、Unix では実行ビットを確認します。シェルを起動して試すことや、全ディスクの検索は行いません。

選択したシェルが削除された場合や、権限・依存関係に問題がある場合は、作成失敗として理由を表示します。別のシェルへの自動切替は行いません。一覧を取得できないときは新規作成を無効にしますが、既存セッションへの接続は引き続き確認できます。

## セッションの共有

共有セッション一覧は左側の上部、その下にクラスター・ピア一覧を表示します。ピアを選ぶ前でも、発見したピアのセッションを確認できます。別の ClientHost から同じセッションへ接続し、操作権を引き継ぐこともできます。

ClientHost が一覧の取得をまとめて行い、ブラウザーへ返します。取得は最短 3 秒間隔、最大 4 件の並列実行です。取得できなかったピアは、前回の情報であることを示して表示します。

### 通信と再接続

端末の入出力には、`Browser ↔ WebSocket ↔ ClientHost ↔ TCP ↔ CoreService` の継続接続を使います。ClientHost から CoreService への TCP 通信を許可してください。接続には指定した IP と、有効期間が短い一回限りの接続許可を使います。

端末のプロセスは CoreService が管理します。画面との接続が切れても動作を続け、出力・操作権・終了状態が変わると通知します。短時間の入力をまとめ、受け付けた連番を確認してから次を送ります。端末のリサイズは、実際に行数・列数が変わった場合だけ行います。

出力は最大 64 KiB ずつ送り、ブラウザーでの描画完了を待って次を送信します。CoreService が保持する出力は 256 KiB で、表示が遅れて保持範囲を越えた場合は欠落を表示します。

再接続時は、保存済みの出力を表示し終えるまで入力と端末からの応答を止めます。過去の色問い合わせなどに再び応答してシェルへ入力が混入するのを防ぐためです。新しいセッションや再接続後に届いた問い合わせには通常どおり応答します。

## 実行ユーザーと権限

Windows のユーザー実行は通常の権限で起動します。使用するアカウントは、CoreService の起動方法によって変わります。

| CoreService の起動方法 | ユーザー実行で使うアカウント |
| --- | --- |
| 通常ユーザーで起動 | 同じユーザー |
| 管理者として起動 | 同じユーザーの通常権限 |
| LocalSystem サービス | コンソールにログインしているユーザー |

管理者実行では、同じ対象ユーザーの昇格済みトークンを使います。必要な権限を取得できない場合は作成ボタンを無効にし、API からの要求も拒否します。UAC の確認画面や別アカウントの資格情報を使って昇格する機能はありません。作成前に対象ユーザーが変わった場合も、セッションは作成しません。

CoreService が LocalSystem で動き、コンソールにログイン中のユーザーがいない場合は、ユーザー実行を無効にし、管理者ボタンを `＋ SYSTEM実行` に切り替えます。作成したセッションには `SYSTEM` と表示します。

画面ロック中でもユーザーのトークンを取得できる場合は、そのユーザーを使います。トークンへのアクセス拒否を、未ログインとみなして SYSTEM 実行へ切り替えることはありません。Unix 系では、CoreService の実効権限で起動できるモードだけを使用できます。

### 厳密な非昇格（試験的設定）

`/terminal?experimental=true` を開くか、[試験的な機能を常時有効にする](web-client.md#試験的な機能を有効にする)と、`厳密な非昇格: OFF / ON` を選べます。既定は OFF です。ON では必要に応じて本人のトークンを Windows の LUA 規則で制限し、通常シェルを Medium 整合性で起動します。子プロセスを起動するためのアクセス権も、その起動用トークンに設定します。

設定は選択した CoreService に保存され、次に作成するセッションへ適用されます。CoreService の再起動やブラウザーの変更後も有効で、URL から `experimental=true` を外しても保存値は変わりません。起動済みのセッション、Windows と CoreService 自体のセキュリティ設定は変更しません。

別の画面で設定が変更されていた場合は保存を拒否します。保存結果を確認できない場合は、CoreService から状態を取得し直します。

## 画面とキーボード操作

セッション作成ボタンの隣に接続解除ボタンがあります。右側のアイコンでは、操作欄を含む画面全体と、端末表示だけの全画面を切り替えられます。Esc、接続解除、セッション切替、画面移動で全画面を終了します。全画面を閉じても共有シェルは終了しません。

端末だけの全画面でも右クリックメニューを使用できます。表示領域が変わると、余白を除いた内側の寸法に合わせて端末の行数・列数を更新します。

コピー・貼り付けは、ツールバー、右クリックメニュー、`Ctrl+Shift+C`／`Ctrl+Shift+V` から行えます。ブラウザーがクリップボードへのアクセスを許可しない場合は、理由と利用できるショートカットを表示します。

矢印キー、Tab、Ctrl+C なども使えます。貼り付けは端末の bracketed paste 設定に従い、8 KiB ずつ順に送信します。入力には連番を付けて重複を防ぎ、受け付けたことを確認できない入力は自動で再送しません。

端末の下には補助キーを表示します。小さい画面では横にスクロールできます。

- Ctrl・Alt・Shift は、もう一度押して解除するまで有効です。文字入力、矢印キー、ほかの補助キーと組み合わせられます。
- Esc、Tab、Del、Backspace、Enter、矢印、Home／End、PageUp／PageDown を直接送信できます。
- Shift は英字の大文字化、Tab、移動キーに適用します。記号はソフトウェアキーボードから入力してください。
- 接続先の変更、切断、貼り付け、ウィンドウからの移動時は Ctrl・Alt・Shift の選択を解除します。画面幅の変更では選択を維持します。

補助キーは端末アプリケーションのカーソルキーモードに従います。OS 上で修飾キーを押したままにする操作ではありません。未接続など、入力できない状態ではボタンを無効にします。

## セッションの上限と終了

| 項目 | 上限 |
| --- | --- |
| ピアごとのセッション数 | 16 |
| セッションごとに保持する出力 | 256 KiB |
| 画面のスクロールバック | 3,000 行 |

シェルは `Terminate` または CoreService の終了まで動作を続けます。CoreService の再起動後にシェルを復元する機能はありません。終了済みの古いセッションは自動で削除します。

## 同梱ライブラリ

対話端末には[Porta.Pty](https://github.com/tomlm/Porta.Pty) 2.2.2と[xterm.js](https://github.com/xtermjs/xterm.js) 6.0.0、addon-fit 0.11.0を使用します。xtermの配信資材とMITライセンスは`Client/wwwroot/vendor/xterm`に同梱し、画面表示時に外部CDNへアクセスしません。

実装とブラウザー試験は[ソース構成](../development/architecture.md#terminal-の実装とブラウザー試験)を参照してください。
