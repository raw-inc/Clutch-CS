# 通信キャプチャの検索・保持・実行条件

## 取得と閲覧

1. 左側の**Host・ネットワークインターフェース**から取得するホストを選択してください。同じホストが複数クラスターに参加していても一つにまとめ、利用可能なCoreServiceを優先して開始時の実体を固定します。各ホストのアダプター欄は個別に折りたため、折りたたんでも選択や取得状態は変わりません。狭い画面ではホスト一覧をキャプチャ一覧の上へ配置します。
2. 各ホストの NIC と取得方式を選択してください。最大16host、ホストごとに最大16取得元です。`pktmon`と`pcap`を混在させることもできます。利用できない機構はその理由を表示します。
3. **Start** を押して、選択した取得元のキャプチャを開始してください。取得元を変更するときは先に**Stop**を押してください。一部の取得元だけ開始できなかった場合は、成功した取得元と失敗理由を区別します。
4. 行を選ぶと、その一件の原本と解析結果を取得してHex／ASCIIを表示します。詳細が保持上限から外れた場合や取得側へ接続できない場合は、その旨を表示します。上へスクロールすると閲覧位置を維持し、**最新に追従**で末尾へ戻ります。新着のたびに選択詳細を消し直すことはありません。

送信元の **Source** 列と宛先の **Destination** 列は、**IP:Port** と **Host:Port** を切り替えられます。既知のホストと NIC の IP を関連付け、名前が分からないアドレスは IP 表示を保ちます。TCP／UDP のポート番号はどちらの表示でも残します。ポート番号を持たない ARP 等には補いません。表示時刻は Dashboard で選択した表示用タイムゾーンに従い、既定は UTC です。

**Stop**は取得を止め、既に取得した内容を閲覧できる状態にします。**クリア**は保持内容を除外しますが、取得状態と検索条件を維持します。画面を離れると接続と取得プロセスを終了します。切断後に取得を暗黙に再開せず、再開する場合は、ホストの再取得と Start を操作してください。

## リアルタイム検索

通常検索はブラウザー内で完結し、入力を変更すると一覧へ即時に反映します。番号・時刻・プロトコル・IP・ポート・既知のホスト名と、Infoに含まれるパス・値を検索します。表示をホスト:Portへ変えてもIP検索を利用できます。比較は大文字・小文字を区別しません。通常検索のために原本をダウンロードしたり、取得側へ問い合わせたりしません。

```text
OSC AND (192.168.10. OR 192.168.20.) AND "/address/to" AND "ready"
server-host AND "/status"
"and" OR "or"
```

最初の例は、指定した IP アドレスの接頭辞と、OSC アドレス `/address/to`、値 `ready` が一覧情報に含まれる通信を検索します。検索式の IP アドレスは文字列として照合され、サブネットの指定ではありません。

- 空白で区切った`AND`／`OR`を演算子として扱います。小文字でも同じです。ANDをORより先に評価し、括弧で順序を指定できます。
- 引用符内の`"and"`／`"or"`は文字列です。空白や括弧を含む文字列も引用符で囲めます。引用符内では`\"`と`\\`を使用できます。
- 演算子を書かずに語を空白で並べた場合はANDです。
- 入力途中で括弧や引用符が閉じていない場合は、その旨を表示し、前回の有効な検索を維持します。

`experimental=true`では**Advanced Search**を追加表示します。Textでは詳細・本文を同じ論理式で、Hexでは`2F 7A 6F 6E 65`のような連続したバイト列を取得側で検索します。結果は通常検索とANDで組み合わせます。入力変更を短くまとめ、同じホストへ検索要求を積み上げません。応答を待つ間も通常検索は動作します。

検索は表示条件です。非一致の原本も取得側の保持上限内では残ります。Advanced Searchはその時点で取得側に残る原本が対象で、一覧だけが残った期限切れの詳細や、回線混雑で配送されなかった一覧を復元する機能ではありません。取得時に欠けた原本や暗号化された通信の本文までは検索・解析できません。

## 重複観測と保持上限

同じパケットを複数ホスト、複数NIC、または同じNICの異なる取得機構で観測した場合は、パケット指紋と時刻を照合し一行へまとめます。観測数と取得元は詳細から確認できます。同じ取得元で繰り返し観測した別の送信は別件として保持し、他の取得元の観測と一対一で対応させます。

完全なIPパケットでは、リンク層・パディング・TTL・チェックサムの観測差を正規化します。IP識別子、TCPシーケンス、ポート、本文は同定情報として保ちます。既定の時刻照合幅は250msです。ホストの時計差がこれを超える観測や、切り詰められた原本は別件として残る場合があります。独立して送信された完全同一のパケットをすべての観測点で区別できる保証はありません。

保持上限は既定で**50,000件・概算320MiB**です。ブラウザーの一覧にこの上限を適用し、原本・詳細もClientHostの接続別メモリに同じ合計上限を設け、選択ホスト数で配分します。各領域でどちらかの上限へ達したら古い内容への参照を除外します。全ホストが同じ量を流すとは限らないため、一覧に残る行の詳細が先に期限切れとなる場合があります。

`experimental=true`では件数、概算容量、重複照合幅を変更できます。件数は100～250,000件、容量は1～1,024MiB、照合幅は0～2,000msです。0msでは重複統合を無効にします。設定と取得履歴は画面を閉じるまで保持されます。

表示する受信数、重複統合数、保持上限による除外数、取得機構の欠落数、ブラウザーへの配送省略数は別の指標です。遅い回線では最大256件の未送信一覧通知を保持し、古い通知から省略します。ローカル取得の読取りをブラウザーの速度で止めず、原本の保持は別の上限内で継続します。取得機構の統計はStartごとの値で、クリアではリセットしません。容量は「一覧」と「原本」を別々に表示する概算で、プロセス全体のメモリ使用量ではありません。

**操作履歴・キャプチャ本文・検索式を永続化しません。** ワークフロー履歴、共有状態、ログの圧縮・保存期間・同期の対象にせず、ファイルへの退避も行いません。Clear・画面離脱・接続終了で原本を破棄します。接続失敗などの一般的なシステム診断へも本文や検索式を転載しません。

接続の拒否や破損では、そのセッションだけを終了し、CoreServiceの一般診断に `Session.Failed` を残します。記録するのは機能名、セッション識別子、発生段階、例外型であり、パケットや操作の履歴を保存するものではありません。

## 実行環境と構成

WindowsではOSのPacket Monitor API、または導入済みのNpcapを使用します。Packet Monitorは管理者権限が必要です。Linux／macOSでは導入済みのlibpcapを使用し、OS側のキャプチャ権限が必要です。ドライバーを同梱・自動導入せず、他アプリの取得セッションやNIC設定を変更しません。

Npcap は独自ライセンスのソフトウェアです。利用台数や再配布の条件は [Npcap のライセンス](https://npcap.com/#license)を確認してください。Wireshark などに限定された利用条件の例外は、Clutch-CS での利用には適用されません。Windows 標準の Packet Monitor を選ぶ場合、Npcap の導入は不要です。

ブラウザーは既存のClientHost（通常5081）の同一origin `/client/signal-scope` へWebSocket接続します。Tunnel／リバースプロキシへ追加ポートを公開する必要はありません。CoreServiceとのTCPは既存の内部管理ネットワークに限定します。

CoreServiceは配布資材内の`tools/signal-capture/SignalCapture`を専用プロセスとして起動します。Windowsでは拡張子が`.exe`です。取得・汎用解析部分をNativeAOTで発行し、CoreServiceとはバイナリpipe、ClientHostとは期限付き許可値で開始するTCP、ブラウザーとは同一originのWebSocketで接続します。

CoreServiceからClientHostまでの内部経路では原本を運び、ClientHostからブラウザーへの通常配信は一覧情報だけにします。原本のBase64化や共有状態への保存は行いません。ClientHostが原本保持・Advanced検索・選択時の詳細配信を、ブラウザーのWeb Workerが一覧保持・重複観測の統合・通常検索を担当します。

監視自身のTCP経路は取得対象から除外します。WindowsのClientHostでは、信頼するローカルプロキシの実TCP接続から所有プロセスを照合し、その外側のTCP／UDP端点も除外します。外側の接続変更は再観測して反映し、同じプロキシプロセスで多重化した通信も除外対象です。プロキシの所有者を確認できない場合は自己観測の増幅を避けて取得接続を終了します。

Windows以外のClientHostではこのプロキシ追跡が未対応のため、キャプチャ画面はClientHostへ直接接続して使用してください。原本キューとHTTP再構成には個別の上限があり、遅い読み手のために無制限に蓄積しません。ブラウザーの離脱、通信切断、CoreService終了時には子プロセスまで回収します。CoreServiceごとの同時表示接続は最大4件です。

オフライン配布パッケージは対応OSのNativeAOTビルド環境で取得プロセスも同時に発行し、同じリリースのハッシュ検証対象へ含めます。NativeAOTを利用できない32bit Linux ARMでは、このキャプチャ機能を含めません。OS・取得機構が利用できない場合も他のCoreService機能へ影響させず、取得画面に利用不可を表示します。
