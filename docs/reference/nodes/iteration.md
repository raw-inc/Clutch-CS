# 繰り返しノード

[ノード一覧](README.md) · [サンプル](../../../samples/generic-iteration/README.md)

Control カテゴリの **ForEach** は配列を順に、**Parallel ForEach** は指定した同時実行数まで並列に処理します。各要素の繰り返す処理には、既存の通信・ファイル・プロセス・変換などのノードを接続できます。

| ノード | 種類ID | 動作 |
| --- | --- | --- |
| ForEach | `control.forEach` | 一要素の繰り返す処理全体が終わってから次へ進む |
| Parallel ForEach | `control.parallelForEach` | `maxConcurrency` 件まで同時実行。既定4、1〜32 |
| ForEach End | `control.forEach.end` | 通常結果を入力順のJSON配列、Key-Value結果を辞書にまとめ、後続を一回だけ実行 |

## 接続

1. 開始ノードの `value` へJSON 配列または辞書を渡してください。辞書の `item` は一組のKey-Valueで、反復順は保証しません。
2. `item` を各要素の処理へ接続してください。`index` は0から始まる添字、`count` は入力配列の要素数です。この3つの出力端子からの接続は要素ごとに動きます。
3. 結果をまとめる場合は、開始ノードの `loop` とEndの `loop` を直接接続し、要素ごとの処理結果を End の `value` へ接続してください。
4. Endの `value` から先は、全件完了後に一回だけ動きます。開始ノードの共通 `result` も全件終了後の結果です。

**Endは省略できます。** その場合は、`item`／`index`／`count` からつながる末端までを各要素ごとに実行します。ファイル送信やログ出力など、結果配列が不要な処理にも使えます。Endなしでも、ワークフローの完了は開始済み繰り返す処理の実行結果を待ちます。

空配列・空辞書は0回の正常完了です。Endの入力がKey-Value型なら `{}`、それ以外なら `[]` を返します。Key-Value結果のキー重複は既定でエラーですが、Endの設定で後の入力による上書きも選べます。要素中の `null`、オブジェクト、配列はそのまま保持します。Endで集約する値はJSONです。バイト列は明示的にJSONへ変換するか、ファイル成果物の参照として渡します。

[`parallel-squares.json`](../../../samples/generic-iteration/parallel-squares.json) は `[2,3,4]` の各要素を二乗し、`[4,9,16]` を集約します。ノードの処理は場所に依存しないので既定のコーディネーターで動きます。`square` の実行先を別ピアにすれば、開始・終了と別のPCで要素を処理できます。

## 型と範囲

配列の要素型が推測できる場合は `item` のANYに型を併記します。整数配列は整数、オブジェクト配列は分かるプロパティまで伝播します。既知の文字列要素を数値演算へつなぐなど、明らかに不適合な接続を拒否します。空配列・混在配列・実行時まで不明の配列は断定せず、実行時の入力検証も適用します。数値範囲・整数性・外部結果の成功を型推測だけで保証しません。

繰り返す処理へ外側の共通値を入力できます。その値は親の依存が完了してから反復全体へ渡され、要素間で上書き・取り違えをしません。各ノードの実行先、設定版、共通運用版は一件の開始時に固定します。要素ごとに取り直しません。各ノードの重複実行方針と安全停止設定も適用されるため、繰り返す処理内ノードが直列化を選んでいる場合は、そのノードは並列になりません。

入れ子の反復も使えます。内側の結果を外側へ集約する場合は、内側Endから外側Endへ接続します。Endを省略した内側反復の出力を外側Endへ直接合流させる配線、部分的に交差する範囲、自分の完了結果を同じ繰り返す処理へ戻す配線、継続待受ノードを含む繰り返す処理は検証エラーです。

## 失敗・取消・保持上限

一要素で失敗・結果不明・取消が確定した場合、まだ開始していない要素は開始しません。実行予定だった枝の未実行も、別枝の成功で全体成功にしません。条件分岐で選択されなかった枝は通常どおり省略します。Parallel ForEachで既に開始した繰り返す処理は、その実行結果を待ちます。成功済みの副作用の巻戻しや、失敗した要素の自動再実行は行いません。

元待受ノードから明示取消した場合も、開始済み要求の実行ID・ピア実体へ既存の取消経路で要求し、残りの要素を開始しません。取消受付だけでは実停止とせず、確認できない結果はUnknownです。

一配列は最大4096要素、入れ子を含む一件の実行全体の反復開始も最大4096回、入れ子は16段までです。要素結果の保持・集約には一件の実行全体で16MiBの上限を設けています。詳細は要素ごとに容量を制限し、必要なら実際の成否を保つ要約に置き換えます。上限超過は失敗として残し、全件成功とは表示しません。これは保持結果の上限であり、進行中ノードの一時メモリを含むプロセス全体の最大メモリ保証ではありません。

実行結果の開始ノードには `iteration.count`（入力要素数）、`iteration.started`（開始した数）、`iteration.items`（添字順の結果）があります。各要素の結果は独立した実行結果または要約で、入力順序と完了順序を混同しません。
