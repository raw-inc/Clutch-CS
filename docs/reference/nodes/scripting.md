# スクリプトノード

[ノード一覧](README.md) · [サンプル](../../../samples/scripting/README.md)

WorkflowEditorで `script.csharp`、`script.python`、`script.javascript` を追加し、実行ピアを選択してください。コード入力が落ち着いた時やフォーカスを外した時に、画面に表示する解析先ピアへ検査を依頼します。「コードと型を解析」でも再確認できます。新規ノードは、解析した引数名と型に対応する個別入力を生成し、返却型を `value` 出力へ表示します。解析だけではユーザーコードを実行しません。

「引数の入力方式」では、引数ごとに入力する方法と、`arguments` ポートへ名前付き JSON オブジェクトをまとめて渡す方法を選べます。方式を切り替えるときは、先に引数の配線を外してください。固定値と Path 型は引き継ぎます。

コードや型の変更によって値・配線が合わなくなった場合は、検証結果で修正箇所を示します。値や配線は自動で削除しません。

たとえば `Run(int a, float b, string c)` の個別入力は `a`（integer）、`b`（number）、`c`（string）です。定義JSONでは `inputMode: "individual"` とし、ポート識別子は `$arguments.a` のように保存します。画面では元の引数名を表示し、`trigger` という引数も共通の開始入力と区別できます。一括入力を明示する場合は `inputMode: "object"` です。

C# の `long`／`System.Int64` は、`int64`（64 bit 整数）として扱います。戻り値、配列要素、オブジェクト・辞書の中の値にも型を保持します。OSC のパケットへ渡す場合は、値の大きさにかかわらず型タグ `h` を使います。通常の `integer` は、32 bit の範囲内なら `i` です。

既定値のある引数は、元の型がnull非許容でも任意入力になります。未入力・明示的な `null` は関数に定義した既定値を使用します。`0`・`false`・空文字はそのまま渡します。C#の `params T[]`、Pythonの `*args`、JavaScriptの `...args` は単一値または配列を受け取り、単一値は1要素、未入力・`null` は空の可変長引数として扱います。これらの規則は両入力方式に共通です。既定値式を解析時に実行することはありません。

## .NET10／C#14

コード欄には次のように `public static Run` を一つ記述します。

```csharp
public static long Run(long left, long right) => left + right;
```

個別入力の `left` へ2、`right` へ3を渡すと、`value` は5です。一括入力では `arguments` へ `{"left":2,"right":3}` を渡します。`System`、`System.Collections.Generic`、`System.Linq`、`System.Threading.Tasks` はあらかじめ参照されます。コード先頭の `using`、別名、`using static` に対応します。

NuGetパッケージはDashboardの「スクリプトパッケージの管理」から導入します。`#r` による個別DLL参照は扱いません。

専用Roslyn アナライザーは引数・返却型を検査し、WorkflowEditorの既存型に対応付けます。基本スカラー、nullable、一次元配列、List、string-key Dictionary、公開get/setプロパティと生成可能な既定コンストラクターを持つPOCOに対応します。ポート直下の`byte[]`はバイナリ、日時とGUIDはJSON文字列です。JSONオブジェクトや配列の内部にある`byte[]`はBase64文字列のまま扱います。

`params byte[]` はJSONの単一数値または数値配列を使用します。`object` はanyとしてJSON値を受け渡します。`Task<T>` の返却も完了まで待ちます。`byte[]`／`Task<byte[]>`の結果は元のバイト列として、ファイル作成や別C#ノードの`byte[]`個別入力へ接続できます。一括JSON入力で`byte[]`引数を渡す場合はBase64文字列を使います。

空配列は長さ0のバイナリ、nullableのnullはJSON nullです。通常の文字列をBase64らしいという理由だけで復号しません。Stream、循環型、ref/out、未対応CLR型は拒否します。

```csharp
public sealed class Row { public long Value { get; set; } }
public static long Run(Row[] rows) => rows.Sum(row => row.Value);
```

この場合の入力は `{"rows":[{"Value":10},{"Value":20}]}` です。JSONのプロパティ名と大文字・小文字を合わせます。

## Python

実行環境の選択欄から、実行ピアで検出・登録されたPythonを選べます。`pythonPath` の空欄はそのピアの既定環境です。明示した絶対パスは優先します。Dashboardでpipパッケージを導入済みで、選択したPythonがその構成と一致する場合は、解析時に専用仮想環境を採用します。実行は `-I` の独立モード、ASTだけを読む解析は `-I -S` で起動し、解析時はユーザーコード・import・site初期化を実行しません。

```python
def run(left: int, right: int):
    return left + right
```

型ヒント、リテラルの既定値、単純な返却式から確認できる型を使用します。文字列形式の型ヒントもASTとして読み、評価しません。不明な引数・返却型はanyとします。必要に応じて画面の型選択や入れ子の型定義JSONで具体化し、再解析できます。既知の型ヒントがある箇所はその型を優先します。`*values: int` の型ヒントは可変長引数の要素型です。Pythonのintをintegerとして宣言する場合、ワークフロー境界ではInt64の範囲を確認します。

## JavaScript（Node.js）

`script.javascript` はNode.js 24以降でES Modulesを実行します。`nodePath` は実行ピアの検出・登録済み候補から選べ、空欄では既定環境を使用します。npmを使わず組込み機能だけを使う場合も、既定環境があれば絶対パスの入力は不要です。既存の明示パスは維持します。

```javascript
export async function run(left = 0, right = 0)
{
    return left + right;
}
```

入口は名前付きの `export function run(...)` または `export async function run(...)` です。引数は他言語と同じ入力方式で渡し、Promiseの完了まで待ちます。`...values` の可変長引数に対応します。ジェネレーターと引数の分割代入は扱いません。

構文木から既定値・リテラル・確認できる式の型を推定します。引数やnpm呼出しの返却型などを推定できない場合はanyとし、画面の「推定できない型を選択」で具体化して再解析できます。可変長引数は既定でanyの配列です。手動で配列の型定義を指定すると要素型も検証します。解析時にユーザーコード・import・既定値式は実行しません。コードブロックのJavaScriptにも構文検査があり、接続先のスクリプトノードへ解析結果を反映します。

npmの `camelcase` を導入した例です。この例では `value` と返却型を `string` に選択します。

```javascript
import camelCase from 'camelcase';

export function run(value)
{
    return camelCase(value);
}
```

scoped package、`exports`のサブパス、CommonJS形式のパッケージもNode.jsの標準のimport規則で読み込みます。`node:path` などの組込みモジュールも利用できます。パッケージ名によるimportは固定したnpm環境に限定し、別のディレクトリーの `node_modules` へ代替しません。

返却値はJSONで表せる値を使用してください。`undefined`、非有限数、BigInt、循環参照、Dateなどの独自オブジェクトは成功として返しません。必要に応じて `toISOString()`、文字列、通常の配列・オブジェクトへ明示変換します。JavaScriptの整数範囲を超える値（±9,007,199,254,740,991より外）は文字列で受け渡してください。範囲外の整数入力は実行前に拒否し、出力も黙って丸めません。

## 保存・実行・資源制限

コード・言語・明示型・外部ランタイムの指紋に対応した解析結果を、設定の `analysis` に保存します。コード変更で古い解析は無効になります。元の配線や入力値は自動削除せず、再検査で不適合を確認します。各言語とも実行先で再解析・入出力検証します。パッケージを使う解析は `packageEnvironmentId` で構成を固定します。

共有先がパッケージ未導入でも定義を保存できますが、実行ピアに同じ構成がなければユーザーコードを開始せず `script.packages.environmentUnavailable` を返します。複数対象の一つで編集時解析が通っても、他の対象ピアの環境確認を済ませた意味にはなりません。

C#はCoreServiceの専用子プロセス、Python・JavaScriptは指定したランタイムの子プロセスで実行します。既定は30秒、入力・出力1MiB、プロセスメモリ観測256MiBです。`timeoutMs` は1～600,000、`maxBytes` は1KiB～16MiB、`maxMemoryMb` は64～4,096に設定できます。メモリは周期観測による停止で、OS sandboxや子孫全体のhard limitではありません。

信頼するコードを、実行ピアのOS権限で実行する機能です。

コード自身の例外は `failure`、入力型不正や古い解析は `notExecuted`、期限・取消・出力上限・出力型不適合・結果未確認は `unknown` です。停止しても外部ファイル・API等の副作用を取り消したことにはせず、自動再実行しません。

作業ディレクトリーは一回ごとの一時領域で、終了後に削除します。残す成果物には実行ピア上の明示した保存先を使用してください。入力ファイルはWindowsではユーザーTempの権限を継承し、Unixでは所有者だけがアクセスできるディレクトリーへ保存します。

CLIからは `script analyze --body analyze.json` を使用できます。入力例は `{"language":"csharp","code":"public static long Run(long value) => value + 1;"}` です。返った解析結果全体をノード設定の `analysis` に含め、`code` と実行先、入力値を設定して通常のworkflow validate/save/runへ進みます。

Pythonの場合は `pythonPath` と、必要なときだけ `manualContract` も解析要求へ含めます。

## スクリプトパッケージの管理

1. Dashboardで導入先のクラスター・ピアを選び、「スクリプトパッケージの管理」を開いてください。
2. NuGet・pip・npmを選び、パッケージ名やキーワードで検索します。検索結果から候補を選ぶと、説明、導入済みの版、公開バージョンを確認できます。PyPIはパッケージ名の完全一致・前方一致・部分一致で検索します。
3. インストールするバージョンを選び、「インストール・更新」を押してください。操作一覧が「完了」になるまで確認してください。NuGetはnuget.org、pipはPyPI、npmはregistry.npmjs.orgから推移依存も含めて導入します。検索・候補選択だけでは導入しません。「導入中」は受付状態であり、成功を示しません。
4. 実行先ピアを指定したC#／Python／JavaScriptノードで「コードと型を解析」を押して保存します。コードブロックからコードを渡す場合も、接続先のスクリプトノードの解析を更新します。

pipにはPython 3.10以降と `venv`・`ensurepip`、npmにはNode.js 24以降が必要です。検出・登録済みの環境、ピアの既定、または新しい実行環境のインストールを選べます。npmが標準配置にない場合は `npm-cli.js` の絶対パスも指定します。「パッケージ名と固定バージョンを直接指定」から、検索せずに既知の版を導入する方法も使用できます。

### Python／Node.jsの選択と導入

実行環境の候補は対象ピアのPATHとログインユーザーのPATH・標準導入先から検出し、対応版として起動できたものを表示します。「実行ファイルのパスを登録」は絶対パスの入力と「参照」に対応し、確認できたパスを次回以降の一覧へ残します。候補は選択欄を使うときに取得し、五分間共有します。「候補を再取得」で即時更新できます。登録・既定設定はピアローカルで、別クラスターの同じPCや他ピアへ自動で変更を広げません。

パッケージ管理画面の「選択した環境を既定にする」で既定を設定できます。「既定の実行環境」を選んで同じボタンを押すと自動検出へ戻します。解析・新しいパッケージ操作では、明示パス、設定した既定、既存パッケージ構成の実行先、自動検出の順に選びます。パッケージ構成を持たない保存済みスクリプトは、明示パスまたは現在の既定／自動検出を使用します。設定済み既定の実行ファイルが消えた場合は、別の環境へ暗黙で切り替えず利用不能を通知します。

「Pythonをインストール」「Node.jsをインストール」から、対象OS・CPU向けの公式安定版を選んで追加導入できます。Node.jsはLTS候補を先に表示します。保存先は対象PCでログイン中のユーザーのホーム配下です。WindowsサービスのSYSTEMプロファイルは使用せず、利用者を確認できない場合は受付を拒否します。

- Python: `<home>/.clutch-cs/runtime/py/<version>-<platform>/python.exe`
- Node.js: `<home>/.clutch-cs/runtime/js/<version>-<platform>/node.exe`

旧綴りの配置は、実行環境一覧の取得・更新時にログインユーザーの管理済みruntimeだけを新配置へコピーし、全ファイルの一致を確認してから登録と既定を移行します。保存済みワークフローの明示パスも確認済みの新配置へ解決します。実行中のプロセスや固定済みPython仮想環境・npm環境を壊さないため、旧配置は互換用として保持します。既存のパッケージ環境を暗黙に再構築しません。

使用中・アクセス不可・移行先と内容が異なる場合は旧環境を維持して移行保留を表示し、一覧更新時に再試行します。

追加導入はWindows x64／ARM64に対応します。他OSでは既存環境のPATH検出・明示登録を使用します。Pythonは `venv` と `ensurepip` を含むフル配布を使い、埋込み用配布は採用しません。

[PythonのWindows向け配布仕様](https://docs.python.org/3/using/windows.html)、[Pythonの公式配布一覧](https://www.python.org/ftp/python/index-windows.json)、[Node.jsの公式配布一覧](https://nodejs.org/download/release/index.json)を使用します。

取得は選択したCoreServiceから行い、実行環境のZIPをブラウザーへ中継しません。

SHA-256照合、展開先の検証、実行ファイルの版とpip／npmの検査に成功した後でのみ、そのピアの既定を切り替えます。既存バージョンとOSのPATHは変更しません。導入中に別の画面で既定が変更された場合は新しい選択を維持し、追加した環境を候補に残します。既存の保存済みスクリプトが固定しているパッケージ構成は変更しません。別の実行環境でパッケージを使う場合は、その環境へパッケージを導入して再解析・保存してください。

導入はピアごとに一件、最大15分で、同じホームへの同時導入も排他します。画面を閉じてもCoreServiceが操作を所有し続けます。CoreService停止後に未完了だった導入は結果不明として残し、自動再実行しません。応答が途切れた場合は「操作」からスクリプト実行環境の元操作IDを照会します。進捗の更新はメモリ上で行い、受付・処理段階・最終結果だけを永続化します。

### パッケージの検索と実行構成

パッケージの検索と公開版の取得はClientHostから公式配布元へ接続します。PyPIの公開名簿はClientHostの状態ディレクトリーで一日キャッシュし、更新に失敗した場合は取得済み索引を使用したことを表示します。索引は小さいチャンクで読み、全JSONや全パッケージをブラウザーへ展開しません。導入の通信・保存先は選択したピアです。

例としてNuGetの `Newtonsoft.Json` を導入すると、次のコードを使用できます。

```csharp
using Newtonsoft.Json;
public static string Run(string name) => JsonConvert.SerializeObject(new { name });
```

pipの `python-dateutil` を導入した例です。配布名とimport名が異なるパッケージがあるため、パッケージ自身の使い方に従ってください。

```python
from dateutil.parser import isoparse
def run(value: str) -> str:
    return isoparse(value).isoformat()
```

導入先はピアのデータディレクトリー配下の `script-packages` です。CoreServiceの更新で置換する実行物のディレクトリーや、システムPythonのパッケージ領域は変更しません。NuGet復元に実行先の.NET SDKは不要です。現在の.NET・OS向けのコンパイル参照、実行時DLL、ネイティブ資産を使います。MSBuildターゲットの実行、source generator、contentファイルのアプリへの自動コピーを前提とするパッケージは対象外です。

pipのソース配布やnpmのネイティブ拡張のビルドには、配布物が要求するコンパイラー等が別途必要です。npmは先にlockfileを作成し、`npm ci` と依存関係検査が成功した構成だけを公開します。npmの通常のインストール処理にはパッケージのinstallスクリプトも含まれます。

新しい構成は、依存関係の復元と検査に成功してから公開します。失敗・中断で現在構成は切り替わりません。導入はピアごとに一件、最大10分です。同じ操作IDの再送は元結果を返し、停止・再起動後の中断処理は自動再試行しません。応答を確認できない場合は、Dashboardの「操作」から元の操作IDを照会します。

パッケージ更新・削除を行っても、保存済みワークフロー・開始済み実行へ遡って適用しません。新しい構成を採用する場合は再解析して保存します。「新しい解析用構成から削除」は次の解析対象から外す操作です。古い解析が参照し得る環境は保持し、NuGetの同じ版のキャッシュと、同じ指定構成の環境を再使用します。過去構成や中断した作業先の自動削除は行いません。データ領域のバックアップ・容量管理に含めてください。

パッケージ・仮想環境はピア間で自動配布しません。複数ピアで実行する場合は、直接依存と解決済み依存の版を各ピアでそろえ、構成IDを確認します。Python・Node.jsは本体の版も構成IDへ含めます。npmは依存関係の配置を含むlockfileも固定します。従来の `packageEnvironmentId` を持たない保存済み解析では、C#はBCL、Python／Node.jsは元の明示パスまたはそのピアの既定環境を使用します。

## コード入力の補助

コードブロックと各スクリプトノードのコード欄は、C#・Python・JavaScript・Bash・PowerShell・JSON・TOML・YAMLの色分けと自動インデントに対応します。既存のスペース幅・タブを優先し、新規のJSON・TOML・YAMLは2スペース、ほかは4スペースを使用します。改行では構文に合わせて字下げし、Tab／Shift+Tabは選択行の字下げを調整します。

入力中またはCtrl+Spaceで、言語キーワード、文中の識別子、代表的な標準メンバーを候補に出します。矢印キーで選び、EnterまたはTabで確定、Escで候補を閉じます。宣言語は `public `・`def `・`function ` のように区切りの半角スペースまで補い、メソッドは `WriteLine()` のように空の括弧を補って括弧内へカーソルを移します。引数名・返却値・メソッド本体を自動挿入しません。

新しく記入したメソッドの宣言末尾でもTabで空の括弧へ進めます。既存の括弧や空白は重複させず、`{` に対する `}` などの括弧補完も使用できます。Escの後にTabを押すとコード欄からフォーカスを移動できます。コード欄内のCtrl+Z／Ctrl+Yは編集のUndo／Redoです。日本語IMEの未確定入力と編集ロックも維持します。

補完のために入力コードを実行したり、外部サービスへ送信したりはしません。コードと型は、入力が600ms止まった時点、フォーカス離脱時、または「コードと型を解析」で、選択した解析先ピアへ静的解析を依頼します。IME変換中には自動解析せず、画面離脱や編集ロック時には待機中の予約を取り消します。

スクリプトの「出力値」は現在のコードの解析結果から型を表示します。C#の `string` は文字列、`int` は整数になり、Pythonの型ヒントとJavaScriptの静的に確認できる返却式も同じ表示へ反映します。オブジェクトのプロパティや配列要素の型は既存の型推論・個別出力へ引き継ぎます。解析前・解析失敗・コード変更直後は未確定の任意型とし、古い型を保持しません。保存・通信では従来のJSON表現を維持します。
