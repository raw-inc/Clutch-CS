## 対応範囲

| タブ | OS | 設定内容 |
| --- | --- | --- |
| NetworkIF | Windows | IPv4/IPv6、DHCP、固定IP/prefix、メトリック、DNS、ゲートウェイ、IPv6ルーター広告、管理OS用Hyper-V vNIC、仮想スイッチの作成・削除 |
| Hosts | Windows / Linux / macOS | hostsの個別編集、複数ホストのエントリー単位の状態編集 |
| Firewall | Windows | Domain/Private/Public、有効無効、ローカルルールの追加・削除・有効無効 |
| PATH | Windows | PATHを含む永続環境変数の追加・変更・削除、Machine/User範囲 |
| Display | Windows | 接続ディスプレイごとの解像度・リフレッシュレート |
| Power | Windows | AC/DC別の自動電源タイマー、無操作シャットダウン、高速スタートアップ、電源ボタンの動作 |
| 電源スケジュール | Windows、Linux / macOSはbest-effort | 毎日・曜日指定のWoL送信と通常シャットダウン。担当クラスター・時刻・タイムゾーンを指定 |
| Windows Update | Windows Pro / Enterprise / Education / IoT Enterprise | 期限なしの手動更新設定、ローカル更新期限の無効化、自動更新制限の解除 |
| Login | Windows | ローカルユーザーの選択、自動ログインの有効化・無効化、保護された資格情報の保存・削除 |
| Wake-on-LAN | Windows、Linux / macOSはbest-effort | 停止後の起動要求に使うNICの選択。既定は確認済みの物理NICすべて |

Windows専用タブでは非Windowsのホストを選択できません。実行権限は対象CoreServiceのアカウントのものです。NetworkIF、Hyper-V、Firewallの変更には管理者権限が必要です。Hostsと環境変数もOSが許可する範囲に従います。

## 共通の操作

1. 左の一覧から対象ホストを選択してください。複数選択と「表示中を選択」を利用できます。
2. 選択したタブの現在値を自動取得します。読み取りは最大3台並列で、取得不能なホストは個別に表示します。「設定を再取得」で最新値を確認できます。
3. 一覧から編集対象を開き、変更項目を入力して「変更内容を確認」を開いてください。
4. 各ホストの変更前・変更後を確認してください。この時点の内容版と対象実体を固定します。
5. NetworkIFとFirewallでは通信影響の確認欄を選択してから適用してください。

開始までに設定が変わった場合、古い版から上書きしません。ピアの再起動や到達不能時にも別ピア・別NICへ変更先を替えません。ブラウザーを閉じても、ClientHostが受け付けた一括操作と履歴を保持します。

同じホスト選択でタブを移動しても、読み取り結果とHostsの編集中の内容を保持します。ホスト選択・発見一覧の更新で未適用のHosts編集を破棄する場合は確認します。変更確認から「編集に戻る」で入力を直せます。確認中に対象や編集画面を閉じた場合、遅れて届いた読取り結果から確認画面を開きません。

「操作履歴」はページ上部から開けます。開始した操作の進捗・結果を表示し、実行中・不明の操作がある場合は作業領域の下にも表示します。操作完了後は現在値を再取得します。結果不明の操作は元結果を照会し、同じ変更を再送しません。

## Display

各ホストのアクティブな接続ディスプレイ、主画面、現在の解像度・Hzを表示します。「解像度・Hzを変更」から、そのディスプレイのドライバーが列挙したモードを選択します。解像度とHzは対応する組として扱い、任意の未確認値を入力して変更することはありません。画面配置・回転・主画面指定は維持します。

変更確認には変更前後のモードを表示し、対象ディスプレイと表示への影響を確認して適用します。開始直前に接続先と内容版を再取得し、ホットプラグや別の設定変更があれば拒否します。ドライバーの検証を通してから変更し、適用後のOS現在値が一致した場合だけ成功とします。再起動が必要な応答は、現在の表示への反映が未確認であると表示します。

WindowsサービスのSession 0からは、既存の対話コンソールへ同じ実行主体の一回限りの補助プロセスを起動します。ログオン中のコンソールを確認できない場合は理由を表示します。別のRDPセッションや別のディスプレイへの代替は行いません。設定変更には管理者権限が必要です。

## Power

現在の電源プランについて、AC電源／バッテリー別にディスプレイオフ、スリープ、スリープ後の休止、無人復帰後の再スリープ、電源ボタンの短押し動作を設定します。時間の入力は分単位で、0は無効、空欄は変更しない意味です。現在値を取得できない項目は「未確認」とし、無効と判定しません。Windowsまたは管理ポリシーで未対応の変更は開始前に拒否します。設定変更には管理者権限が必要です。

「連続稼働向けの設定を入力」は、読み取れた自動タイマーと高速スタートアップを無効にする変更予定を入力します。複数ホストでは全対象で読めた項目が対象です。電源ボタンの動作は維持し、変更する場合は別途選択してください。適用前にホストごとの変更前後を確認してください。FastBootはWindowsの高速スタートアップを指し、UEFIのFast Bootや休止機能そのものは変更しません。プランが途中で切り替わった場合も再確認を求めます。

無操作シャットダウンはWindowsの電源プランとは別の、Clutch-CS が実行する PC 共通の設定です。初期値は無効です。CoreServiceが動作している間に約15秒間隔で、ログオン中の全セッションの入力を確認します。コンソールの入力をWTSで取得できない場合は、対話コンソール内の補助プロセスで`GetLastInputInfo`を使用します。複数CoreServiceはPC共通の排他と永続開始記録を共有し、同じ無操作期間の要求を再送しません。

シャットダウンは既存の非強制OS電源操作を使用します。

停止の有効化・時間変更後は保存時点から改めて指定時間を待ちます。新しい入力・確認不能なセッション・不明な電源供給があれば実行しません。未ログオン状態や、CoreService停止中・PCのスリープ／休止中はこの監視による停止を保証しません。無操作シャットダウンを使う場合は、先にスリープへ入らない時間設定にしてください。Windowsのバッテリー危険時動作や第三者の停止タスクは、この画面の「管理対象の自動タイマー」に含みません。

## 電源スケジュール

対象ホストと、その予定を管理するクラスターを選び、操作・時刻・タイムゾーン・毎日または対象曜日・有効無効を設定します。一ホスト・一クラスターにつき最大32件です。「予定を保存」で共有し、有効にした予定だけを実行します。他の編集と版が異なれば上書きしません。稼働基準は履歴とは別の現在値として保持するため、操作履歴の保持期限が過ぎても予定は失効しません。ブラウザーを閉じても担当クラスターのCoreServiceが監視を続けます。

左側で対象ホストを複数選択し、電源スケジュールの「一括設定」を開くと、同じ予定一覧を配布できます。コピー元ホストの保存済み予定を初期値にし、時刻・曜日・有効無効などを編集してから「選択Hostへ保存」で反映します。対象ホストの既存予定は一覧全体を置き換えます。各ホストで選択した担当クラスターを確認画面に表示し、別クラスターの予定には触れません。

「保存済み予定を一括有効化」「保存済み予定を一括無効化」は各ホストの全予定の有効無効だけを変更し、時刻・曜日・操作などを維持します。予定のないホストや既に同じ状態のホストには書込みを行いません。個別編集が未保存のとき、現在値を未取得のとき、保存結果が未確認のときは一括操作を開始できません。各ホストの表示済み版を使って順番に保存し、成功・失敗・未確認をホストごとに表示します。一ホストの失敗で別ホストの保存を戻したり、未確認の要求を自動再送したりしません。

WoLは対象ホストをオンラインと観測できない場合に、同じクラスターで稼働している別ホストのCoreServiceから送信します。停止前に確認したNIC情報と、Wake-on-LANタブで選んだNICを使用します。ClientHostが既に確認した一覧があれば、初回保存時に同じホスト・所属クラスターの情報だけを引き継ぎ、停止中でも設定できます。未観測の場合は対象ホストを稼働させ、NIC情報の保持表示を確認してください。

以降は対象CoreServiceがNIC選択を約30秒間隔で再確認し、内容が変わった場合だけ共有します。送信元は確認済みIPv4ネットワークとの一致を優先します。全CoreServiceが停止している場合は予定を処理できず、Magic Packetの送信成功は実際のPC起動完了を意味しません。

シャットダウンは、その時点の対象CoreService実体へ通常のOS停止要求を送ります。アプリケーションの強制終了は指定せず、進行中ワークフローの完了待ちは行いません。同時刻に複数PCを停止する場合は、どのPCも停止させる前に予定の受付を共有し、送信元自身の停止は最後にします。同じPC上の別CoreService・別クラスターから同時刻の停止が届いても、PC共通の永続受付位置で重複を抑止します。

CoreService起動前・長い観測中断中に過ぎた予定は遡りません。通常の巡回や送信待ちで到来した回にも予定時刻から1分の期限を設け、期限切れの停止を受信側でも拒否します。受付済みの要求が結果不明になった場合、別ピアや再起動後の実体へ自動で送り直しません。

予定ごとの受付位置は一行を更新し、停止中のピアへ新しい共有保存を要求しないよう、直近の実行結果は処理担当CoreServiceへ保持します。担当CoreServiceが停止した場合は結果を未確認として表示することがあります。全体の表示と通常ログから、受付とOS停止・起動完了を区別してください。電源スケジュールの画面では、ClientHostが停止前に記録したホストも選択候補に残します。他のOS設定タブは稼働中の対象実体が必要です。

## Windows Update

「手動更新のみに設定」は、Windowsの「自動更新を構成する」を無効にするローカルグループポリシー（`NoAutoUpdate=1`）を保存します。一時停止日数による自動再開はありません。期限に達すると優先されるローカルの更新・再起動期限も無効化し、確認画面に表示します。更新する際は、対象PCのWindows設定から明示的に実行します。

「自動更新の制限を解除」は`NoAutoUpdate`を未構成へ戻します。既存のダウンロード方式・更新サーバー等は保持し、無効化した期限ポリシーは無効のままです。解除後は他のWindows設定に従って自動更新が再開する可能性があります。

変更には対象CoreServiceの管理者権限が必要です。ドメイン参加・MDM登録PCや管理元を確認できないPCは参照専用にし、管理元で設定する理由を表示します。現在の設定を再取得して確認するため、ポリシーに反映されていなければ成功とは表示しません。

インストール中と更新による再起動待ちは別に表示します。既に開始済みの処理やインストール済み更新を取り消す機能ではありません。Microsoft Store、Defenderの定義情報、各アプリの更新は対象外です。Windows Updateサービス自体は無効化しません。

## Login

ホストごとにローカルユーザーを選び、自動ログインを設定できます。無効・ロック中・パスワード期限切れ・スマートカード必須のアカウントは選択できません。有効化にはアカウントのパスワードが必要です。Windows HelloのPINとは異なります。空欄は空のパスワードとして確認するため、パスワードのあるアカウントで省略すると認証に失敗します。ドメイン／Entraのユーザーを暗黙にローカルアカウントへ読み替えません。

パスワード入力はHTTPSまたはlocalhostで行います。ブラウザーが対象CoreServiceの公開鍵で暗号化してから送信し、ホスト・CoreServiceの起動実体・操作ID・ユーザーSIDに結び付けます。ClientHostの操作履歴や管理通信へ平文を渡しません。CoreServiceは一時鍵をディスクへ保存せず、復号バッファーを使用後に消去します。CoreServiceが再起動した場合は設定を読み直してパスワードを再入力してください。ホスト発見を含めた管理経路には、信頼できる管理ネットワークを使用してください。

Windowsの対話認証で対象SIDと資格情報を一度確認した後、自動ログインをいったん無効にし、LSAの`DefaultPassword`へ保存します。Winlogonの平文`DefaultPassword`は削除し、対象ユーザーを保存してから最後に有効化します。既存の`AutoLogonCount`による回数制限は解除します。途中で保存が失敗した場合は有効化せず、完了済みの段階を表示します。無効化ではパスワード入力を要求せず、LSAと旧方式の保存値を削除します。

LSAはWindowsの保護領域ですが、PC管理者は資格情報を復元できます。自動ログインではPCにアクセスできる人が選択したユーザーとして利用できるため、設置場所へのアクセスを管理する運用で利用します。スマートカード必須、確認できたEASパスワードポリシーがある場合は有効化を拒否します。

ログイン時のメッセージ表示ポリシーがあっても、対象ユーザーと資格情報を保存できます。ただし、Windowsはメッセージが残っていると自動ログインできないため、「アカウントは保存済み・メッセージ表示により自動ログイン不可」と表示します。「このPCのログインメッセージ表示を無効化」を明示選択すると、資格情報の確認後、現在適用中のタイトル・本文をポリシーと旧Winlogonの保存先から削除します。既定では削除しません。

削除に失敗した場合は自動ログインを有効化せず、完了した段階を表示します。管理元のグループポリシーは変更しないため、再適用でメッセージが復活する環境では管理元も調整してください。

設定の適用だけでサインアウト・再起動は行いません。次回のWindowsログインから使用します。アプリケーションの自動起動は、対象ユーザーのスタートアップや既存ワークフロー等で別途設定します。実際の再起動を伴う自動ログインとアプリ起動は、配備先PCのポリシー・アカウントで確認してください。

## NetworkIF

NICは表示名でなくInterfaceGuidで固定します。変更しない項目をそのまま残せます。DNSだけの変更ではIP、DHCP、メトリック、ゲートウェイを変更しません。

- IPv4/IPv6のプロトコルバインドを個別に有効・無効にできます。
- DHCP、自動メトリック、自動DNSは「変更しない」「有効」「無効」から選択できます。手動メトリックは0〜9999です。
- 固定IPは `192.0.2.10/24` のように指定します。「固定アドレスを置換する」を選んだ場合だけ手動アドレス集合を置換します。空欄は手動アドレスの削除です。
- DNSは入力順が優先順です。自動取得へ戻す場合は自動DNSを有効にします。
- DNSの「変更しない」はDNS設定を一切送信しません。デフォルトゲートウェイだけの変更にも使えます。「DNSを設定しない」は設定済みDNSリストを空にする明示操作です。DHCP、IPv6ではルーター広告も、既に無効であるか同時に無効化を指定している必要があります。
- ゲートウェイは「デフォルトゲートウェイを置換する」を明示した場合だけ変更します。空欄は既定経路の削除です。
- IPv6のルーター広告とDHCPは別に扱います。自動構成を停止する場合はそれぞれ明示します。

固定IPの変更でDHCPを暗黙に無効化しません。ゲートウェイ変更はDHCPが無効であることを要求し、IPv6ではルーター広告も確認します。必要なら個別編集で無効化と固定IPを明示します。ゲートウェイのファミリーと接続先サブネットを検証します。IPv6 link-localのゲートウェイは、固定したNICのInterfaceIndexで範囲を決めます。

各NIC行のIPv4／IPv6スイッチで変更予定を選び、画面下の `Apply` から変更分をまとめて確認・適用します。スイッチを押しただけではOSを変更しません。変更予定には枠線アニメーションと変更前→変更後を表示し、元の値に戻すと予定から外れます。動きを減らすOS設定では枠線を静止表示します。「変更予定をすべて解除」で一括解除できます。

検索や表示モード、HostManager内のタブを切り替えても予定は保持し、「変更予定を確認」では非表示のNICも含めて一覧できます。ホストの選び直し・明示的な再読取りは、未適用の変更を破棄する確認を挟みます。同じNICのIPv4／IPv6は一つの内容版・一つの操作で扱い、OS反映後に両方を照合します。操作前に両bindingの存在を確認し、有効化を先に行います。OS操作の途中で失敗した場合は完了済み項目を残し、全体成功にしません。

DNS、IP、メトリック等は同時に書き換えません。

NIC一覧はNetTCPIP/DNSのCIM providerを直接照会し、Hyper-V情報を独立した読取りと並行して取得します。不要なbinding列挙を省き、すべての読取りが揃ってから内容版を作ります。期限付きキャッシュでApply前の検証を省略せず、変更予定を選んだ時点と確認時の内容版が変わっていれば再確認を求めます。

DNS未設定化にはWindowsの [`netsh interface ... set dnsservers source=static address=none`](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/netsh-interface) を使い、対象InterfaceIndexとIPv4／IPv6を固定します。

IPv6では未設定でもWindowsが既定のサイトローカルDNSアドレス3件を返すため、明示設定と区別して「DNS未設定（Windows既定値）」と表示します。既定の探索動作そのものを無効にする機能ではありません。

### 同じネットワークへの一括設定

複数ホストのNICを読み取ると、IP/prefixから計算したサブネットと確認済みVLAN情報で候補を絞り込めます。対象NICのチェックを選び、DNS とゲートウェイの変更項目を入力してください。一回の一括操作は最大256件です。

NIC名・ホスト名・IPによる検索と、IPv4／IPv6・ネットワークの絞込みを組み合わせられます。「表示中のNICを選択」または個別チェックで対象を選ぶと、一括操作バーにNIC数・ホスト数と「DNS／ゲートウェイを設定」を表示します。個別のIP・DHCP・メトリック変更は各行の「編集」から行います。

サブネット一致だけで同じ物理ネットワークとは保証しません。VLANと接続先を確認してください。loopback、APIPA、IPv6 link-local、multicastは自動のサブネット候補から除きます。候補を切り替えるとNIC選択を解除します。

一括DNS／ゲートウェイ欄はDHCPや固定IPを変更しません。自動設定と競合するNICは事前確認で拒否します。自動設定を解除する場合は個別編集で影響を確認します。

### Hyper-V vNIC

既存仮想スイッチに接続する **ManagementOS用vNIC** を扱います。物理NICの削除、ゲストVM用NICの変更は行いません。スイッチ自体の作成・削除はNetworkIF内の「仮想スイッチ一覧」から操作します。

NetworkIF内の「仮想NIC」へ切り替えると、ホスト・接続スイッチ・VLANモードをまとめて確認できます。作成時には対象ホストと既存スイッチを選び、タグなしの場合はVLAN ID欄を無効にします。

- スイッチ名と接続先の物理IF、vNIC名、MAC、取得できたIPv4/IPv6を確認できます。
- **Access VLAN** はVLAN IDを表示し、1〜4094を指定できます。
- **Untagged** は「タグなし」と明示します。VLAN IDがnullであることだけで判定しません。
- 「詳細」から現在値をプレビューできます。タグなしへの変更確認でも、変更後の「タグなし」を省略しません。
- Trunk等のその他モードは読み取ったモードを表示し、Access／Untaggedへ暗黙に読み替えません。
- VLAN表示チップはAccessを青、Trunkを紫、Untaggedを灰色、未確認等を黄系で区別します。NIC一覧・仮想NIC一覧・詳細と変更確認で配色を共有し、文字でもモードを示します。
- Hyper-Vの詳細を取得できない場合も、OSデバイスIDで確認できたHyper-V NICのIP・MAC等は表示します。スイッチ・VLANは「未確認」とし、vNICの変更操作を無効にします。

Windows上のNICと管理OS用vNICは、照会したMACが一意に対応する場合だけ関連付けます。名前の変更やwildcardを対象選択に使いません。

### Hyper-V仮想スイッチ

NetworkIF内の「仮想スイッチ一覧」では、ホスト・スイッチ種別・物理NIC・接続中の管理OS用vNICとゲストVMを表示します。詳細はこの表示へ切り替えたときに取得します。対応するCoreServiceへの更新とHyper-Vの管理権限が必要です。

「仮想スイッチを作成」から対象ホストと名前、次の種別を指定します。

- **External（外部）**：使用していない物理NICを一つ選び、管理OSの共有有無を明示します。共有を許可するとホスト用vNICが作成されます。物理NICのバインドが変わるため、操作中の接続が切れる場合があります。
- **Internal（内部）**：ホストとVMを接続し、管理OS用vNICを作成します。
- **Private（プライベート）**：VM同士を接続し、管理OS用vNICは作成しません。

既存スイッチに使用中のNIC、対応を確定できないNIC、同名スイッチがある場合は開始前に拒否します。ExternalのNICはInterfaceGuidで固定し、OS呼出直前に対応を再確認します。物理NICのチーミングや既存スイッチの種別変更はこの画面の対象外です。

[MicrosoftのNew-VMSwitch仕様](https://learn.microsoft.com/en-us/powershell/module/hyper-v/new-vmswitch)に沿って、種別ごとの引数を分けています。

削除はスイッチIDで対象を固定し、確認画面に接続中の管理OS用vNICと通信への影響を表示します。管理OS用vNICも削除されますが、物理NICは削除しません。ゲストVMが接続されている場合、WindowsのDefault Switch、対応物理NICを確定できない場合は削除できません。ゲストVMは先に別のスイッチへ移すか、接続を切り離してください。

確認後にスイッチ・NIC・接続アダプターが変わった場合は開始前に拒否します。作成後は種別・物理NIC・管理OS共有、削除後は対象IDの消失まで再読取りで照合します。通信断や照合不能では結果を不明として保持し、自動再送しません。

## Hosts

Windowsは `%SystemRoot%/System32/drivers/etc/hosts`、Linuxは `/etc/hosts`、macOSは `/private/etc/hosts` を使用します。任意パスのファイル編集ではありません。

左の現在値で表示・コピー元のホストを選び、「この内容を編集欄へコピー」で編集元を切り替えられます。右の編集領域では、同じ内容を次の二つの方法で編集できます。

- **一覧編集**：IPアドレス、ホスト名・複数別名、コメント、有効／無効を扱います。追加・編集・削除は編集内容だけに反映し、確認・適用まではOSのhostsファイルを変更しません。
- **テキスト編集**：hosts全文を直接編集します。一覧と内容を共有し、切替時に入力を失いません。通常のコメント・空行・一覧で解釈できない行も保持します。

コメントアウトされたIP・ホスト名の行は無効なエントリーとして表示します。通常の説明コメントはエントリーへ変換しません。一覧で変更していない行の書式と改行は保持します。一覧で扱えない行はテキスト編集で確認でき、不正な有効行は適用前に拒否します。

一台選択時はそのホストの本文を置換します。複数ホストを選択した場合はエントリー単位の一覧に切り替えます。IPアドレスとホスト名／別名の集合を同じ定義として集約し、コメント・別名の順序・各ホストの書式は統一しません。

| 状態 | 判定と操作 |
| --- | --- |
| disable | 全ホストで定義済みかつ無効。選択すると既存の該当行をコメントアウトし、未定義ホストには無効の定義を追加します。 |
| other | 有効／無効が混在、同じホスト内で重複行の状態が混在、または一部ホストで未定義。otherのままなら変更しません。 |
| enable | 全ホストで定義済みかつ有効。選択すると該当行を有効化し、未定義ホストには定義を追加します。 |

操作していない行は、元の状態がenable／disableでも送信対象に含めません。プレビュー時に各ホストの最新本文を読み、明示変更したエントリーだけを反映します。別エントリー・コメント・空行・改行方式を保持し、実際の差分がないホストも除外します。otherへ戻すとその項目の変更を取り消せます。

「ホストを指定してテキスト編集」は選んだ一台だけを対象にします。読取り後に内容が変わった場合は再取得を要求します。確認画面ではホストごとの変更箇所と前後の行を表示し、追加・削除部分を色で示します。必要に応じて全文も開けます。

IP・別名・制御文字・サイズを検証し、新しい本文はUTF-8換算128KiBまでです。UTF-8とBOM付きUTF-16を扱い、元のBOMと改行方式を保ちます。未対応の文字コードを置換文字で保存しません。元のバイト列をCoreServiceのdata directoryの `host-manager-hosts-backups/<操作ID>.hosts` に退避し、同一ディレクトリの一時ファイルで原子的に置換します。Unixでは元のファイルモードを引き継ぎます。

シンボリックリンク等のファイルは拒否します。

外部アプリによる変更も置換直前に確認します。バックアップは自動削除しません。OS側で復元する場合は元操作IDのバックアップを確認し、現在の内容も退避してから戻してください。

## Firewall

Domain、Private、Publicと、10件ずつのルール一覧を表示します。ルール名で絞り込めます。追加時には方向、Allow/Block、プロトコル、ローカル／リモートのポートとアドレス、Program、Profileを指定します。

上部のプロファイルカードは、選択したホスト群の有効件数・混在状態を示します。プロファイル変更とルール追加は選択ホスト群へ適用します。既存ルールは表示するホストを切り替えて検索・ページ移動し、対象ルールの有効無効・削除を行います。名前から詳細な通信条件を開けます。

複数ホスト選択時は、プロファイルとルールをdisable／other／enableで操作します。ルールの概要を全ホストから取得したうえで、表示対象の通信条件を照合します。同じ表示名だけで同一ルールと判断せず、方向・動作・プロファイル・プロトコル・ポート・アドレス・Programまで同じ定義をまとめます。

未定義ホストはotherの判定に含めます。enable／disableを明示すると、存在するルールは状態だけを変更し、未定義ホストには同じ条件と指定状態で新しいローカルルールを作成します。プレビュー前に再取得し、直前に追加された同じ定義を二重作成しません。未操作またはotherの定義は変更しません。

GPO等の編集不可ルールや、サービス・パッケージ・認証・インターフェース指定・説明／グループ等、画面の作成項目では再現できない条件を含む定義は、一括トグルを無効にして理由を表示します。未対応の動的ポート・アドレス条件も複製しません。一台選択時の参照・個別操作は利用できます。

ポートは単一番号・範囲・`Any`、アドレスはIP・CIDR・`Any`・`LocalSubnet`です。Profileは `Any` または `Domain,Private,Public` の組合せです。ポート条件はTCP/UDPで使用します。

既存ルールは有効無効と削除に対応します。取得できたローカルルールだけを変更可能とし、GPO等は参照専用です。表示で省略したサービス・認証等の条件も内容版へ含めます。OSの有効な状態を再読取りし、ポリシーで反映されなかった場合は成功と表示しません。

## PATH・環境変数

Machineは機械全体、Userは明示選択したユーザープロファイルの永続値です。User では、各ホストで取得できる読み込み済みの SID を個別に選択してください。LocalSystemのHKCUを利用者の環境として扱わず、未ロードのユーザーハイブを自動ロードしません。

PATH以外の変数も編集・削除できます。`REG_SZ` と `REG_EXPAND_SZ` を区別し、`%SystemRoot%` 等を編集時に勝手に展開しません。選択ホスト群へ同じ名前・値を適用する場合も、ホストごとの現在値と対象SIDを確認します。

変数名・値で検索でき、PATHを一覧の先頭に表示します。PATHの編集では各パスを一行ずつ表示し、追加・削除・上下への並べ替えに対応します。順序・重複・空のエントリー・変数参照を自動で整理しません。User範囲では、対象ホストそれぞれのユーザーを明示選択してから読み取ります。

複数ホスト選択時のPATHは、各パス行のdisable／other／enableで管理します。全ホストに存在すればenable、一部で未定義ならotherです。enableを選ぶと不足しているホストの末尾にだけ追加し、disableは一致するパス行を削除します。otherと未操作の行は、順序・重複・空エントリー・環境変数参照を含めて保持します。文字列表記を勝手に正規化・展開せず、そのままの値で照合します。既存PATHのレジストリ型も保持します。

PATH以外の変数は、ホストごとの値と未定義を確認できます。値や型が異なる場合も先頭ホストの値で上書きせず、「変更しない」を初期選択にします。「値を設定」または「削除」を明示した変数だけを対象にし、必要ならコピー元ホストを選べます。スコープや対象ユーザーの切替で未適用のPATH編集を破棄する場合は確認します。

レジストリ変更後、CoreServiceの実行セッションへ環境変更を通知します。既存プロセスの環境は変えません。LocalSystemサービスは通常Session 0にあり、別ユーザーセッションの既存ランチャーへ通知が届く保証はありません。新規プロセスの親が古い環境を持つ場合は、ランチャーの再起動または再サインインが必要です。

## 中断・不明結果・保存

CoreServiceはOS変更前に開始記録を永続保存し、同一PCのプロセス間ロックを取得します。コマンド終了後も指定項目を再読取りして照合します。一括操作は順番に処理し、不明になったホストの後続だけを未実行とします。別ホストの処理は継続できます。

OS処理が通常の管理応答待機を超えた場合は、同じ変更を再送せず、元結果の読取りだけを最長60秒継続します。この間は実行中として表示し、期限までに確定できなければ不明のまま保持します。

- **成功**：変更後の値まで確認しました。
- **失敗**：開始した処理の失敗を確認しました。完了した段階は併記します。自動ロールバックはしません。
- **未実行**：対象・版・権限等の理由で開始していません。
- **不明**：通信、プロセス終了、結果保存、反映照合等で結果を確定できません。

「元の操作結果を照会」は読取りだけを行います。ClientHostやCoreServiceの再起動時に変更要求を再送しません。ClientHostのstate directoryの `host-manager` に計画と結果を保存し、直近20件を表示します。古い履歴も重複受付防止と不明結果の確認に使います。ブラウザーの既存操作履歴にも送信前に元IDを記録します。

不明が残るホストに新しい変更を行う場合は、元結果の照会、必要に応じた[Terminal](../guides/terminal.md)や現地での確認を先に行います。確認画面で以前の不明な操作と現在の設定を確認した旨を明示した、新しい操作だけを受け付けます。以前の不明結果を成功や未実行に書き替えず、新しいIDと確認内容を保存します。

保存先には適用したhosts本文や環境変数の新しい値が含まれます。CoreServiceとClientHostのdata/state directory、hostsバックアップは運用者のOSアクセス権で管理してください。

## 実装と検証の境界

公開経路は `/client/host-manager/*`、CoreService管理操作は `host-manager.capabilities`、`host-manager.read`、`host-manager.apply`、`host-manager.operations` です。内部の契約・責務名は `DeviceManagement` にまとめています。既存のUDP管理輸送を使い、新しいCoreService HTTP待受を追加しません。

NetworkIF・Firewallでは固定PowerShell処理に型付きJSONを標準入力で渡します。入力値をPowerShellコードへ埋め込まず、起動・出力・時間を制限します。Displayでは接続先を固定したWin32 APIを使用し、対話セッションとの連絡は接続プロセスを検証する専用パイプを使います。

Windowsの実読取り、管理者Terminal経由のHyper-V Access／Untaggedと物理IFの対応、隔離ファイルでのhosts置換、OS境界を置き換えたPowerShell変更試験、複数実CoreServiceとClientHostによる集約・開始前拒否・再起動後の結果照会を確認しています。実NIC・Firewall・永続環境変数・vNICの変更と、Linux/macOS実機のhosts置換は別途実機で確認する範囲です。

## Wake-on-LAN

PCがオンラインの間に「Wake-on-LAN」で使用するNICを選び、変更前後を確認して保存します。既定の「物理NICをすべて使用」は、新しく認識した物理NICも対象に含めます。個別にチェックを変更すると明示選択になり、すべて外して保存すると送信対象なしになります。OSが物理NICと報告するWi-Fiも既定選択に含まれます。物理NICと確認できないものも、使用可能なMACがあれば「仮想・未確認」として表示し、手動で選択できます。

選択の変更には、CoreServiceの管理者権限またはroot権限が必要です。同じPC上の全CoreServiceが次の保存先と変更排他を共有します。Windowsの既存設定はそのまま読み取ります。Unixでは選択ファイルを完成後に置換し、未設定と「明示的に選択なし」を区別します。読取りだけではファイルを作成・更新しません。

| OS | NIC選択の保存先 |
| --- | --- |
| Windows | `HKLM\SOFTWARE\ReArtWord\Contents\WakeOnLan` の `Selection` |
| Linux | `/var/lib/ReArtWord/Contents/host-manager/wake-selection.json` |
| macOS | `/Library/Application Support/ReArtWord/Contents/host-manager/wake-selection.json` |

Linuxでは[sysfsの実デバイス階層](https://www.kernel.org/doc/html/latest/admin-guide/sysfs-rules.html)を確認し、`devices/virtual` のNICを物理NICの既定対象から除きます。

macOSでは標準の [`networksetup -listallhardwareports`](https://developer.apple.com/documentation/network/recording-a-packet-trace) にあるEthernet系のBSD名（`en0`など）を確認します。追加の監視ソフトやドライバーは使いません。情報を確認できない場合は物理と推測せず、手動選択を使います。

Unixの選択IDはOS・NIC名・MACから固定して生成するため、NICの改名や交換、MAC変更後は明示選択を再確認してください。

ClientHostは、稼働中に一台につき一つのCoreServiceへ毎分照会し、NIC・選択・所属クラスターの内容が変わったときだけ `wake-hosts.json` を更新します。停止後やClientHostの再起動後にも最後の確認値を使えます。NICのOS列挙は5分間再利用しますが、HostManagerの「設定を再取得」は一覧も取り直します。選択は毎回読み取ります。

別ClientHostへの反映はそのClientHostがPCを観測している間に行うため、変更直後に停止する場合は、後で使用するClientHostで設定を確認してください。

DashboardのPC healthでオフラインPCの電源ボタンを開き、「Wake-on-LANを送信」から確認して送ります。対象PCと同じIPv4ネットワークが確認できる稼働中CoreServiceを優先し、同じクラスターの候補を次に優先します。選んだ一つのCoreServiceが、選択済みMAC宛てのMagic Packetを有効なローカルIPv4リンクからUDPポート9へ送ります。送信元CoreServiceのOSはWindows・Linux・macOSに対応します。

Hyper-Vの管理用vNICも送信元に含みます。各リンクのIPv4へbindし、Windowsでは[IP_UNICAST_IF](https://learn.microsoft.com/en-us/windows/win32/winsock/ipproto-ip-socket-options)で送信インターフェースも固定します。送信はCoreServiceからのみ行います。稼働中CoreServiceがない場合、NIC情報が未取得の場合、送信対象なしの場合は、送信せず理由を表示します。

ブロードキャストが通る範囲はネットワークの構成に従います。

送信受付はPCの起動成功ではありません。再検出されたPC healthの状態で起動を確認します。通信断や応答取消で送信結果が不明になった場合は、別CoreServiceへの切替や再送を自動では行いません。同じ操作IDの照会は元の結果だけを返します。ファームウェア、NIC、OSのドライバーが目的の電源状態からのWoLに対応・設定済みであることが前提です。この画面では、その設定やホスト全体の電源ポリシーを自動変更しません。
