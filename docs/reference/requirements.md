## 1. 提供範囲

主な機能を利用場面ごとにまとめます。設定方法、対応する形式、上限は、それぞれの機能の資料に記載します。

| 利用場面 | 主な機能 |
| --- | --- |
| 複数PCをつなぐ | ピアの発見、状態共有、実行先指定、役割交代、縮退、再参加、変更競合の統合 |
| 処理を組み立てる | YAML／JSONの定義、TOML起動設定、クラスター共通運用設定、ノード・ポート・ワイヤー、条件、イベント、基本データ変換、配列の逐次／制限付き並列反復、クライアントなし実行 |
| 外部と通信する | HTTP（REST・GraphQL）、OSC（UDP・TCP）、Art-Net、汎用UDP・TCPの送受信役割、UDP ブロードキャスト、インターフェース指定 |
| データを読む・作る | Binary・JSON・TOML・YAML・CSV・Textのserialize・deserialize・抽出、基本的な項目・構造変換 |
| PC上で処理する | アプリケーション起動・停止・監視・復旧、CPU・GPU・メモリ等の監視、ファイル・ディレクトリ操作と変更監視 |

| 状況を確認する | 独立したWorkflowEditor・Dashboard・LogViewer、Command-Line Web クライアント、端から端の追跡、ログ保持、リソース診断履歴 |
| 導入・更新する | 各ホストの初回配置とOS自動起動登録、閉域導入、選択クラスターの手動開始による分散更新 |

一ピアの複数クラスター同時参加、一ワークフローのクラスター横断共有・保存・実行、完全遠隔一括初回配置、Windows Arm、DST timezoneの時間指定保証は対象外とします。明示アドレスへの通常API通信によるクラスター間連携は利用でき、両クラスターの状態やコーディネーターを統合しません。

ClientHost は複数の NIC から独立したクラスターを観測し、Dashboard にまとめて表示します。ワークフローの保存・実行はクラスター単位です。FileTransfer の転送先は操作ごとにクラスター・ホスト・ピアを指定し、ワークフローの `file.transfer` は所属クラスター内で実行します。Terminal は、選択したホストの対話シェルを共有する機能です。

全ピア更新の並列数は 1〜3、既定は 2 です。同じ PC や同じクラスターを同時に更新せず、3 ピア以上のクラスターでは、更新中も Ready の過半数を維持します。詳しい手順と失敗時の動作は[更新](update-process.md)を参照してください。

DB 接続は SQLite・PostgreSQL・Redis、コードを記述するノードは .NET 10 の C#・Python・Node.js の JavaScript に対応します。C# は専用アナライザー、Python と JavaScript は静的解析で、WorkflowEditor が扱える引数・戻り値の型を確認します。推定できない型は利用者が選択します。型の確認のためにコードを実行することはありません。

依存パッケージは Dashboard からピアごとに管理します。NuGet・pip・npm のバージョンと依存関係を解析時に保存し、実行時にも同じ構成を使用します。パッケージの更新をワークフローへ取り込むには、再解析して保存してください。利用方法は[DB 接続](nodes/databases.md)と[スクリプト](nodes/scripting.md)に記載しています。

## 2. ワークフローを構成して実行する

ワークフローの定義は保存・共有する設定であり、その定義を使って開始する一件が実行に当たる。ワークフロー内の処理要素をノードと呼ぶ。PC・VM等をホスト、その上で動いてクラスターへ参加するプロセスをピアと呼び、処理ノードと区別します。一つのホストで複数のピア、一つのピアで複数のワークフローを動かせる。一つのワークフローには、複数のホストで実行する処理を含められる。

用意済みノードと設定だけで初回の通常機能を構成できます。正規表現、パス、抽出指定、比較値は設定として使えるが、初回に自由記述の式・スクリプト・コードを要求しません。通信・処理・条件・フックは共通契約とDI登録で追加でき、中核へ種類別の巨大分岐を増やし続けない。

定義は原則YAML、共通設定は原則TOMLとし、GUIとCLIのいずれも起動していなくても、サービスが読み込み・構文／意味／参照検証・非クライアント処理実行を行える。不正な定義、未知ノード、設定不足、解決不能な割当は対象と理由を示して開始しません。データ変換用YAML／TOMLノードとサービス設定の読込みは別責務とします。

現在のインポートはYAMLとJSONを受け付けます。定数入力の `inputs` は通常値、`binaryInputs` はbase64で指定し、管理APIの型付き定義とは区別します。TOMLのトップレベル `workflows` は新規クラスターの初回導入用であり、導入完了後の再起動でファイルを再保存しません。通常の更新は画面・管理APIの保存と有効化を使用します。

TOML はピアの起動情報、固定 NIC・IP、保存領域、ローカル資源の許可範囲を指定します。timezone、ファイルの競合方針・対象内部失敗方針、ホストグループはクラスター共通の運用設定として保存・共有・有効化を分けます。明示した新規クラスターの最初の値だけを TOML から初期化し、再起動で共有設定をローカル TOML に巻き戻しません。各入力・ファイル処理は開始時の共通運用版を保持します。

通信受信、状態変化、操作、日時、ファイル変更、プロセス、ピア参加・離脱、復旧、更新等をイベントとして扱います。必要な対象、時刻、相関、重複判定情報、結果を後続に渡せる。全イベントを無期限保存する仕組みや一律replayは要求しません。

### 一回の実行と結果

一回・一件・接続は開始時に共有・有効化済みだった設定を使用します。通常の設定変更、秘密値変更、新ノード追加を開始済み処理へ途中適用せず、新しい単位から使用します。新設定でやり直す場合は、現在処理の停止・取消・終了結果を確認して別の一回として開始します。

成功、確認済み失敗、確認済み未実行、実行有無または外部結果不明を区別します。処理・対象・理由・対象別結果・確認できた実状態を、利用者、後続処理、フック、ログで利用できます。結果不明だけを理由に暗黙再実行しません。

通常失敗では成功結果に依存する後続だけを未実行とし、失敗経路と独立経路は続けます。一般的な全Instance停止の選択を付加しません。複数対象の一部失敗は一回全体の失敗とし、既定では成功済み副作用を維持します。補償に成功しても元処理の失敗を成功へ書き換えない。

正常出力を必要とする処理は、固有の正常完了条件と期待出力の実取得を満たした時点で成功とします。後続の接続、消費、成否を出力元の成功条件へ含めず、後続失敗で完了済み出力元を遡って失敗にしません。

### 継続待受・監視

待受・監視自体の利用可能状態と、一件の受信・一回の観測結果を分けます。一件の不正入力、取得失敗、判定不能だけでは継続可能な待受全体を終了しません。インターフェース・権限・対象等の喪失で継続できなければ、稼働中と示さず対象・理由・影響を示します。

受信は終了条件未指定なら無期限継続します。一件または指定件数、通常ワークフロー条件、予定した人操作で正常終了でき、正常終了を一度だけ後続へ伝えます。緊急停止・取消・失敗・待受不能と区別し、再開は新しい待受実行とします。

全待受ノードの共通設定 `listenDurationMs` は任意の受付終了時間とし、未指定なら常時待ち受ける。開始時に固定した時間で受付を正常終了し、受付済みの処理には緊急取消を伝えない。TCP・HTTPの `timeoutMs` は受け付けた一件の通信期限として別に表示し、0またはnullで無期限にできます。UDP受信の旧 `timeoutMs` は待受期限として読み替えない。

人が進行中入力を含めて取消を指定した場合は、元の待受実体から既に受け付けた一件にも取消を伝えます。待機中の未開始入力と、開始済みのローカル・遠隔ノードを区別し、元の実行 ID・ピア実体へ要求します。通常の接続切断を取消意思とみなさず、独立したワークフローや再開後の別実体には波及させない。取消要求の受付は外部副作用の実停止保証ではなく、確認できない元結果は不明のまま示します。

予定した一回の取消指示が保存され、まだ配送開始を許可していない場合は、担当交代後も取消済みであることと結果の保存確認待ちを分けて示します。配送を許可した後は、取消指示だけから実停止を断定しません。結果を保存する項目に未完了の予約が残る間は、新しい操作 ID で失敗する更新を繰り返さず、元の予約を維持します。予約の解消後に改めて現在の版を検証して保存します。

`startOnLoad` は待受ノードの待受開始にだけ使用します。一回で完了する処理の起動は `service.started` を起点に構成します。この待受ノードは通常参加後、同じピア実体のワークフロー・ノードごとに一度だけ発生し、再適用・位置編集・役割交代では再発生しません。ピアプロセス再起動は新しい実体として発生します。各ピアの起動を受ける構成では下流に `target.sourcePeer` を指定します。

停止中入力・待機回・出力には件数とバイト数の有限保持上限を設ける。保持不能を黙って破棄・正常完了にせず、未実行または副作用後の結果不明を示します。大きなファイル成果物は所有ピアと内容ハッシュを持つ参照で扱い、別ピアの同名パスを同じ成果物と見なさない。

### 条件・データ

条件は成立・不成立・判定不能のいずれか一経路だけへ前段値を渡します。比較に使用した実値、判定結果、安定した理由種類と人向け説明を後続で利用できます。選択されなかった必要入力が欠ける合流ノードを、他入力だけで部分実行しません。取得不能値へ0、空文字、前回値を黙って補わず、代替は明示した別処理で構成します。

六形式のserialize・deserialize・抽出を提供し、JSON等の項目・配列要素、CSV行・列・セル、Text行・範囲・一致部分、定義済Binary項目・範囲等、形式に意味のある単位を扱います。入力形式不正は失敗、正しい入力の項目未存在は正常nullとします。明示nullと未存在を抽出結果では区別せず、必要なら元入力への別の存在確認を構成します。

抽出は値とCountを返します。単一非nullは1、nullと空配列は0、配列はnullも含めた全要素数です。Countを文字列長・バイト長・オブジェクト項目数へ流用しません。複数箇所は抽出の組合せで表せればよい。

データノードは、出力構造の作成、項目の追加・更新・削除・名称変更・選択、固定値や抽出値の設定、連結、対応付けを提供します。複数集合の結合、グループ化、入れ子の展開・平坦化、条件別の分割も利用できます。入力件数・出力量・処理量の上限と、上限に達した場合の動作は[データノード](nodes/data.md)を参照してください。

現在のMathは四則演算に加えて大小比較、一致／不一致、累乗／累乗根、真偽値の論理演算とInt64のビット演算、配列のAND／OR集約を提供します。四則演算・累乗・累乗根は有限binary64を使い、大小比較は対応範囲内の十進数値を丸めずに比較します。真偽値と整数を混在させず、上流処理を短絡実行しません。具体的な入力・数値範囲は[データ・制御](nodes/data.md)を参照します。

ForEachとParallel ForEachは、同じキャンバスで接続された一回で完了する処理を配列の要素ごとに実行します。逐次版は要素の処理完了を待って次へ進み、並列版は同時に実行する要素数を制限します。Endは任意とし、省略した場合は要素側の接続先の末端までを反復します。Endを使用する場合は開始側loopから対応付け、要素ごとのJSON結果を入力順に集約して後続を一回だけ実行します。空配列は正常なゼロ回実行とします。既知の要素型は表示・接続検証に反映し、不明な型を断定しません。

開始時の設定版・対象ピア実体と元待受ノードの取消を全要素で共有し、非成功時は未開始要素を止めて開始済みの結果を待ちます。件数・保持量を制限し、未開始・未保持を全件成功としません。反復範囲の曖昧な交差と、内側反復から外側Endへの直接合流は開始前に拒否します。

## 3. 実行先と通信経路を指定する

各処理は、実行PCにあるファイル・プロセス・NIC等の環境を使用します。特定の環境が必要な処理には、PC選択や既存のピア指定で実行先を明示できます。実行先の指定がない場合はコーディネーターを使い、そのPCに必要な環境がなければ理由を示して開始しません。

処理ノードごとに「1台で実行」「全候補PCで実行」を選び、既定は1台とします。実行PCの指定がなければ、クラスター内で実行可能な最優先PCを使用します。ピア・ホストグループ・入力の発生元を直接指定することもできます。

各処理ノードの実行PC入力には、複数のPC選択ノードを接続できます。PC選択は現在のクラスターに所属するPCから1台・複数台・全参加PCを指定します。候補を合わせて同じPCの重複を除き、1台実行は候補内の最優先PC、全候補実行は各PCで一回とします。全候補実行は候補の明示を必要とします。未接続と、接続された選択の候補なし・評価不能を区別し、後者を未指定の最優先PCへ置き換えない。実行先の直接指定と PC 選択ノードによる指定は、同時には使用できません。

低負荷PC選択はCPU・RAM・GPU・VRAMの比較対象を選択します。CPU・GPUは使用率、RAM・VRAMは使用率を既定として実使用量も選べる。VRAMは専用領域を扱い、共有GPUメモリを混ぜない。複数GPUは比較対象を指定でき、未指定時は選んだ単位で最大の測定値をPCの代表値とします。使用率を選んだ場合は最大使用率、使用量を選んだ場合は最大使用量を使用します。比較したGPUと値を示し、PC選択だけで処理アプリケーションのGPU割当まで完了したとは扱わない。

共通採取の時刻・実体・鮮度を確認して比較し、取得不能・欠測・古い値を0にしません。比較できなかったPCと理由を示し、一部欠測時は比較できた候補内の最低値であることを明記します。最低値が同じなら優先度、さらに同順位なら安定した共通規則で決める。比較対象がなければ開始しません。候補、観測情報、対象ピア実体は一件の実行計画を確定するときに固定し、開始済み処理や継続待受を負荷変動だけで移動・再実行しません。

時間指定で、予定時点から対象PCが不在だった場合は、そのPCを固定したまま遅延方針に従って待ちます。復帰後の初回配送直前に、実行するピア実体を固定します。入力の取得時には稼働していた実体を後から失った場合は、この復帰待ちによる差替えの対象にしません。

実際の担当 PC、選択理由、対象ごとの結果を確認できるようにします。選択した候補以外の PC へ実行先を変更することはありません。実行先の指定は、保存・共有・設定スナップショットの対象です。

通信はピアと、そのホストの物理／仮想インターフェース・local IP・外部宛先を分けて指定します。送信と受信の集合は非対称でよい。複数ピアへの実行指定とネットワークブロードキャストは別機能です。

同じ通信ノードを複数PCへ割り当てる場合、共通のNIC・IP指定に加えて、ホスト IDごとのNIC識別子・local IPv4を明示する方式を選べる。各PCの候補を個別に取得し、同名NICを混同しません。未検出・実行候補外になったPCの保存値を保持し、未割り当てPCを別PCや共通設定へ代替しません。未割り当てやNIC・IP喪失の影響は当該PCの処理へ限定します。既存の共通指定を自動移行しません。

同じインターフェースの名称変更でIP条件を満たす場合は割当を維持します。同一インターフェースが同一IPで一時障害から戻れば、必要条件確認後に新しい待受・処理を自動再開します。IP変更・削除・同一性不明では未解決として、人の再選択・再適用まで開始しません。障害中の失敗／不明な一回は再開時に暗黙再実行しません。

HTTP・OSC・Art-Net・UDP・TCPの受信／送信／双方向を連携別に構成できます。成功確認は送信受付、応答受信、応答内容一致、明示した応答不要等から連携別に定める。個別待機上限なし指定がなければ共通の上限を適用し、連携別有限値または上限なしで上書きできます。通信成功と相手の実動作保証を分けます。

OSC受信では、アドレスを空欄にすると全件、指定すると完全一致するメッセージだけを受け取る。受信結果はOSCパケット、アドレス、型タグ付き引数を個別に取り出せる。引数の個数・順序・型を固定すると、引数ごとの型付き出力が現れる。数値精度（32／64ビット）、文字列、Binary、真偽値、null、OSC時刻タグを区別し、型や個数が違う一件を暗黙変換しません。対象外アドレスは失敗にも受信件数にも含めない。

bundleは時刻と構造を保つパケット形式で受け渡し、暗黙に分解・即時実行しません。

OSC送信も同じ引数型の一覧から入力端子を構成します。アドレスは設定または接続で指定できます。型を固定しない場合は既存のOSCパケット入力を維持します。パケット入力時のアドレス指定は単一メッセージのアドレスを上書きします。bundle全体へのアドレス上書きは拒否します。引数型は編集時に固定する構造設定であり、設定入力の配線でポート構成を変更しません。UDPとTCPで値の扱いを共通化し、OSC over TCPではlength-prefix方式だけを選べる。

同一CoreServiceプロセスのUDP受信は、同じNIC・IP・ポートのソケットを共有し、各ノードへ全パケットを配布します。OSC・汎用UDP・Art-Netに共通で適用し、アドレス条件・件数・停止は購読ごとに管理します。同じローカルポートからの送信もソケットを共有し、送信ノードごとのブロードキャスト設定を直列化して適用します。返信は待受中のノードへ通常どおり配布します。最後の送受信の利用が終了した時点でソケットを解放します。各購読の待ち行列には上限を設け、処理遅延を他の購読へ波及させない。

別CoreServiceプロセスや外部アプリとの同一ポート共有は行わない。TCP／HTTPの返信付き待受は応答の所有者を一つに定める。

ホストグループは初回flatとし、重複所属と空Group保存を許す。複数Group経由の同一実対象は一処理で一回だけ扱います。開始時から空なら対象なしとして開始しません。範囲外クラスターのメンバーを含む指定は一部除外せず訂正まで開始しません。

一回完結処理のGroup所属は開始時に固定します。継続待受・監視の所属変更は有効化後の新しい一件へ反映し、追加メンバーで開始、除外メンバーは新件を止め開始済み一件完了後に待受を終了します。動作中にゼロになっても継続定義を維持し、後の追加で再開できます。明示停止・削除後は新件を開始しません。

## 4. 複数ピアで継続・縮退・再参加する

一ピアは一クラスターに属します。内部参加・発見・状態共有に使うインターフェースを選択し、必要ブロードキャストが相互到達する共通範囲で、相手IPの個別登録なしに発見します。通常P2Pは原則ブロードキャスト UDP、ログ転送は別経路TCPとします。

ピアの ID と起動中のプロセスを区別します。通常の再起動では同じピアの ID を使い、新しい PC の追加や OS の再導入、保存データの複製では新しいピアとして設定します。同じ ID のプロセスが同時に動いている場合、正しい実体を特定できればそれを維持して後発を除外します。特定できない場合は、両方の通常実行・外部出力・役割取得を止めます。

保存領域には ClusterId・PeerId・HostId と選択 NIC の同一性を記録し、別識別の起動に既存領域を流用しません。NIC を省略した初回は指定 IP に一意に対応する NIC を確定して記録します。次回に同じ IP が別 NIC へ移っていても黙って代替せず、元の NIC・IP が戻るか明示的に再選択されるまで通常参加しません。

実際に受理した既知ピアの集合はローカル保存し、再起動しただけで停止中ピアを忘れない。過去の Ready は復元せず、再観測まで Unavailable とします。人の明示 Detached は通信喪失と区別し、通常の期待参加集合から除く。既知集合を保存・検証できない場合は通常参加へ進めない。

コーディネーターは通常協調中にクラスターで一担当とします。通常参加可能な最高優先度を選び、同順位では現担当を維持します。新規選出時だけ連続通常参加開始順を用い、同順位でも安定して一担当へ決める。高優先度ピアの復帰では新入力だけを戻し、現担当で開始済み処理を中断・移動しません。コーディネーターを唯一のデータ正本や全通信中継点にしません。

担当喪失時の実行中一回は失敗／不明とし、透過的resumeや暗黙retryをしません。未開始・要求保持・現在実行条件を確認できる要求だけを新担当が一度開始します。開始有無不明は未開始へ丸めない。旧担当復帰だけで現担当の待機要求を移動・重複させない。

### 縮退時の停止・継続

少なくとも一つの実行可能ピアと必要資源・経路が残る限り、利用可能な設定・保存・スナップショット・状態・操作・処理を継続します。固有機器、GPU、NIC、local IP等を失った処理は対象・理由・影響を示し、影響外を継続します。

単体判定はホスト台数ではなく実効参加ピア数で行います。readyと協調可能degradedを数え、syncing・オフライン・detached・到達不能は数えない。同一ホストの複数ピアも別々に数える。

単体時は安全停止方針を適用、複数残存縮退時は継続が既定であり、それぞれ処理のまとまりと個別例外を設定できます。ノード自身の既定は継続で、状況別停止対象として指定したノード自身と依存後続を止め、前段・独立経路を続けます。必要入力不足の合流は部分実行しません。停止中入力は既定全破棄、最新一件または全件処理を明示選択できます。復帰前提は通常条件ノードで構成します。

一時続行と一時停止を全接続クライアントから操作できます。一時続行は障害解消で通常判断へ戻り、一時停止は人が解除するまで維持します。逆方向操作は後から受理したものを採用します。対象別に確認なし・続行だけ確認・双方確認を選べ、既定は追加確認なしです。現在状態と人為操作中を共有し、成功／失敗を即時通知するが、通常操作履歴への保存と再接続後の過去通知再配信は行わない。

一時続行は承認時の障害条件・欠損ピア・通常参加実体に結び付ける。通信回復を確認した元操作だけを失効させ、別の障害回に対する新しい続行を一括解除しません。元の実体が一つも確認できない全実体入替後は自動復元しません。部分再起動で元の実体が残る場合と、設定未読込で判断不明な場合を区別します。表示上の保存要求と現在実効の続行も分けます。

同じ対象の人為停止中に後から続行を受け付けた場合は、人による明示的な停止解除も兼ねる。別の解除操作を先に要求しません。新しい稼働操作は現コーディネーター（離脱中はローカル実体）の受付順に直前状態へ適用し、古い画面の期待版を編集競合として拒否しません。受付実体と実体内順序を示し、分断側を跨ぐ全順序は捏造しません。同じ操作 ID は元の受付結果を照会し、結果不明の副作用要求を新しい担当へ作り直さない。

分断中の稼働操作は不変の操作 ID 別に保存し、実際に観測していた同じ対象の旧操作だけを置換します。再接続で未観測の人為停止を続行側が黙って消さず、これをワークフロー編集競合としてクラスター全体の停止や三択解決へ持ち込まない。並行操作は表示で区別し、再接続後の明示続行はその時点で観測した同じ対象の停止をまとめて解除できます。

### 分断と復旧

分断中は各側で参加数・方針・コーディネーターを定めて許可処理を継続します。クラスター全体一回が各側一回になり得ること、自側実行結果、反対側結果不明、全体一回保証喪失を区別して示します。既発生の外部送信・ファイル・プロセス・物理動作は再接続だけで取り消さない。

復旧ピアはsyncingとし、定義・割当・保存・必要スナップショット・共有runtime・schedule・障害・役割を同期し、一致、必要プロセス・資源・インターフェース、結果共有まで通常実行・外部出力・コーディネーター・古い状態による上書きを認めない。

共有状態全体の同期は転送元・先の実体と一つの書出しを固定し、UDP の小さい断片で双方向に取得します。全長・内容ハッシュ・期限を検証するまで保存へ取り込まず、転送途中で異なる版を継ぎ足さない。作業容量・同時数・期限に上限を持たせます。通常参加の準備中であっても、同じ実体から直近の生存通知を実受信していれば同期の読取りを許す。同期済みの共通運用版と稼働反映済み定義をローカルに準備してから実行先の候補へ進み、個別の不正定義や機器問題はその対象へ隔離します。

内部UDPの応答は、同じ要求・送信実体・内容なら再送でも配送IDを維持し、欠けた断片を補えるようにします。異なる内容の断片は混ぜない。分割配送は短い間隔を挟んで送り、受信側への集中を抑える。宛先の実体は先頭の断片で照合し、別実体や期限後の応答を新しい要求として扱わない。同期の読取量も小さく区切り、更新中の新旧版の混在でも一度の応答が大きくなりすぎないようにします。

共有操作の結果保存が別の確認処理と競合した場合は、すでに保存された結果が全項目で一致し、未解消の競合もないことを確認します。同じ確定結果を先に保存した処理があれば、その結果を採用し、元の変更を再実行しません。内容が異なる場合は確認不能のまま扱います。

同じ操作が各ピアで取消済みの場合、準備要求より先に取消が届いた側だけ要求内容の指紋を持たないことがあります。この差だけで同期を拒否せず、各ピアの取消結果と保存先を保持し、遅れて届く準備・確定要求から取消済みの変更を実行しません。取得済みの指紋同士が異なる場合や、取消と適用済み結果が食い違う場合は引き続き取込みを拒否します。同期データを拒否した場合は、その理由を応答し、通信の無応答として扱わない。

保存先を確保した後でも、準備が成立する前の取消結果には指紋が残らない場合があります。取消として矛盾しない場合だけ保存先に記録された指紋で同期内容を照合し、既存の取消結果と保存先は書き換えない。

分断側は対等に比較し、非競合変更を自動統合、競合を取消・上書き・比較選択で解消します。意味上競合に依存せず単独で整合確認できる変更だけ先行利用できます。競合と依存範囲は停止し、影響外を続けます。統合後コーディネーターは高優先度、同順位なら通常参加可能な分断前担当、それ以外は通常新規選出条件で一担当へ戻します。

共有保存の候補分岐と、同じ草稿を編集したときの比較不成立を区別します。内容の分岐は全候補を保持し、検証できた依存範囲だけを制限した参加状態を `Degraded` として示します。保存候補だけが分岐していて旧有効版を確認できるワークフローは旧版で継続できます。有効な共通設定の一部が分岐した場合は、実際の共通変更元と全候補から非競合項目を合成し、派生版・元候補版・未解消項目を示します。

未解消項目は実行要求にも保持し、受信先にまだ同じ分岐が見えていなくても、その項目に依存する新規処理やホストグループ選択には使わない。候補の明示解消は確認した候補集合を比較し、保存・スナップショット・反映を別段階で実施します。識別子衝突や未検証の破損を、この限定参加で許可しません。

全停止後は、必要状態の完全性・整合性・非破損・版互換性・最新確定状態・競合候補不存在を確認できれば一ピアから単体縮退再開します。明示的なクラスター停止操作では一時追跡を先に解除し、人の一時停止は維持します。任意の OS クラッシュで全停止したことと分断は区別できないため、単体で戻った事実だけから全停止を推定しません。信頼できる一状態がなければ復旧・診断だけを提供し、通常出力を開始しません。候補を人が選んでも再検証します。後から別の完全候補が現れた場合も黙って上書きせず復旧限定へ移る。

明示離脱はOS再起動を越えて維持し、人が再参加させる。離脱中の操作を種類別設定でき、未設定ではlocal編集・ワークフロー・ファイル・プロセス・外部送信を含む独立運転を許す。ただし通常P2P参加・コーディネーター・共有状態の直接変更は行わず、変更を共有済みと表示しません。再参加で統合可能な変更だけ統合し、外部副作用を巻き戻した扱いにしません。

離脱側のワークフロー保存・有効化・自動スナップショット・共有範囲のノード状態は、そのピアのローカル変更として変更元を保持します。ローカル保存の成立と未共有を同時に示し、草稿と操作者通知も通常参加側へ送らない。再参加で非競合だけを統合し、競合は変更元・現在共有版・ローカル版を比較します。人が比較した共有版が送信前に変わった場合は再確認を求めます。固定した統合要求の結果不明は元 ID の照会に限定し、変更前の未実施が確定した場合だけ、新しい明示比較またはローカル破棄を許す。

ピア固有のノード状態はワークフロー専用範囲に保存し、同名ワークフローが membership・effective 等の内部保存を変更しません。

## 5. 共同編集・保存・復元する

全接続クライアントは全ワークフローの定義、接続、配置、設定、実行、保存、スナップショット、警告を共有して閲覧・操作できます。同じノード・同じ値を同時編集でき、選択・cursor・drag途中・操作者・未保存変更の存在を共有します。入力途中の具体値や確定前接続線 previewは必須共有にしません。

競合は後続編集者へ現在値と変更案を示し、取消・上書き・比較選択を本人が決める。別copy保存や競合保留を標準三択に加えない。切断中でもlocalで有効な編集状態を保って編集でき、再接続時に非競合を自動統合し、競合だけ三択とします。統合前のlocal変更をクラスターへ保存・反映済みと示さない。短命画面識別の変更で変更内容を失わない。

保存済み・共有済み・現在有効を分けます。変更種類別に自動有効化・明示反映・影響確認付き反映を選べ、未指定は保存共有後に新しい処理から自動有効化します。ただし本体保存共有成功後の自動スナップショットだけFailed／ResultUnknownなら、本体成功を維持してスナップショット非成功を別表示し、新設定の自動有効化を保留、旧有効を維持します。

内部保存方法は用途ごとに選択可能とし、全用途をひとつのDB製品役割へ固定しません。保存不能時は用途別に旧保存状態維持または未保存有効を選べ、RPO 0対象・外部影響設定は旧状態維持が既定です。代替方法は事前明示・保存成功確認後だけ使用します。ワークフロー編集以外のオフライン情報は用途別に利用不能・最後の確認済read-only・端末内未確定変更を選び、外部業務データへ内部の自動統合を黙って適用しません。

設定・実行状態・プロセス・診断の用途に SQLite または JSON を指定できます。同一の原子的保存を構成する設定本体・履歴・スナップショット保護は同じ用途にまとめる。保存不能時の候補利用も通常の意味検証・編集保護・自動反映／明示反映／影響確認に従う。現在有効・保持候補・保存済み・復旧可能な版を区別し、保存だけ成功してスナップショットが失敗した際に、以前の未保存有効版を保存済みへ読み替えない。未保存候補の採用結果が不明なら同じ候補を再適用しません。

再起動は確認済み永続版を基準とし、明示代替媒体に採用済みとして保存・検証された候補だけを、現在の保存版との対応を再検証して復旧します。

保存不能・オフラインの候補利用は設定と内部実行状態へ適用します。プロセスの外部動作や診断の実測値を、未保存候補の自動採用で実施・観測済みにしません。これらの用途では従来の確認結果を維持し、非既定の候補利用指定を設定時に拒否します。

### スナップショット

設定とruntime状態を別に保存・復元します。手動作成、ワークフロー保存時、ノード設定変更前の自動作成を提供します。復元範囲はワークフロー・選択ノード・サブワークフロー・ホスト・ホストグループで選べる。

ホスト・ホストグループ指定は選択時点の実ピアと設定上のノード集合へ展開し、その明示範囲で取得・復元します。ノード部分復元では選択ノードと接する接続線だけを置換し、ワークフロー全体属性と対象外ノードを現在値のまま保つ。全体スナップショットから部分選択できるが、部分スナップショットから未収録範囲へ拡大しません。同じワークフロー・ピア・状態種別に異なる候補を混合せず、一つの選択集合に一つの候補を指定します。

任意キーの runtime 状態を根拠なくノードに所属させず、宣言された状態単位と互換契約で復元します。

空のホストグループや対象ピアのない指定は、対象なしとして開始前に拒否します。選択結果が空になったことを「対象未指定」と扱い、全ピア・全ワークフローへ拡大しません。

対象別に指定時点以下の最新スナップショットを選ぶ方式と、明示組合せを併用します。時点以前のスナップショットなしは現在状態維持・未実施warnとし、対象スナップショットを適用する実集合からだけ除外します。人が復元範囲から明示除外した対象も現在状態維持・未実施warnとするが、この対象は復元範囲そのものから外す。明示したスナップショットの欠損・読取不能・破損・対象不一致・不整合は全体開始前に拒否し、別物へ代替しません。

設定だけ、runtimeだけ、両方を選べる。選ばなかった現在側との整合も検証し、黙って初期化しません。復元を保証するruntime項目は保存・復元・事後比較すべての対象にします。外部副作用、外部内部状態、開始不明処理を古い値だけで復元済みと示さない。

復元開始前に退避し、現在稼働を維持したまま新状態を準備・検証して切り替える。実復元集合は全体成功／全体失敗とし、失敗時は時点以前のスナップショット自然欠損対象も含む当初復元範囲全体へ退避状態の復元を試みる。人が復元範囲自体から明示除外した対象は補償範囲にも含めない。期待状態と実状態を比較し、不一致・比較不能・補償失敗は手動介入として示します。補償成功を対象スナップショット復元成功にしません。

影響範囲の未保存編集は確定または取消を待ち、範囲を再確認して全クライアントread-onlyにします。退避前から準備・切替・比較・補償まで維持し、整合と結果共有後に解除します。影響外編集は続け、実dataflowや所属だけでlockを広げない。現在稼働を維持して準備できなければ拒否／中止し、復元のためだけに自動停止しません。

復元要求の指紋、下書きの版、ピア、UI 実体を確認して保存済み確認または選択範囲取消を行います。他 UI の未送信入力を代理承認しません。共有の編集保護は通常保存と同じ CAS で検証し、結果不明では保持します。回復は元操作履歴と固定実体の元操作記録を照会し、元操作が存在しない回復要求から新しい復元を開始しません。

独立した共通運用設定も同じ共有保護に参加し、復元対象でないピアからの保存・有効化で迂回しません。`cluster-operational` と登録済み独立設定の識別子はワークフローに使用できません。旧保存物で識別が衝突している場合も別対象を選んだとは解釈せず、曖昧なスナップショットの取得・準備を拒否します。

## 6. アプリケーション・リソース・時間を扱う

アプリケーション別に管理対象／監視のみを明示します。既存プロセスも監視できます。監視のみは人の直接操作・人が開始したワークフローからもプロセス状態を変更しません。未登録プロセスは個別操作せずホスト全体のリソース監視に含めます。

管理対象の稼働要求期間中の予期しない終了を自動復旧対象とし、対象別の準備・復旧成功条件を構成できます。プロセス生存中の応答不能等も明示条件の成立を確認できた場合に追加できるが、判定不能を異常成立へ丸めない。人が停止前に復旧抑止を指定し、人が解除するまで維持できます。

自動復旧限界と準備待ちの製品初期値は有限とし、共通既定と個別設定で無制限／上限なしを選べる。有限復旧限界到達は再起動を止め、復旧不能・人待ち・警告・後続へ進む。一時復旧後の再異常は安定稼働条件または人の確認まで同じ故障とし、プロセス／ピア／クラスター再起動・日付変更だけでresetしません。

起動→監視準備待ち→後続起動と、起動→後続起動＋独立監視の双方を通常接続で構成できます。準備待ち失敗は独立監視まで終了させない。予定停止失敗時の強制終了／人待ちは処理別事前指定を必須とし、未指定なら通常終了要求も開始しません。実終了確認後だけ終了依存後続へ進む。

CPU・GPU・メモリ・device・ネットワーク等の取得値と取得不能をワークフローで扱えます。異常警告は対象・条件・時間・ログを通常ワークフローで組み合わせ、専用基準設定を増やしません。無効状態の編集可能な警告出発例を提供します。記録用ワークフロー未設定でも障害後に調べられるリソース共通診断履歴を提供し、警告ログだけで代替しません。

時間指定ノードはクラスターで一つの日時契機を渡し、実行先・回数は後続処理に従う。全ノードはクラスター共通timezoneを使用し、ノード別override・OS localへの暗黙依存をしません。

- 確認済み未実行回は、遅延実行・見送り・許容時間内遅延から選択します。未指定は遅延実行、複数未実行は最新実行可能一回だけを残します。見送りで次回を失効させない。
- 前回実行中の次回は既定並行、明示で見送り・最新一回保留・全回順番待ちを選択します。指定全ピアでは対象別に適用します。全件待機を黙って破棄しません。
- 予定が発生した時点で、設定・タイムゾーン・対象を固定します。スケジュールの無効化は、これから発生する予定に適用します。遅延実行に必要な予定は保持し、開始済みの処理を取り消す場合は、その処理の取消操作を使用します。時差を含めて指定した一回限りの日時は、タイムゾーンを変更しても同じ時点を指す。
- 時刻品質不足は停止／warn継続を選べ、未指定warn継続。存在・未実行不明の回を暗黙開始しません。全ピア停止後の待機状態の復元は保証しません。

## 7. ファイルとAI・メディアを処理する

ファイルは存在確認、読み取り、新規作成、置き換え、追記、コピー、移動、名前変更、削除に対応します。ディレクトリは作成、存在確認、一覧取得、名前変更、移動、空の削除と、内容を含む操作に対応します。操作元・操作先のピアと絶対パスを指定し、それぞれの CoreService が持つ OS のアクセス権で実行します。

存在前提不一致を別操作へ変えず、明示していない同名上書きをしません。削除対象なしは指定により正常変更なしにできます。複数対象一部失敗は処理別に成功維持／全対象復元を選べる。

両立しない操作のクラスター共通方針は、既定が後発開始前失敗、選択で先行完了待ちとします。待機後は実状態で前提を再検証します。別のクラスター共通方針として対象内部途中失敗の完了済維持／失敗対象内部復元を選び、既定は維持とします。この二つの共通方針を個別ファイル処理で上書きしません。

全対象復元を指定したファイル操作は、固定した全対象で許可・実パス・重複範囲・開始前退避を確認した後に実行します。read/read は併存し、同一ホストの別ピアも書込み範囲の予約を共有します。一対象の非成功時は元実行結果と各対象の補償結果を分け、結果不明の所有者を期限だけで解放・再実行しません。外部通信、プロセス、AI の外部生成等の副作用はファイルの退避復元で取り消した扱いにしません。

中断後の明示retryは新しい一回とし、元・先・内容・完了部分を確認できる途中成果を再利用できます。確認できなければ先頭から新規または失敗とします。再帰操作のワークフロー明示を実行意思とし、実行時追加人確認と共通取消猶予は必須にしません。取消は安全に止められる未実施部分に適用し、完了済を自動復元せず、遅すぎた取消・途中停止・停止不明を区別します。

AIは四媒体の生成、設定済処理先選択、AIによる内容分類と後続選択を提供します。メディアは音声・動画・画像変換を提供します。専用能力を単なる外部プロセス起動で代替せず、Generator／Converterは固有条件を満たした最終出力を取得します。Router自身の選択成功と選択先処理成否を分けます。

長時間処理は処理中と最終結果を示します。提供先が進捗／取消を提供し対応範囲に含めた場合に利用し、取消要求・受付・実停止・結果不明を区別します。対応する外部サービス、モデル、コーデック、バージョン、出力形式と制約を対応一覧に記載します。実接続で確認した範囲と、ローカルの試験で確認した範囲を区別します。

AI・メディアノードの対応サービス、入出力形式、上限、失敗時・取消時の動作は、[AI・メディア](nodes/ai-media.md)にまとめています。

### AIノードの接続設定と入出力

OpenAI（テキスト・音声・画像・分類）、Qwen音声、Wan動画、ElevenLabs音声は、それぞれ専用の公式API接続を使用します。任意Endpointを入力させたまま無視する構成にせず、設定画面には実際に使うAPI接続先を読み取り専用で表示します。OpenAIとElevenLabsにはRegion欄を出さず、QwenとWanはSingapore／Beijingから選んだリージョンで接続先を決める。

APIキー、モデル、Qwen音声ID、再照会するWanジョブは同じリージョンのものを使用します。Wanの既存ジョブを再照会する場合は、新規生成の指示文・長さ・画面サイズを要求せず、元のジョブだけを照会します。保存済み設定にリージョンがなければ、Singaporeを使用します。

生成ノードは実際に返す生成物だけを公開し、Wanには未確定ジョブの識別子、内容分類には分類結果と判定対象の情報を追加します。すべてのAIノードに分類結果やジョブ出力を一律で付けない。内容分類の入力形式は音声・画像で、フレーム抽出時点は動画で使用します。詳細設定は選択した媒体に必要な欄だけを表示し、媒体を切り替えた場合に備えて非表示の値を保持します。ノード内の概要欄では使用しない項目を明示します。

参照: [OSC 1.0仕様](https://opensoundcontrol.stanford.edu/spec-1_0.html)、[Wan 2.1–2.6 API](https://www.alibabacloud.com/help/en/model-studio/legacy-wan-text-to-video-api-reference)。Wanの既存リージョン別ドメインは公式APIで引き続き利用できます。

ワークスペース固有ドメインや未対応サービスへの接続は、利用先の契約を確認してから追加します。

## 8. ログ・秘密値・操作画面

[HostManager](pc-management.md)は全発見クラスターのピアをホスト単位にまとめ、NetworkIF、Hosts、Firewall、PATH、Display、Power、Windows Update、Loginを管理します。NetworkIF・Firewall・永続環境変数・DisplayはWindows、hosts編集はWindows/Linux/macOSに対応します。各ホストへ能力を照会し、専用機能で非対応ホストを選択できないようにします。

Displayはコンソールに接続されたディスプレイごとに、ドライバーが公開する解像度・リフレッシュレートの組を選択します。設定確認から接続や現在値が変わっていた場合は開始せず、変更後も現在値を照合します。配置・回転・主画面は維持し、サービス実行時は接続主体を検証する補助プロセスで対話セッションへ処理を渡します。

Power では自動電源タイマーの状態を確認し、AC 電源／バッテリー別の時間と電源ボタンの動作を変更できます。連続稼働向けに、自動タイマーと高速スタートアップを無効にする設定をまとめて入力できます。高速スタートアップは休止機能と分けて設定します。無操作シャットダウンは PC 共通の明示設定とし、ログオンセッションの入力を検証します。全 CoreService で開始記録を共有し、同じ無操作期間の副作用を自動再送しません。

Windows Updateは対応するPro以上のエディションで、期限を設けず手動更新のみとするローカルポリシーを設定できます。優先されるローカル期限ポリシーも無効にし、その変更を確認画面に含めます。組織管理下のPCは管理元での設定へ案内します。既に進行中・再起動待ちの更新を取り消したとは報告しません。

LoginはPC起動後のパスワード入力を省略する運用に向け、ローカルユーザー選択と自動ログインの有効無効を設定します。有効化時は対象SIDと資格情報を確認し、秘密値をブラウザーから平文で送信・履歴保存しません。WindowsにはLSAで保存し、無効化時は自動ログイン用の保存資格情報を削除します。ログインメッセージがあってもアカウントを保存できるが、自動ログインを妨げる状態は明示します。メッセージのタイトル・本文は明示選択時だけ削除し、管理元ポリシーによる再適用の可能性を表示します。

アプリケーションのスタートアップ登録や即時再起動は別の操作とします。

NetworkIFはInterfaceGuidを固定し、IPv4/IPv6、DHCP、IP/prefix、メトリック、DNS、ゲートウェイを部分変更します。同一ネットワーク候補をサブネット・確認済みVLANで絞り込み、DNS／ゲートウェイを明示選択したNICへ一括適用できます。同じIP帯が同じ物理LANとは推測しません。Hyper-Vは既存スイッチ上のManagementOS用vNICを作成・削除し、Access VLANとUntaggedを区別して表示・設定します。

未確認値をタグなしとして扱わない。

HostsはOS既定ファイルの版を確認し、原文退避と原子的置換を行います。Firewallはプロファイルとローカルルールを対象にし、GPO等のルールを編集可能としません。PATHタブはMachine/Userの永続環境変数を扱い、Userではホストごとのロード済みSIDを明示します。既存プロセスの環境を変更したと表示しません。

一括操作は元対象と各操作IDをClientHostで保持し、CoreServiceは同一PCの排他、OS変更前の永続開始記録、変更後の照合を行います。通信断、途中失敗、未実行、不明を区別し、再起動で副作用を再送しません。不明結果の照会は参照専用とします。現地確認後の新規操作は明示した確認を要求し、過去の不明結果は保持します。

Windowsの[RemoteDesktop](remote-desktop.md)はVP9を既定とし、Intel QSV、CPU（libvpx）の順に実際の符号化を試してエンコーダーを選びます。H.264・H.265はURLの `experimental=true` または[ブラウザーの常時有効化設定](../guides/web-client.md#試験的な機能を有効にする)で選択でき、NVIDIA NVENC、AMD AMF、Intel QSV、CPUの順に試します。VBRを通常機能として既定にし、`experimental=false` でも利用できます。接続設定のCBR／VBRトグルで方式を選び、次の接続に反映します。

VBRでは設定した映像最大ビットレートを目標最大値、平均目標をその半分として扱います。品質指定とは併用しません。瞬間的な通信量や音声・ヘッダー込みの帯域上限を保証する設定ではなく、画面上の注意書きはツールチップへ集約します。

ホスト選択の左に伝送プリセットを設け、モバイル回線の安定性優先・品質優先、固定回線の安定性優先・バランス・品質優先、LAN環境を選べる。既定は固定回線のバランスとします。fps、映像と音声のbitrate、音声コーデック・バッファー、キーフレーム間隔をまとめて設定し、通常画面でもキーフレーム指定を送信します。設定値が一致しない場合だけ「カスタム」と表示します。モバイル安定性優先は8fps・映像1024kbps・Opus 64kbps・バッファー36000・キーフレーム8を使用します。

LANはPCMと映像10240kbpsを使用し、60fps・キーフレーム30で短い参照間隔とします。各値と選定根拠は[伝送プリセット](remote-desktop.md#伝送プリセット)に定義します。

[GUIのFileTransfer](file-transfer.md)は対応CoreServiceとの固定NIC・固定実体のTCP接続で最大1MiBずつ転送します。旧版または本文送信前の接続不能時は32KiBの管理経路へ戻る。送信開始後の切断では別方式へ切り替えて暗黙再送せず、各転送片・全内容・マニフェストを確認してから確定します。確定応答の欠測は元の永続操作を照会し、新しい操作として確定を再実行しません。

ワークフローの `file.transfer` は従来の32KiB RPC経路を維持します。

高頻度正常通信は通常運用で一件情報・集約情報を既定保存し続けず、warn／errorを維持します。ワークフロー単位で保存済み詳細追跡と一時詳細追跡を利用でき、受信場所、ノード順、各結果・条件経路、ピア間引継ぎ、最終出力または停止地点を正常・異常とも追える。

詳細取得範囲を選べ、未指定時は生受送信・解析値・変換前後値・条件値を対象にします。秘密値は常に除外します。一時追跡はクライアント切断・ピア交代を越え、人の解除またはクラスター全停止まで続けます。時間や資源圧迫で自動終了せずwarnします。ログが実際に出せなくても本来処理を続け、欠損を示して回復後の新規から再開します。

入力、出力、生通信を独立選択し、未指定はすべて取得します。生通信の任意上限は秘密値をマスクした後に適用し、元バイト数と切詰めの有無を示します。HTTP 認証ヘッダーは取得しません。方針は一件の開始時に固定し、待受ノードの次の一件から新方針を使用します。状態取得不能だけで以前の確認済み方針を自動解除しません。

運用操作「一時追跡を解除して Cluster 停止を要求」は、固定した参加実体へ解除を共有確認してから停止要求を送る。停止受付、実停止確認不能、部分停止を区別し、全停止完了を推測しません。停止進行中は新しい一時追跡を有効化できず、停止要求の取消とは別の明示操作でこの保護を解除します。任意のクラッシュ全停止と partition の識別不能は運用上の制約として残します。

全ログレベルに同じ利用不能原則を適用します。元ログが残る転送・圧縮・検索不能は生成欠損と区別し、元を削除せず復旧後に利用できるようにします。存在しない過去ログを再構築しません。

保持はレベル別・同レベル内共通とします。全レベル共通rolling時刻で日付を区切り、rolling日付からの経過日数で通常ファイル→zstd→削除を管理します。無期限も通常ファイル期間後はzstdへ移す。稼働中変更は次に従う。

| 変更 | 既存ログへの結果 |
| --- | --- |
| 保持延長・無期限化 | 残存既存へ適用、削除済みは復元しない |
| 非圧縮期間短縮 | 新境界を越えた既存を追加確認なしでzstd化 |
| 削除期限短縮 | 既存にも適用するか、新規だけにするか選択 |
| 非圧縮期間延長 | 既存zstdを再展開するか圧縮維持か選択 |

API キー・トークン・passwordは全クライアントから登録変更できるが、保存後通常再表示と全ログ・error・詳細追跡への生値出力を行わない。必要ピアは障害・再参加・スナップショット復元後も再入力なしで利用できます。秘密変更とログ保持変更は対象・時刻・成否・端末名・任意表示名を値なし通常ログに残します。

個人情報取扱箇所を明示でき、非DEBUG ログと表示は伏字、DEBUGは許可された生値を扱えます。保存・外部送信は別の明示処理を要し、個人情報指定そのものを保存許可としません。音声・会話・VoiceID 等のデータを扱う場合は、本人の同意、利用先の契約、保存期間の条件を確認してください。

WorkflowEditor、Dashboard、LogViewer は Web ブラウザーから利用できます。Web クライアントは Blazor、インストーラーは Avalonia を使用します。CLI はサービスを別プロセスで起動し、管理 API を通じて設定の検証・適用、状態やログの照会、診断を行います。内部 DB を直接変更しません。

### 管理画面の操作と表示

画面間で名称、色、操作方法を揃えます。設定値や未保存の編集を保持しながら、利用者が修正箇所と操作結果を確認できることを重視します。

- 共通: 正式名称Clutch-CSと画面上の表示名を区別し、Web クライアント左上の既定をClutch-CS／WebUIとし、上下段の表示名は導入先の設定で変更できます。共通フッター右側にはClutch-CS・著作権・現在読み込んでいるUI版、左側にはOSS License・Storage status・FileTransfer進捗・更新進捗・UI assetsを配置します。領域に収まる文字組みにし、暗いマットな Fluent 系ダークテーマを固定し、重複する枠や階層を減らす。英語を既定とし、表示設定で自然な日本語へ切り替える。ユーザーが付けた名前・入力値・ログ本文・識別子は翻訳によって変更しません。
- WorkflowEditor: 到達可能なクラスター、そのクラスターのワークフローを二段のタブで切り替える。切替時に未保存の編集を保全します。カタログは折り畳み、ドラッグ＆ドロップ、Tab／Shift+A の検索メニューから追加できます。ノード内で定数入力と設定を編集でき、接続された入力は読み取り専用にします。値の表示は折り畳める。
- カタログ・操作: カテゴリ別・種類別・表示名順を選べる。グループは個別に折り畳み、検索中は一致した内容を表示します。名前順は選択言語の表示名と照合規則に従う。キャンバスの空欄ドラッグで座標移動、Ctrl＋ホイールでポインター中心の拡縮を行います。フォーカス中のノードや線は Delete・右クリックメニューから削除し、Undo で戻せる。文字入力中の Delete と復元保護を維持します。
- 配線: ノード分野と入出力の種類を色・ラベルで示します。未確定のデータ型を確定型に見せない。線は曲線・直線・直角から選択し、方向アニメーションを任意で有効にできます。既定は曲線・アニメーションなしとし、方向表示を実行中の表示と混同させない。
- ポート名と型表示: `value`・`result` などの保存用識別子は維持し、画面には受信データ・変換結果・計算結果・実行結果などノードごとの役割を示す名前を表示します。共通の実行結果、入力元情報、実行PC候補、反復の境界は値の型と区別します。カタログ・グラフ・設定入力・接続線・接続候補の名前と色を日英で揃え、未知の拡張ノードの独自名は保持します。JSONテキストやBase64を入力する必要がある欄では、値の種類とは別に入力方法を説明します。
- 接続操作: 入出力端子からドラッグして配線できます。入力側・出力側のどちらから始めても同じ型互換判定を使い、既知の不適合接続を拒否します。推測できない型を不適合と決め付けない。ドラッグ取消・不適合・保護中の対象では元の配線と保存値を維持し、正常な差替えは一回の Undo で戻せる。クリックでの接続も同じ判定を使用します。
- 値と設定: 入出力には、内部の格納形式ではなく、文字列・整数・数値・真偽値・バイト列・配列・オブジェクトなど、扱う値の種類を表示します。ノードの処理内容・定数・明示型・接続された設定から出力型を推測し、配列の要素型と項目の抽出にも反映します。nullや項目の省略があり得る場合はその可能性を併記します。未知・欠落・循環を具体型へ丸めず、任意の値または未確定として扱います。設定には `$settings.<設定名>` の宣言済み端子から純粋な値を接続でき、保存時の元値は維持します。接続値を解決してスキーマと固有条件を検証し、通信などの動的結果を静的設定として採用しません。Interface ID と対応 IP、固定列挙などは選択式にします。欠落した選択肢は値を保持してエラーを示し、別の値へ黙って変更しません。
- Dashboard: 全観測クラスターを集約した概要を左端・既定にし、選択クラスターの概要も提供します。PCの状態は概要／詳細を切り替え、既定は概要とします。概要にはホスト名・参加状態とCPU・RAM・GPUの実測を表示し、各指標に推移グラフを付ける。CPUは使用率・CPU名・コア数／スレッド数を表示し、CPU名は1行に収まらなければ末尾を省略します。RAMは使用量を大きく、その下に総容量と使用率を表示します。GPUは専用メモリの総容量が最も大きいものを選び、GPU使用率と専用メモリの使用量・総容量・使用率を表示します。詳細にはCPU構成、各GPUの専用・共有メモリ、取得可能なCPU温度、選択NICの通信速度など従来の情報を表示します。クラスターの状態は十分な表示幅がある場合に1行2クラスターとします。各クラスターのReady数・確認済み数・コーディネーター・最終確認時刻は、カードの幅に余裕があれば横1行、狭ければ2行に並べる。クラスターとPCのカード外観・Readyバッジをそろえ、クラスターの判定条件は見出しの補足として表示します。ワークフロー完了頻度と直近ログもまとめて表示します。専用VRAMと共有GPUメモリは区別します。初回・欠測・古い値・カウンターのリセット・取得範囲の省略を区別し、推測値を埋めない。同じPCの複数ピアを別PCとして数えず、クラスター集約の取得で他画面の選択先を変更しません。
- LogViewer: 時刻、PC／ピア、ワークフロー、ノード、起きたことを優先します。関連する実行を追う識別子は詳細と絞込みで扱い、専門用語だけを主導線にしません。
- 追加ノード: `data.convert` は文字列・有限数・正確な64bit整数・真偽値への明示変換を行います。`math.add`／`subtract`／`multiply`／`divide` は有限数の四則演算を行い、暗黙の文字列変換、整数の黙った切捨て、ゼロ除算や範囲外の成功扱いをしません。日時・周期・曜日による実行は既存の `scheduling.timer`、登録済みプログラムの起動は `process.start` と準備待ち・終了・監視ノードを組み合わせる。
- 値ノード: `value.constant` は自動解釈／bool／バイト／Int64／有限の浮動小数／正確な decimal／Unicode 一文字／文字列を生成します。`value.type` は要素型・プロパティ型・任意値を定義します。`value.array`／`value.keyValue` は実データと型定義の両方を構築し、重複キーの拒否／明示置換を選択します。`http.method` は選択したメソッド、`value.interface` は選択した NIC 識別子を出力します。Math は日英共通のカテゴリ名とします。
- 型付き HTTP: `http.listen` の method／queryType／bodyType を値ノードから構築できます。照会は型に沿って文字列・反復項目を変換し、本文は明示型と一致する JSON を受け付けます。必須・未知項目・要素型・数値範囲・壊れた Unicode を検証し、不適合は HTTP 400 と一件失敗にします。メソッド不一致は 405 とし、いずれも待受全体を終了させない。日時スケジュールは一回・日次・曜日・対象日・除外日と、指定区間内の一定間隔を共通ノードで構成します。

CoreService は Generic ホストの常駐バックエンドとし、Web クライアント/Blazor 参照、画面配信、HTTP 管理待受を持ちません。ClientHost は端末内の GUI・CLI 用 HTTP facade と Blazor 配信を担当します。利用者は ClientHost 自身の NIC・IP・ブロードキャスト範囲を選び、受動 UDP 監視処理で到達する複数クラスターを発見します。

各要求に ClusterId・PeerId を指定し、通常の閲覧・変更は型付き UDP 管理操作として CoreService 内の既存サービスへ直接渡します。RemoteDesktop・Terminal、対応版の更新ペイロードとGUIファイル転送の本文は、それぞれ用途を限定したTCP経路を使用します。GUIファイル転送の最終確定は既存の永続管理要求で行います。CoreService への HTTP proxy、クライアントのピア登録、暗黙の全画面共通クラスター切替は行わない。

同じブロードキャスト範囲で他のピア間に大量の同期・返信が流れても、自分宛ての管理要求の受信を妨げないようにします。先頭の断片から対象外と確認できた配送は、組立て待ちの枠を使わずに破棄します。先頭断片だけでは判断できない場合は従来の組立てを行い、配送全体の宛先・実体・ハッシュの検証も維持します。

閲覧定期照会と cursor・編集者情報の一時通知は永続操作記録を蓄積しません。確定変更は呼出元が指定した要求 ID・指紋・対象実体・開始期限を保持し、再送は同じ結果を返します。結果不明は元操作記録の照会へ進み、再起動後の別実体へ副作用要求を差し替えない。ログ転送は通常管理 UDP と別の TCP 経路を使用します。

ワークフロー・スナップショット・実行履歴・ログの管理一覧は、本文と識別に必要な情報を分け、件数とバイトの上限でページ化します。巨大な一項目で後続を永久に取得不能にせず、省略した項目・範囲・理由を示します。省略したノード集合を全体指定へ読み替えない。大きいワークフローの完全本文は版と対象を固定して分割取得し、全長・順序・ハッシュが一致した後だけ編集へ使用します。

実行結果の詳細を保持・返却できない場合も、確定済み成否と確認できた対象別理由をサイズを制限した要約として永続保存し、別ピアや再起動後に不明へ戻しません。結果のシリアライズ失敗を未実行の証拠にしません。

クライアント到達可能な未知端末も全操作可能とし、login・account・role・端末認証を設けない。端末名・任意表示名・短命画面識別で操作元を見分けます。内部通信は平文を許容するが、外部認証・通信保護・ネットワーク到達制限は別境界です。

### 操作に応じたノード編集

組み込みノードは、設定・入力・出力の宣言と実際の処理を一致させる。抽出方法、構造変換、条件分岐、スケジュール、PC選択、HTTPの成功確認・返信方法、AIの入力媒体に応じて、詳細設定では使用する項目を表示します。別のモードで使う保存値は保持し、現在の処理に無関係な値で実行を妨げない。条件を決める設定が接続されていて値が未確定の場合は、保存済みの値だけを根拠に関連項目を隠さない。

型定義入力は通常データのAnyと区別して表示・検証します。型構築では配列要素とオブジェクト項目の役割を説明し、設定に応じた入力と生成結果を示します。OSCの引数型は固定設定値の接続にも対応し、接続後の形状を表示と開始前検証で共有します。OSCの型定義指定では汎用整数をInt32（i）、明示Int64をh、数値をFloat64へ対応させる。OSCパケット構築の型未指定整数は32bit範囲内ならi、範囲外ならhとし、明示Int64とOSCタグの精度は保持します。未対応型を黙って変換しません。

ファイル関連設定は手入力に加え、対象PC・ピアの許可フォルダー内の選択を提供します。転送元と実行先の役割を混同せず、ピア・ファイル・ディレクトリ選択ノードからも設定を供給できます。APIキーはクラスターに登録した名前から選び、ノード設定から実値を登録できます。ワークフローには登録名だけを保持し、暗黙の環境変数を想定しません。実行PC自身のアドレスと相手側エンドポイントを別の役割として明示します。

メディアの形式とコーデック、AI分類の媒体と入力形式、リソース比較の対象と単位は、対応する組合せを候補として提示します。以前の選択が新しい条件に合わなくなった場合は、その値を明示し、別の値へ黙って置き換えない。固定の既定値は実処理と同じ値を宣言します。nullが有効な設定には明示選択を用意し、たとえばプロセス準備待ちの「未指定（共通の待機上限）」と「null（無期限）」を区別できるようにします。

プロセス操作、リソース観測、イベント受信、状態操作で、値を使用していなかった旧入力は新規作成時には表示しません。保存済みの配線・定数がある場合は表示を残し、値が使用されないことを説明します。既存の開始順序への依存を削除せず、新しい開始依存は共通の開始契機入力へつなぐ。操作が使用しない旧設定も保存値を勝手に削除せず、未使用の説明と解除操作を示します。状態の期待版は比較更新、保持期限は重複抑止で使用します。

条件分岐には真偽値または判定不能のnullを返す `matched`（条件の判定）を設ける。共通の `result`（実行結果）とは別の出力とし、真偽値を次の処理へ直接配線できるようにします。既存の実行結果の構造・経路は維持します。

## 9. 導入・更新・検証

### セットアップ

インストールでは、OS・CPU・権限・ネットワーク・保存先を確認し、必要なファイルと自動起動設定を配置します。起動後に同期と参加状態を確認し、通常の処理に参加できる状態（Ready）になったことを確かめます。

Windows の対話型セットアップは、インストール・更新・修復・アンインストールに対応します。対象と実行内容を確認してから処理を開始し、進捗と結果を表示します。詳しい操作は[導入ガイド](../guides/manual-install.md)を参照してください。

### 更新する対象と順序

クラスターを指定する更新と、ClientHost が発見した複数のクラスターをまとめて更新する操作を提供します。開始時に対象、ピアの起動実体、優先順位、並列数を確定します。並列数は 1〜3、既定は 2 です。

- 同じ PC または同じクラスターの更新は同時に行いません。
- 3 ピア以上のクラスターでは、更新対象を除く Ready のピアが過半数を満たすことを確認します。
- 2 ピアで複数の PC に分かれる場合は、相手の Ready を確認します。
- 2 ピア以下で 1 台の PC に配置される場合は、更新中の一時切断を許容します。
- 条件を満たさない対象がある場合は待機し、その間に更新できる別の対象を処理します。

所属数と Ready は、準備前と停止直前に CoreService へ照会します。発見一覧に表示されていない停止中のピアも、所属数に含めます。更新後は、新しい起動実体、指定したバージョン、Ready、メンテナンス状態の解除まで確認してから次の対象へ進みます。

稼働中の更新は既定で拒否します。実行する場合は利用者が許可し、対象のピアを停止しても残ったピアで必要な処理を続けられることを確認します。更新を進めるために、指定済みの実行先を別の PC へ変更することはありません。

### 失敗・中断からの復帰

適用前に配布物の破損・欠落を確認します。部分的に失敗した場合の対応は、開始前に選びます。

| 状況 | 対応 |
| --- | --- |
| 一部の対象で更新に失敗 | 更新済みの対象を維持して続行するか、成功した対象も旧版へ戻すかを選択 |
| 旧版への復帰にも失敗 | 対象を除外して続行するか、クラスターを停止するかを選択。既定は除外して続行 |
| 処理が始まっていないことを確認できた | 回数の上限を設けて再試行 |
| 旧版への復帰を確認できた | 方針に従い、回数の上限を設けて再試行 |
| 更新や復帰の結果を確認できない | 結果不明として後続を保留し、元の操作記録を確認 |

中断した更新は、対象ごとに完了・未開始・処理中・結果不明と実際のバージョンを表示します。続行方針がなければ、中断を失敗として終了し、開始時に選んだ部分失敗の方針を適用します。利用者が続行を指示する場合は、新しい更新操作として開始します。

処理を書き込んでいたプロセスが終了した場合も、まず同じ操作の記録を読み直します。終了直前に保存された最終結果や、別プロセスへの引き継ぎを確認してから中断を判定します。ClientHost の再起動後は元の操作 ID と結果を復元し、確認なしに更新を再開しません。

配布物に ClientHost を含む場合は、すべての CoreService の更新成功後、操作元の ClientHost を更新します。保存先、自動起動設定、実行ユーザーの権限を維持し、独立した Updater の記録から結果を確認します。失敗した場合は旧版への復帰を試み、その結果を表示します。この操作で更新するクライアントは操作元の ClientHost です。詳細は[更新手順](update-process.md)に記載します。

### ワークフローの互換性

ノードごとに動作のバージョンと互換関係を定め、保存したワークフローが要求する動作を提供できるか確認します。互換性がない場合は、影響するワークフロー・ノード・設定・スナップショットと理由を示し、その開始・復元を拒否します。影響のない処理は続行します。

設定形式が同じでも、意味や処理結果が変わる場合は互換性の確認が必要です。対応するバージョンを開発側で定義し、試験で確認します。利用者は表示された対象を編集・保存・反映して修正できます。

### 動作環境と検証

Windows x64 を必須の検証環境とします。Linux x64、Linux Arm、macOS arm64 は Best-Effort とし、OS 固有の機能は対応状況を各機能の資料に記載します。AVX2 は必須とせず、.NET と依存ライブラリが CPU の対応状況に応じて提供する最適化を利用します。実際に検証した OS、デバイス、GPU、実行権限は、試験結果に記録します。

通常ビルドでは共通 SourceCodeQuality アナライザーを有効にし、単体試験・結合試験を実行します。分散機能は複数の実プロセスと実通信で検証します。性能の測定方法は[性能試験](../development/performance-tests.md)、配布の生成方法は[セットアップと配布](../../installer/README.md)を参照してください。

次の事象は重大な不具合として扱います。

- 実行条件を満たす別のピアが残っているのに、1 つのピアの喪失で全体が継続できなくなる。
- 保存成功を応答した定義・設定・スナップショットを失う。ログはこのデータ損失ゼロの対象には含めません。
- 同期が一致する前に通常の処理へ参加します。
- 通常の操作ができない、操作の安全性を判断できない、確定済みの状態が一致しない状況が続きます。
- 処理待ちが増え続け、負荷が下がっても回復しません。

設計上の目標は、年間可用性 99.9%、担当ピアの喪失後 5 秒以内の回復、再参加条件が揃ってから 60 秒以内の復帰です。共有中の状態の反映は p95 200 ms、確定した状態は p95 500 ms を目標にします。構成・負荷・測定条件を揃え、実測値と影響を確認して改善します。

## 10. 外部システムとの接続確認

導入時に、接続先、通信に使うネットワークインターフェース、操作を許可するディレクトリ、アプリケーションの準備・復旧条件、処理の上限、履歴の保持期間を設定します。

外部システムや機器との接続では、送受信の成否に加えて、相手側で処理が完了したことをどの応答・状態から確認できるかを決めます。応答がない場合や接続が切れた場合も試し、結果不明の操作を再実行する条件を確認してください。
