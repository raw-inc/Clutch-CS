## 接続先

WorkflowEditorのクラスタータブにはクラスター名と状態を表示し、横のピア選択は設けません。特定のピアを指定する場合は、ヘッダー右側の「接続」を使用してください。明示選択がなければ、そのクラスターで一意に確認できるReadyのコーディネーターを接続先にします。明示選択したピアは優先し、指定ピアやコーディネーターを確認できない場合は任意のピアへ置き換えません。クラスタータブで自動選定したコーディネーターは、明示的なピア指定として固定しません。

ワークフローは通常クラスター共有であり、この接続先は管理通信の窓口です。未保存草稿の保全、切替時の実体照合、ノードに設定した実行先の扱いは維持します。

## 基本操作

1. `/editor` を開き、上段のクラスター、下段のワークフローのタブから編集対象を選択してください。
2. カタログからノードをドラッグして配置してください。キャンバス上の `Tab`／`Shift+A` から検索して追加することもできます。
3. ノードの値を設定し、入出力端子を接続してください。
4. 検証結果を確認して保存してください。明示的な反映が必要な設定では、内容を確認してから反映してください。

接続線の形、方向ガイド、端子の型表示は表示設定で変更できます。方向ガイドのアニメーションは、通信の発生状況を示すものではありません。

全体マップには、ノード全体の配置と、現在画面に表示している範囲を示します。既定で表示し、右上の「マップ」または空のキャンバス上で `M` を押すと表示を切り替えられます。

| 操作 | 動作 |
| --- | --- |
| クリック・ドラッグ | その場所へ表示の中心を移す。倍率は維持 |
| `Shift`＋ドラッグ | 選択した範囲全体が見えるように中心と倍率を調整 |

倍率は 5〜150% です。現在の保存版で実行中のノードは緑で表示します。複数の処理が並行している場合は、いずれかが実行中の間、緑を維持します。

保存などの操作結果は右上の通知カードに表示し、全体マップが見えているときはその直下へ配置します。通常の結果は約8秒で閉じ、ホバー・フォーカス中は表示時間を止めます。クラスター観測の取得失敗は同じ場所で復帰まで表示し、成功後に自動解除します。失敗中の候補には「前回の観測」と明記し、手動更新と定期取得を重ねません。

`Ctrl+F` でノード名・設定値・入力値を検索し、前後ボタンまたは `Enter`／`Shift+Enter` で一致ノードへ移動できます。件数はノード単位です。検索一致は黄、選択中の一致は紫の枠で示し、マップにも反映します。実行中の緑の塗りと検索の枠は併用できます。バイナリ本文は検索しません。コード編集など専用の入力領域では、その領域のショートカットを優先します。

配置したノードの見出しをダブルクリックすると、任意の**論理名**を編集できます。見出しにフォーカスして `Enter`／`F2` でも開始できます。`Enter` または入力欄から離れる操作で確定し、`Escape` で取り消します。空欄は種類名の表示へ戻ります。同じ論理名を複数のノードに付けられ、`Ctrl+F` では論理名・種類名の両方を検索できます。論理名を表示中も、その下に種類名、ホバー時にはノードIDを表示します。

論理名はワークフロー定義の各ノードの任意項目 `logicalName` に保存し、コピー・Undo・エクスポート・サブワークフロー内の表示にも引き継ぎます。ノードIDや配線の参照先には使用しません。論理名だけの変更は表示変更として扱い、待受の再接続や実行PCの選び直しを要求しません。

`Ctrl+B`、またはワークフロータブのダブルクリックで、現在観測しているエラーのノードへ移動できます。複数ある場合は文書順に巡回します。対象がなければ、その旨を表示します。レシピの検索は通常カタログ・クイック追加とも表示名の完全一致、前方一致、部分一致を優先し、内部の種類名や説明だけの一致はその後に表示します。

DashboardのRecent logs、LogViewerの検索結果をダブルクリックすると、記録元のクラスターでワークフローを開き、ノード IDがあればその場所へ移動できます。LogViewerの詳細にも移動リンクがあります。保存済みワークフローの現在の配置を表示するため、記録後に削除されたノードは存在しない旨を表示します。過去の実行を再実行する操作ではありません。

カタログはカテゴリ別・種類別・表示名順を切り替え、グループごとに折り畳めます。空欄をドラッグすると移動、`Ctrl`＋ホイールでポインターを中心に拡縮します。複数選択したノードは `Delete` または右クリックメニューで接続線とまとめて削除し、一回のUndoで戻せます。選択範囲に復元保護中のノードや接続がある場合は、全体の削除を拒否します。線にフォーカスした `Delete` はその線だけを削除します。

ノード内の入力欄・Preview・コードブロックやキャンバスの空白からもワークフロー用の右クリックメニューを開けます。入力欄の文字編集はグラフ削除と分けます。推測できる `ANY` は型を併記します。選択式の設定で候補がなくなった場合は保存値を保持して問題を表示します。

種類別の「Values & types／値・型」は、定数・型・ピア・パスの生成に加え、形式変換、構造操作、四則演算・比較・論理演算、値の中継を含みます。カテゴリ別では Data／Math／Control などに分かれます。設定端子への静的な値構築には、対応する `value.*` と `http.method` を使用します。

実行PC選択の `execution.pc.select`／`execution.pc.lowest` と、ピアID文字列を生成する `value.peer` は用途が異なります。

配線は入力・出力のどちらの端子からもドラッグできます。型が合わない接続は受け付けず、外側へのドロップや Esc では元の線を保持します。既存の入力への接続差替えも Undo で戻せます。クリックでの接続にも同じ型判定が適用されます。

ドラッグ中は、接続可能な端子の円へ近づけると、候補を強調して線の端を円の中心へ吸着させます。その位置で離して接続できます。円の外側の余裕は100%表示で約6px、縮小時は倍率に比例して狭めます（50%で約3px、5%で約0.3px）。拡大時も約6pxを上限とします。ほぼ同じ距離の候補が密集している場合や、型・復元ロックの条件を満たさない場合は吸着しません。範囲から離れると吸着を解除し、端子を直接指した場合はその端子を優先します。

接続の確定時にも同じ検査を行い、取消し・文書変更後に遅い確認結果で線を追加しません。

ワークフロータブはドラッグ、または右クリックメニューの「タブを左へ移動／右へ移動」で並び替えられます。「タブから非表示」は表示だけを閉じ、ワークフロー本体や未保存草稿、自動実行の状態を変えません。「保存済みワークフロー」の一覧から選択すると再表示します。表示順・非表示状態は、このブラウザーのクラスター／ピアごとに保持します。

タブの右クリックからも削除確認を開けます。削除確定後は隣の表示タブへ移り、残りがなければ未選択画面を表示します。新規ワークフローは自動作成せず、「新規」から明示的に作成します。

初めて開く接続先や、前回選択した草稿の本文を復元できない場合も、空の新規ワークフローは作りません。画面を開く際、オンラインで保存済み一覧を読み切れた場合は、その一覧にもこの画面の保持草稿にもない古いタブ情報を自動整理します。旧画面から残った、開けない「New workflow」もこの対象です。名前やノード数だけでは削除せず、同名の保存済みワークフロー・未保存の草稿本文・他画面の草稿は保持します。オフラインや一覧取得の途中では不在と判断しません。

## ノードと型

ワークフローはノードと端子を接続した YAML/JSON 定義です。利用できるノードの種類と設定項目は、画面または CLI の `catalog` から取得できます。`data.convert` は文字列・Path・数値・整数・int64・真偽値の明示変換、**Math** グループの `math.add`／`subtract`／`multiply`／`divide` は四則演算です。

演算は有限の binary64、整数変換は Int64 を扱い、変換不能・範囲外・ゼロ除算を成功扱いにしません。

Mathには、Compare（大小比較）、Is Equal／Is Not Equal（一致／不一致判定）、Power／Root（累乗／累乗根）、AND／OR／NOT／NAND／NOR／XOR、配列用のANDS／ORSもあります。比較は真偽値、論理ノードは入力に対応した真偽値またはInt64整数を返します。AND／ORなどは2入力、NOTは1入力、ANDS／ORSは配列入力です。[設定と実行例](nodes/data.md)を参照してください。

Controlには **ForEach／Parallel ForEach** があります。配列の各要素を、同じキャンバス上の接続先へ逐次または制限付き並列で渡します。**ForEach Endは任意**で、結果配列の集約と全件完了後の後続処理に使います。型を推測できる配列は要素型を表示・検証し、不適合な接続を拒否します。[反復の接続例と失敗時の扱い](nodes/iteration.md)を参照してください。

Audio generationには **OpenAI Speech／Qwen3-TTS／Qwen3-TTS-VC／Qwen-Audio-3-TTS／Eleven Multilingual v2／Eleven v3／Eleven v4** があります。生成先ごとの音声IDとsecretRefを指定し、完成ファイルを検証して返します。[音声生成の設定と例](nodes/ai-media.md)を参照してください。

`value.constant` は自動解釈・真偽値・バイト・整数・浮動小数・decimal・一文字・文字列の値を作り、`value.type` は型を指定します。`value.array` と `value.keyValue` は実データと型定義の両方を組み立てます。`value.dictionary` はKey-Value配列から重複方針付きの辞書を作ります。

辞書の反復・集約・キー／値の抽出とC#／Python／JavaScriptへの入出力は[DictionaryとKey-Value](workflow-nodes.md#dictionaryとkey-value)を参照してください。`http.method` は HTTP メソッド、`value.interface` は実行先の Interface ID を選んで出力します。

`http.listen` の `queryType`／`bodyType` に型を接続すると、必須項目・配列要素・値の型を検証してから受信結果を後続へ渡します。整数と decimal は元の数値を黙って丸めず、文字は Unicode の一文字を扱います。[型付き HTTP の例](../../samples/generic-communication/http-typed-input.json)を参照してください。

**型定義**は、データそのものではなく「どの形式の値を受け付けるか」を表す値です。例えば、文字列の型定義を、配列を選んだ型定義ノードの「要素の型」へ接続すると `{"type":"array","elementType":{"type":"string"}}` になります。オブジェクトは、キーと値ノードで項目名と型定義の組を作り、「項目ごとの型」へ接続します。設定画面には生成結果が表示され、値ノードの型入力からも型を選べます。

型が確定しないJSON値はBinaryも受け付ける任意値と区別して表示します。

OSC の「引数の型」にも型定義や順序付きの型配列を接続できます。単独の型定義は引数1つ、配列はその順序と個数の引数になります。汎用の整数は32bit範囲ならInt32（`i`）、範囲外ならInt64（`h`）、数値はFloat64（`d`）に対応します。明示した `int64` は小さい値でも `h` です。通信上の精度を決める場合は、設定画面または `["i","f","s"]` のようなOSC型タグの配列を使用します。

ANYはすべての入力への変換を意味しません。接続元で判明したJSON／バイト列の区分を中継後も維持し、JSON Pointerによる抽出結果はJSONとして扱います。明示した配列要素型、論理演算の左右の型、組込みノードの入力条件、後続の既存配線も確認します。設定への接続には、依存する入力を含めて静的に構築できる値が必要です。未確定の型は実行時に検証します。

OSC／HTTP／TCPを含む待受ノードは、**受付を終了するまでの時間** が空欄なら常時待ち受けます。時間を指定すると、その待受を正常終了し、受付済み処理の完了を待ちます。TCP／HTTPの `timeoutMs` は受け付けた一件の通信期限で、待受期間や下流ワークフロー全体の期限ではありません。`0` または `null` で一件の通信期限も無期限にできます。

設定欄にも値を接続できます。設定端子は `$settings.interfaceId` のような名前で、定数・純粋な値ノードから構築した JSON を使います。保存してある設定値は残り、線を外すとその値へ戻ります。実行時に変化する通信結果や副作用ノードを設定へ接続した場合は、検証エラーになります。`scheduling.timer` は指定日時・時刻・曜日・対象日と、開始／終了区間内の一定間隔発火を共通に扱います。

プログラム操作は `process.start` と準備待ち・停止・監視ノードを組み合わせます。

ファイル関連のパス欄では、実行PCを指定して **参照…** からそのピア上のファイル・フォルダーを選べます。手入力と未作成パスの指定も可能です。**ピアを選択**・**ファイルを選択**・**フォルダーを選択**ノードから設定値を接続する方法もあります。ピア間転送の転送元は「転送元ピア」、転送先はノードの実行PCです。[ファイル操作の詳細](nodes/files.md)を参照してください。

ワークフローと管理UIのファイル操作は、対象CoreServiceの実行アカウントがOS権限でアクセスできるパスを対象にします。`[files].roots` は、これらの操作をその配下へ制限しません。ファイルシステムのルート自体の変更禁止、リンク通過の検証、競合・転送内容の検証、および内部の更新stagingなどの限定領域は維持します。

AI／HTTP の **登録したAPIキーの名前** は、このクラスターに登録する秘密情報の名前です。設定欄の **APIキーを選択・登録** から実値を登録して使えます。ワークフローには名前だけを保存します。**実行PC自身のIPv4アドレス** は使用するNICの送信元・待受先で、通信相手のアドレスではありません。相手は接続先アドレス・要求先URLで指定します。AIノードでは、サービスとリージョンから決まるエンドポイントを設定画面に表示します。

## 保存・反映と共同編集

ワークフローの設定画面で、変更種類別に自動有効化・明示反映・影響確認付き反映を選べます。複数の変更種類を含む場合は厳しい方針を使い、未反映変更も有効版から比較します。反映画面には実差分と確認できる／できない影響を表示し、確認後に候補・有効版が変われば再確認を要求します。ノード設定変更前には変更前の保存版・有効版のスナップショットを取り、保護失敗や結果不明では本体保存を開始しません。保存後のスナップショットとは結果・IDを分けて確認します。

共同編集では他の編集者のカーソル、ドラッグ途中の位置、未保存変更の存在を表示します。途中位置は保存済み定義を書き換えません。入力途中の具体値や未確定接続線の共有は必須機能に含めていません。

サンプルのYAML／JSONはWorkflowEditorでインポートし、実行先・NIC・パスを設定して検証、保存・共有します。多くの例は `enabled: false` のため、使用時に有効化して保存します。インポート用の定数入力は `inputs` に通常値、バイト列は `binaryInputs` にbase64を指定します。

管理APIの型付き定義とは形式が異なるため、サンプルをそのままCLIの `workflow save --body` へ渡さず、[CLIの解析・保存手順](command-line.md)を使用してください。

### 保存できない下書きの復旧

「JSONを書き出す」は画面上の現在の定義（ノード・配線・設定・配置）を退避します。型が未確定の入力文字列は通常の定義JSONに含まれないため、入力エラーがある箇所は別途保管してください。再インポートは内容の復元であり、共同編集の通信や競合を必ず解消する操作ではありません。

共同編集では、サーバーの版識別子に対応する比較元を受信したまま保持し、表示順の差だけを比較時に吸収します。旧版で比較元の順序と版識別子が食い違った草稿は、最新共有草稿との三者比較で手元の編集を維持して再照合します。照会の期限や一時的な通信エラーで監視ループを終了せず、未送信の変更を「照会中」と表示し続けません。拒否理由は共同編集画面に表示します。

別ピアの草稿へ追従するときも、その直前の比較元を保持します。同じ保存を確認した遅延通知を、保存後の自分の編集との競合として追加しません。実際に同じ項目を別々に変更した場合の競合確認は維持します。内容の変わらない共有ACKでは編集履歴全体を比較し直さず、追加編集とUndoを保持します。通常ワークフローの保存では変更のないノードカタログの再取得を省き、レシピを参照しないワークフローは無関係なレシピ草稿を全件読み込みません。

保存の検証・版照合・スナップショット・反映確認は行います。

ピア間の草稿通知には、編集元ごとの単調な版番号と元操作の識別を含めます。古い複製や解消前の通知は新しい編集として扱わず、並行変更は直前の共通草稿から比較します。本文の比較履歴は各ピアで件数・容量を制限して保持し、通知へ履歴本文を毎回載せません。比較元が保持範囲外の並行編集は、自動統合で変更を失わないよう全文候補の選択へ残します。共同編集には、対応する CoreService と ClientHost が必要です。

旧CoreServiceが残る更新途中は旧方式の通知も受けるため、クラスター内のCoreService更新を完了してから競合を解消してください。

保存ボタン横の設定、または共同編集画面から「現在の草稿を強制保存」を開けます。最新保存版、ノード・配線数と変更項目を確認し、「確認した版へ上書き保存」で現在の草稿を保存します。共同編集の成立は待ちませんが、型検証、復元中の保護、確認後に別の保存が入った場合の版競合は維持します。保存後は、確認済みの競合選択を共有草稿へ返します。後から追加された別の変更は通常の三者比較で保護し、別のブラウザーに残る未保存草稿は削除しません。

草稿と上書き前の保存版は送信前にブラウザーへ退避し、JSONとしても個別に書き出せます。

強制保存の応答が不明になった場合は「元の保存結果を照会」で同じ操作を確認します。閉じ直しや再読み込みでも、不明な要求を新しいIDへ作り替えて再送しません。保存・共有・スナップショット・反映の結果は個別に表示します。

## 選択とコピー

表示倍率は5%〜150%です。右下の「−／＋」は5ポイント刻みで変更し、Ctrl＋ホイールではマウス位置を基準に拡縮します。サブワークフローの読取り専用プレビューも、倍率スライダーから5%まで縮小できます。

- 通常のクリックでノードを選択できます。Ctrlを押しながらクリックすると、そのノードを選択集合へ追加・解除します。
- ノードを選択して `Shift` を押している間、所属する実行区間以外のノードを暗くします。ForEach／ParallelForEachと同時実行制限の開始・Endは自身の区間、内部ノードは最も内側の区間を表示します。最上位のノードはワークフロー全体、複数選択は各範囲を合わせた表示です。入力欄の編集中は適用せず、キーを離す・別画面へ移ると解除します。
- Shiftを押しながらキャンバスの空白からドラッグすると、矩形内に完全に入ったノードを現在の選択へ追加します。Escapeで範囲操作を取り消せます。
- 選択したノードをドラッグすると、選択集合を相対位置を保って移動します。
- ノードを右クリックして「コピー」、貼り付けたい位置で右クリックして「貼り付け」を選択してください。空白位置でも貼り付けメニューを開けます。
- キャンバスでは `Ctrl+C` / `Ctrl+V`（macOSでは `⌘C` / `⌘V`）でもコピー／貼り付けできます。貼り付け位置はキャンバス上の現在のマウス位置で、ポインター位置がない場合は表示範囲の中央です。入力欄・コード編集・ダイアログ内では通常の文字編集を優先し、ノード操作を行いません。
- 両端が選択されている線は条件・抽出指定を含めてコピーします。選択外へつながる線はコピーしません。設定・定数入力・実行先・サイズも保持します。
- 貼り付け元の最小X・最小Yを、右クリックした位置に合わせます。元の配置にその両方を満たす一個のノードがなくても、選択全体の左上が基準になります。追加は一回のUndoで戻せます。

## 実行PCを選択する

処理ノードの実行PCを指定しない場合は、クラスターの最優先PCで実行します。画面で接続先として選んだピアに、新規ノードの実行先を自動固定することはありません。

1. カタログの **実行PC** から **PC選択** または **低負荷PC選択** を配置してください。
2. **PC選択** は、クラスターのPC一覧から選ぶ方式と、全参加PCを候補にする方式を選べます。**低負荷PC選択** は、比較するリソースを指定してください。
3. 選択ノードの出力を、処理ノードの実行PC入力（`$execution.pc`）へ接続してください。同じ入力に複数の選択ノードを接続できます。低負荷選択の `candidates` 入力へPC選択をつなぐと、比較対象を絞れます。
4. 処理ノードの **実行台数** で **1台で実行** または **全候補PCで実行** を選択してください。既定は1台です。候補を合わせて同じPCの重複を除き、1台実行ではその中から最優先の PC が選択されます。全候補実行は各PCで一回ずつ実行します。

CPU・GPUは使用率で比較します。RAM・VRAMは使用率が既定で、使用量（バイト）も選べます。VRAMには専用領域だけを使います。複数GPUのあるPCではGPU識別子を指定でき、未指定時は対象リソースの最大値をPCの代表値にします。欠測や古い測定値はゼロとして比較しません。

実行結果の **実行PCの選択結果** に、候補、選択時刻、測定値、比較できなかった理由を表示します。測定できたPCだけで選んだ場合も、その範囲を確認できます。候補と観測は入力の取得時に固定し、処理中や継続待受中に負荷が変わっても、実行先を移しません。

継続待受の担当には、現在参加可能なPCだけを共有保存します。停止中・再参加中の観測を新しい担当として固定せず、対象が復帰してから確認します。全候補PCで待ち受ける場合は、参加可能なPCの待受を維持し、復帰したPCを追加します。旧版で利用不可の観測が担当として残っている場合も、その観測を再利用せず現在の実体で選び直します。

ピア・ホストグループ・入力発生元による指定も使用できます。PC選択の入力とこれらの指定を同じノードへ併用すると、検証エラーになります。PC選択を接続した結果が空の場合も、未指定とは区別して実行を開始しません。

## 入力欄・コード編集・エラー表示

通信ノードのNIC／IPは、候補を取得できない間も保存値を保持し、「現在の候補にない」値として表示します。候補の復帰、CoreServiceの再起動・再参加、実行先の変更では候補を再確認し、保存値と一致する項目の選択表示へ戻します。右の詳細欄での再取得はノード内の表示にも反映します。実際にNICの識別子やIPが変わった場合は、保存値を別の候補へ自動で置き換えず、利用者が選び直します。ホスト・保存済みキー名などの選択欄も、候補の消失や復帰だけでは設定を削除しません。

複数PCへ同じHTTP・OSC等のノードを割り当てる場合は、「NIC・IPの指定方式」を「PCごとにNIC・IPを指定」に切り替え、「PC別のNIC・IPを設定」から各 PC の NIC と IPv4 を選択してください。各行の候補はそのPCから取得します。未検出PCの値は保持でき、手動入力も可能です。未割り当てPCは開始せず、他PCの設定や共通設定で代替しません。既存の「共通のNIC・IPを指定」は引き続き使用できます。

[対応ノードと保存形式](nodes/communication.md#複数pcのnicip割り当て)を参照してください。

ノードと配線の型・設定・接続値プレビューは、同じ文書とカタログの間で解析結果を共有します。本文や未確定入力、カタログが変わると対応する表示を更新します。共同編集者のカーソル・選択枠はノード本体から独立して表示します。既定ではクリック・入力変更・ドロップ時の座標と選択ノードを共有し、単なるマウス移動は送信しません。在席確認の更新は20秒ごと、他画面の位置確認は無操作時に約1秒間隔です。閉じたノード一覧と詳細パネルは表示内容を作り直しません。

同じワークフローを開いたブラウザー間では、保存前の設定・配線も共有します。編集通知はその都度送信し、取得漏れを回復するピア間の全文照会は同じワークフローにつき5秒間に一度へまとめます。通常の画面照会ごとに草稿全文を再配信しません。ドラッグ途中は確定した変更へせず、ドロップで共有します。実行中ワークフローへの適用は既定では「保存・反映」で行い、共有草稿を受け取っただけでは適用しません。入力中の欄と競合する他画面の変更は入力終了後に照合し、入力を途中で置き換えません。

処理中ノードの発光は通常の表示オプションで選べ、未設定時は有効です。既存ブラウザーで明示的に保存された無効設定は維持します。発光は選択ワークフロー・同じ保存版の処理中状態を約500ms間隔で読み、出力値の取得・ノード実行・履歴保存を追加しません。短時間で完了するノードを必ず描画するトレースではありません。無効時は追加の状態照会を停止します。

`/editor?experimental=true` の表示オプションでは、移動中のポインター共有とクラスター共通の自動保存・反映を追加で選べます。[試験的な機能の常時有効化](../guides/web-client.md#試験的な機能を有効にする)でも同じ操作を利用できます。移動中のポインター共有は最大約7Hzで、停止後は在席維持だけになります。

自動保存・反映の設定はクラスターで共有・永続化します。有効な間は、そのクラスターのコーディネーターが変更の止まった草稿を約2秒後から通常の保存経路へ渡します。連続編集はまとめ、競合・検証・変更種類ごとの反映方針・スナップショットの境界を維持します。結果不明の同じ候補を新しい操作として再実行しません。通常URLから編集した草稿にも共通設定が適用され、有効中は現在のモードを表示します。自動反映を止めるには設定をOFFへ戻します。

URL指定やブラウザーの常時有効化を解除しても、クラスター設定は変わりません。`extra=true` や誤記の `experimeltal=true` では試験的な機能を有効にできません。

配線の方向アニメーションは未設定時にONです。「表示」から変更でき、既存の保存済み表示設定は維持します。画面外の線はアニメーションを休止し、再表示時に再開します。OS・ブラウザーの動きを減らす設定も優先します。終端の矢印は表示せず、端子の左右とアニメーションで方向を示します。右側から左側へ戻る接続は、出力端子からいったん外へ出て折り返します。上下に離れたノードは両者の間を通り、上下が重なる場合は端点から近い外周を通ります。

これは配線の見た目の変更で、実行順や分岐条件には影響しません。

ノードや接続線をドラッグ中に編集領域の端から約48px以内へ近づけると、その方向へ自動スクロールします。端へ近づくほど速くなり、ポインターを止めても継続します。中央へ戻す、ドロップ、取消、フォーカス喪失で停止します。上下左右と斜め方向に対応し、表示倍率を反映してノード・線のプレビューがポインターへ追従します。線は入力側・出力側のどちらからでもドラッグできます。左上の座標0を越えて余白を増やさず、右下は必要に応じて編集領域を広げます。

WorkflowEditor上部の「その他の操作」→「ワークフローを削除」から、確認画面を開けます。対象名・IDと未保存変更の破棄を確認してから削除します。未保存の新規草稿はこのブラウザー内だけを削除し、保存済み定義はクラスター共有の削除として扱います。離脱中のローカル保存版は、再参加・変更解決後に削除してください。

保存済み定義の削除は、確認した保存版が変わっていない場合だけ進みます。削除前の保存定義と受付ピアの有効定義をスナップショットへ保存できなければ、削除しません。保存定義と共有の有効化希望へ同時に削除印を記録し、他ピアも同期後に新規入力を停止します。開始済みの実行は保持した版で継続し、暗黙に取り消しません。操作履歴で、スナップショット・共有削除・受付ピアの新規入力停止を区別して確認できます。結果不明の場合は元の操作IDを照会し、新しいIDで削除を繰り返さないでください。

履歴・スナップショットは残ります。削除前スナップショットの保存定義を再取込して新規保存することで戻せます。既存定義を対象とする通常のスナップショット復元と、削除済み定義の再取込は区別してください。

- `Comment`（コメント）は入力値と型を変えずに渡します。「出力の表記名称」は通常入力として直接記入またはノードから接続できます。空欄なら接続元の端子名を引き継ぎます。編集時に確定できる接続値は名前へ反映し、実行時にしか決まらない名前は「動的な表記名称」と表示します。配線に保存する出力端子IDは常に `value` のままです。コメント本文は直接記入専用で、接続端子を設けません。
  PC選択・低負荷PC選択も、Commentを経由して実行PCや比較候補へ接続できます。複数のCommentを挟んでもPC選択の型と候補を保持し、固定PCを指定した通信ノードのNIC・IP候補も同じ実行先から取得します。PC選択は通常のJSON入力・開始合図へ変換されません。
- `値の型を変換`で数値を文字列へ変換するときは、任意の`フォーマット`入力へ直接記入または文字列ノードを接続できます。`D4`は`42`を`0042`、`N0`は`1234567`を`1,234,567`、`F2`は`1.236`を`1.24`、`0000.00`は`12.3`を`0012.30`へ変換します。[.NET数値書式](https://learn.microsoft.com/en-us/dotnet/standard/base-types/standard-numeric-format-strings)をInvariantCultureで適用し、ホストの地域設定で区切り文字を変えません。未指定・空文字は従来の数値表記を維持し、文字列・Char・Pathの文字列化には数値書式を適用しません。真偽値に非空の数値書式を指定すると失敗します。書式は256文字、標準書式の精度指定は1024までです。不正・範囲外の書式は理由付きの失敗になり、書式なしの成功へ置き換えません。適用外の変換では未使用の書式口を隠しますが、既存の配線や入力は編集・解除できるよう保持します。
- `Code block`（コードブロック）はコードを実行せず、改行を含む文字列を出力します。C#・Python・JavaScriptノードの `code` 設定入力などへ接続できます。言語はプレーンテキスト・C#・Python・JavaScript・Bash・PowerShell（ps1）・JSON・TOML・YAMLから選べます。同梱したエディターで色分け・自動インデント・括弧と語の補完を行い、補完時に仮の引数やメソッド本体は挿入しません。C#・Python・JavaScriptは入力が600ms止まった時点やフォーカス離脱時に構文を検査します。Python・JavaScriptは解析先ピアの実行ファイルを指定するか、Dashboardで導入した管理中のパッケージ環境を使用します。コードブロック自体は `Run` / `run` や入出力型を要求せず、接続先の実行ノードでは従来の契約解析を行います。コードブロックの構文検査が成功すると、同じコードに接続した実行ノードの引数・返却型も解析します。具体的な型は実行ノードの出力へ表示し、解析前の未確定な出力は任意型として表示します。
- コードブロック右下のハンドルでノードとコード欄を拡縮します。ハンドルにフォーカスした状態の矢印キーでも操作でき、Shift併用で大きく変更できます。寸法は草稿・保存・共同編集に含め、実行設定の変更とは分けて扱います。
- 不正な入力、現在のコードに対応する解析エラー、ワークフロー検証結果、確認した実行・待受エラーを、該当ノードとワークフロー／クラスタータブの落ち着いた赤系の枠と印で表示します。ノードのツールチップとInspectorで理由を確認できます。コード変更・再検証・観測した回復に応じて解除し、別クラスターの同名ワークフローへ混ぜません。
- 自動実行の成否と待受状態はDashboardの既存キャッシュを参照します。ノード別の最新成否は各ピア最大512件・5分間で、入力・出力・自由記述メッセージを含めません。編集画面への応答にはグラフ用リソース履歴やログ本文も含めません。これは現在のクラスターについて観測できた有限の履歴で、未確認ピアや保持外の全履歴を網羅するものではありません。通信失敗を成功として表示し直すことはありません。

## 接続値のプレビューとログ本文

「ログを記録」のレベル `NOLOG` は、そのノードからのログ出力を無効にします。元の `value` と成功信号は通常通り後続へ渡します。レベル未指定の既定は `INFO` のままで、ワークフローの異常終了などシステム側の診断ログは抑制しません。

接続済みの通常入力・設定欄は読み取り専用のまま、定数・コードブロック・コメントのパススルーなどから実行せず確定できる値を表示します。ノードカードとインスペクターの両方が対象です。入力元の編集に追従し、保存した設定をプレビュー値で書き換えません。実行時の受信値、未確定な変換、無効な編集中入力は「実行するまで確定しません」と表示し、古い保存値を代わりに表示しません。表示のためにワークフローやスクリプトを実行したり、外部接続や秘密値の取得を行ったりしません。

「ログを記録」の通常入力 `message` には、OSCパケットなどPreviewでJSON表示できるオブジェクト・配列もそのまま接続できます。文字列は引用符を付けず、数値・真偽値・null・オブジェクト・配列はJSONとして記録し、数値精度と構造を保ちます。明示nullは `null` と記録し、未接続の場合だけ従来の設定 `message` を使います。バイナリは本文へ直接接続せず、必要に応じて解析・変換してください。

`value` は付随データとして記録・パススルーし、本文とは分けます。秘密値・秘密項目と個人情報の保護は共通ログ処理で適用します。設定端子にも実行時の文字列を接続できます。

一回で完了する処理の設定端子は、静的な定数に加えて他ノードの実行結果を受け取ります。AIのモデル・音声・エンドポイント・生成オプション、HTTPの設定、データ変換やメッセージ組立て等にも共通で適用され、文字列だけでなく数値・真偽値・配列・Objectも宣言された型で供給できます。Qwen3-TTS-VCの「Voice ID（登録済みクローン音声）」は、DashScopeで登録したクローン音声のIDを `input.voice` へ渡す項目です。

接続値は実行ごと・対象ピアごとに固定し、型・範囲・項目間の制約を検証してから処理を開始します。接続が未供給の場合は、保存値へ戻しません。設定同士の制約は、接続値が揃った段階で確認します。

AI生成ノードの省略可能な任意設定では、成功したObjectの項目欠落とJSON `null` を未指定として扱います。たとえばForEachの `item/feature` をQwenの指示文へ接続しても、要素に `feature` がない場合は指示文を送らず生成できます。`0` と `false` は省略せず、型・範囲の検証を通した値を送ります。必須項目や入力元の失敗は処理開始を止めます。

PC候補の不足は実行PC入力だけで判定し、ほかの入力・設定の不足と区別します。

音声・画像・動画の生成先で親ディレクトリがなければ、API要求前に同じ実行PC上で再帰作成します。「ファイル存在時モード」は上書き（既定）／スキップ、「ファイルロック時モード」はエラー（既定）／スキップを選べます。スキップは正常終了で、`value` に既存ファイルの `peerId`・`path`・`skipped: true`・`skipReason` を返します。既存内容の媒体検査やハッシュの保証は付けず、後続では既存ファイルの参照として扱います。

既存ファイルをスキップする場合は、生成APIを呼びません。上書きでは一時ファイルを検証してから置き換え、生成失敗時は旧内容を維持します。生成中に同名ファイルが作成された場合や、保存直前のOS共有ロックにも設定を適用します。容量・権限不足をロックとしてスキップしません。

フォルダーと同名の出力先は `ai.outputIsDirectory`、不正パス・親の作成不能は `ai.outputPathInvalid`、ffprobe未配置は `ai.ffprobeUnavailable` です。

Qwenの明示エンドポイントは、`/api/v1/services/aigc/multimodal-generation/generation` まで含むHTTP URLです。DashScope SDKが受け取る `/api/v1` までのベースURLとは異なります。AlibabaのドメインでベースURLだけが指定されている場合は `ai.qwen.endpoint.path` として送信前に拒否します。独自の互換サーバーでは指定された完全URLをそのまま使います。

静的な値が必要なのは、待受ノードの待受設定と待受PCの選択条件、OSCの引数の端子構成、型定義ノードの型種別、スクリプトのコードと解析契約、並列反復の同時実行上限、複数PCにまたがるファイル補償方針です。これらも定数・純粋値から構成できます。コメント本文などの編集専用情報は配線対象にしません。

「ディレクトリの作成」は、存在しない親階層も含めて再帰的に作成します。新たに作成する最上位のディレクトリから下を、ファイル排他・補償復元の対象にします。作成先自体が既存の場合は失敗し、既存内容を変更しません。親階層がファイルの場合やリンクを通るパスも拒否します。音声生成用の `downloads/<グループID>` のような階層を、親が未作成の状態から用意できます。

ファイル・ディレクトリの有限操作では、`path`・`destination`、ピア間転送では `sourcePath`・`path` の設定端子へ実行時の文字列も接続できます。スクリプト、文字列変換、Concatなどで組み立てたパスをそのまま渡せます。一回の実行・対象ピアごとに値を固定し、権限・競合範囲の確認と補償用退避にも同じパスを使います。接続値が未供給・空文字・文字列以外の場合は、その操作を開始せず、保存済みの古いパスへ戻しません。

未接続の直接指定と、定数からの静的接続も引き続き適用されます。ディレクトリ監視の開始場所など、待受の構成設定は引き続き開始前に確定する値を使用します。

通信の一回で完了する処理では、OSC（UDP/TCP）・UDP・TCP・Art-Net・Redisの `remoteAddress`（接続先IPv4）と `remotePort`、HTTP・WebSocketクライアントの `url` に、実行時の値を接続できます。IP・URLは文字列、接続先ポートは整数を指定してください。例えば数値 `20` を文字列へ変換し、Concat で `192.168.1.` の後ろにつなぐと、接続先 IPv4 アドレスとして `192.168.1.20` を渡せます。

一回の実行・対象ピアごとに接続先を固定し、IP・ポート範囲・URLの方式を通信開始前に検証します。接続値が未供給または不正な場合、保存済みの接続先へ戻って送信することはありません。送信元NIC・ローカルIP・待受ポートの構成設定は、開始前に確定する値を使用します。

OSC（UDP/TCP）・UDP・TCP・Art-Net・HTTP・WebSocketの待受ポート `localPort` は、整数 `9000`、整数配列 `[9000,9002,9006]`、文字列 `9000-9005` や `9000, 9002, 9006-9010` を指定できます。画面では文字列を引用符なしで入力できます。設定端子へ接続する値も同じ3形式に対応し、待受開始前に確定します。範囲は両端を含み、重複は一度だけ待ち受けます。

1〜65535の最大256ポートを指定でき、従来の `0`（OSによる自動割当て）は単独指定で維持します。逆順・空の項目・小数・文字列配列・0と固定ポートの混在は拒否します。一つでも確保できなければ、そのノードが先に確保した待受も解放し、全ポートが揃うまで稼働中と表示しません。受信件数は指定した全ポートの合計です。

OSC等の継続入力は、受信一件を共通キューへ渡した後、その後続処理の完了を待たずに次の入力を受け付けます。同じ待受から複数の後続実行が並行して進められます。通常入力の実行枠は同じワークフロー・ピアにつき最大64件で、超過分には既存の有限キュー・容量拒否・安全停止方針を適用します。ワークフロー返信を選択したTCP／WebSocketでは、その接続の返信待ちは引き続き通信上の一件処理として扱います。

OSCの引数なしメッセージは、標準の空型タグ `,` に加え、型タグを省略してアドレスだけで終わる旧形式も受信できます。[OSC 1.0仕様](https://opensoundcontrol.stanford.edu/spec-1_0.html)の旧実装との互換性に関する注意に対応するもので、UDP・TCP・Bundle内のメッセージで共通です。終端・4バイト境界・ゼロ埋めが正しいアドレスの後にデータがない場合だけ、空の引数配列へ変換します。

型タグ不明のデータ、引数の途中切れ、余剰データは引き続き拒否し、送信時には標準の型タグを付けます。宛先IDを持たない死活メッセージなどは、受信後の条件分岐で転送対象と分けてください。

ワークフロー全体の自動入力は、上部ツールバーの「自動実行 ON／OFF」で変更できます。ノードを選択していても表示します。このボタンは編集中の設定を示し、保存・反映後に適用します。OFFを反映すると自動入力の受付は停止しますが、手動の一回実行は可能です。インスペクター内のワークフロー設定とも同じ値を編集し、取り消し・共同編集の制御を共有します。

自動実行ONのまま後続や配置を保存した場合、接続条件が同じ待受は接続を維持し、表示用の設定版も反映時点で更新します。次の受信やOFF→ONの操作を待たずに、現在版の稼働状態を表示します。NIC・ポート等の接続条件を変更した場合は、元の待受の停止を確認してから現在の担当PCで自動再開します。受付済みの一件は取得時の設定版で継続し、後の保存を遡及させません。

待受ノードの自動開始は、ノードを選択して「インスペクター → 実行 → 有効化・再起動時に自動開始」で変更できます。OSC・UDP・TCP・HTTP・WebSocket・監視・タイマー等の待受ノードに共通です。ONはワークフローが有効で開始に必要な入力が揃った場合に自動開始し、OFFはStartSignalまたは明示的なノード実行で開始します。設定の保存・反映が必要で、ON/OFFを変更しただけでは既存の待受を停止しません。実行中の待受は停止操作で終了してください。

件数0・待受終了時間なしのOSC受信は、同じ待受から一件ずつ独立した処理をキューへ渡して継続します。待受の維持に自己接続や再帰的な再実行は不要です。

タイマーの受付記録が同期や担当交代と競合した場合、全参加者で受付中止を確認できた版競合に限り、250ms間隔で確定済みの進行位置を読み直して継続します。別担当が受付済みの回は再発生させません。受付結果が不明、保存内容が競合、または元の担当を確認できない場合は発火を停止し、結果不明の回を自動で再実行しません。

PC選択条件を実行計画へ反映済みのノード、設定版として供給済みの値、今回選ばれなかった入口・反復の未実行は、ノードやワークフロー・クラスタータブのエラー表示に含めません。接続先の利用不能、実際の失敗、結果不明は引き続き強調します。

生成APIのタイムアウト・エラー・取消でローカルのファイルアクセスが終了した場合は、その処理自身のファイル予約を解放します。外部サービスへの送信後に結果を確認できなかった場合は、実行結果は引き続き「結果不明」です。予約の解放は外部要求の成功確認や再生成を意味せず、新しい明示要求を古い予約で妨げないための処理です。Qwen・Eleven・OpenAI・画像・動画の生成で共通に適用します。

外部プロセスの停止未確認や、補償の未完了など、ファイルアクセス・復旧の確認が必要な予約は別に保持します。

### Path型

「値」「型定義」「値の型を変換」と、配列・Object・ForEach・スクリプト等の共通型選択で `Path`（`path`）を指定できます。ファイル選択・ディレクトリ選択ノードもPathを出力します。本文はJSON文字列のままで、Stringと相互に接続できます。型情報は値とともに保存・ピア間通信され、コメントのパススルー、配列／Key-Valueの構築、Object展開、JSON Pointer、ForEachの要素化・集約でも保持します。

Concat に渡す入力がすべて Path なら、入力順に区切りを補って結合します。例えば Path の `C:\Clutch-CS\content`、`audio`、`clip.wav` を接続すると、`C:/Clutch-CS/content/audio/clip.wav` になります。途中に絶対パスを置くとエラーになります。通常の String を混ぜる場合は、区切りを補わず文字列として連結します。

任意入力「結合文字列」(`separator`) に空でない文字列を指定した場合もStringとして連結し、入力間だけにその文字列を挿入します。未接続またはnullは空文字です。配列のConcatは区切りなしで要素を連結し、共通のPath要素型を保ちます。

Pathはファイルシステム用で、URLやワイルドカードではありません。空文字、不正なUnicode、制御文字、禁止文字、Windowsの予約名、末尾の空白・ピリオドを拒否します。OS間の可搬性を優先した規則なので、Unixでのみ有効な特殊な名前を扱う場合は従来のStringを利用してください。相対Pathは結合やスクリプトに使えますが、ファイル操作ノードの絶対パス要求・OSアクセス権・許可範囲は維持します。

予約名等の根拠は [Windowsのファイル名・パス規則](https://learn.microsoft.com/ja-jp/windows/win32/fileio/naming-a-file)です。

通常は内部区切りを `/` に揃え、実ファイル操作とC#／Python／JavaScriptの引数では実行先OSで扱える形にします。UNCは別OSでローカルの絶対パスへ誤解釈されないよう `\\server\share\file` のWindows表記を保ちます。ドライブ名や共有ルートを他OSのマウント先へ自動対応付けしません。

C#では `string`、Pythonでは `str`、JavaScriptでは文字列として渡し、言語の文字列リテラルを手動エスケープする必要はありません。

JSON／YAML／TOMLやHTTPの型指定では、`{"type":"string","format":"path"}` をPathとして扱います。配列の `items`、Objectの `properties` 内でも指定できます。外部へ普通のJSON文字列として出した後は文字列だけからPathを推測せず、受け側のスキーマ・手動指定・変換でPathを指定します。JSON Schemaの `format: path` はContentsでの追加の型指定です。

Pathを使うワークフローは、対象のCoreServiceと編集Web クライアントをすべて対応版へ更新してから保存・実行してください。
