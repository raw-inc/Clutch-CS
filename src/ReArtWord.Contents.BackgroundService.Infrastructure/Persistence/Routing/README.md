# 用途別保存の設定と境界

[関連する設定・開発資料](../../../../docs/reference/cluster-operations.md#用途別保存と保存不能時の扱い)

このディレクトリは、用途別の保存先を選ぶ処理と、媒体をまたぐ操作の制約を管理します。

共通 TOML の既存 `storage.backend` は未指定用途の既定です。初回の新しい保存領域では、必要な用途だけ SQLite／JSON へ分けられます。同じバックエンドを指定した用途は同じ `state.db` または `state.json` と原子的な取引を共有します。

```toml
[storage]
directory = "D:/Clutch-CS/data"
backend = "sqlite"

[storage.purposes]
configuration = "json"
runtime = "sqlite"
processes = "sqlite"
diagnostics = "json"
```

| 用途 | 同じ整合性を維持する単位として保存するもの |
| --- | --- |
| configuration | ワークフロー定義・履歴・有効版、スナップショットと編集保護、クラスター共通運用設定と有効版、秘密値、追跡設定、離脱中の定義・履歴・スナップショット |
| runtime | ノードの共有・ローカル状態、実行履歴、PC選択の担当、日時処理の進行位置・保持入力・取消記録、ファイル操作・予約・補償の履歴、更新履歴、離脱中の状態 |
| processes | 登録アプリケーションの定義と起動・故障・復旧状態 |
| diagnostics | 共通リソース診断履歴とログ索引 |

内部で未分類の用途と routing 自身のローカル管理情報は既定媒体へ保存します。ログ本文のファイル／zstd 形式や外部業務 DB 接続の選択を、この設定で置き換えるものではありません。

一回の `ApplyBatch`／`Prepare` が異なる媒体に分かれる場合は、`Persistence.CrossBackendBatch` として開始前に拒否し、一方だけを書きません。定義・履歴・スナップショット保護条件の通常保存は同じ configuration 用途にまとめています。異なる用途を一括変更する拡張処理では、関連用途を同じバックエンドへ指定してください。

ピアごとに物理媒体が異なっても、通常複製と同期は論理スコープを使います。ただし送り元で一括確定した履歴が受信先の複数媒体へ分かれる設定は、同期開始前に理由付きで拒否します。その履歴の用途を同じ媒体にまとめる必要があります。

同期する内容は、ローカルの一時ファイルとハッシュに固定します。すべての保存先への取込みが終わるまで、通常の読み取り・書き込み・書き出しを停止します。途中で失敗・取消が起きても、次のアクセスやハートビートで保存済みの内容から回復を試みるため、プロセスの再起動は不要です。別のスナップショットを途中から継ぎ足すことはありません。取込み完了後は各項目の版と未解決の競合を公開します。一時ファイルの破損・欠損や保存先の障害が続く場合は、通常の読み書きを再開しません。

SQLiteの共有版確認では、変更世代と保守世代を同じ読取り取引内で確認します。世代が変わらない場合も、前回の本文検証から30秒以上経った共有版確認では、共有行の実バイト列と保存ハッシュを再検証します。この確認には新しい接続を使用し、接続内のページキャッシュでSQL外の破損を隠しません。内容が変わらない行は復元済みの値と正規化済みJSONを再利用し、小さい更新で全共有データを再展開することを避けます。キャッシュは保存本文と正規化JSONの合計64 MiBを上限とし、上限超過分も通常どおり読み取って照合します。削除行は次の確認でキャッシュから外し、履歴の失効索引や最新スナップショットなどの保護条件は同じ取引の最新状態で再評価します。共有版の形式とSQLite／JSON間の互換性は変わりません。UTF-16のSQLite保存は従来の読取り経路を使用します。

通常参加中の相手との版比較では、照会前または照会後のローカル版が相手の応答と一致すれば、その確認済みの一致点を採用します。返信待ちの間に次の保存へ進んだ場合も、確認できた一致点を捨てて履歴全体を転送することを避けます。一致のない継続変更は有限の猶予後に実同期へ進み、新規参加や転送失敗後の確認は従来どおり必要です。

用途割当は保存領域へ固定します。既存単一バックエンドの設定は互換で利用できますが、後から別媒体へ変更して既存値を空の保存先へ置き換えることは拒否します。稼働中の変更・自動移行・代替保存先への自動切替は提供しません。保存領域を別構成へ移す場合は、旧情報を保全した明示移行が必要です。

保存不能時の「旧値維持／未保存有効」とオフライン編集方針は別契約です。用途選択だけで未保存の設定を有効化したり、保存成功と表示したりしません。
